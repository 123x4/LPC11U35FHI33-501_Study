## 🎯 现象

你按下左键，电脑立刻收到“左键按下”；松开，电脑收到“左键松开”。

但这块板子的左右键**不是机械开关**：没有“咔哒”一声接通的触点。板子测的是一个**连续的模拟量**（光强 → 电压），然后由软件决定“按到多深算按下”。这就是“磁轴 / 光轴”鼠标和普通鼠标最大的区别，也是这个项目的核心卖点：**触发点（AP）和快速触发（RT）可以在 GUI 里调**。

> T1A 上把“红外光”换成“霍尔芯片测磁场”，**后面的算法完全一样**。所以这一课学的就是你毕业项目的需求①要保留的那一大半。

---

## 📌 必须掌握（5 句话）

1. 左右键的数据流是：**光 → 电压 → ADC 数字（0~1023）→ 段数（0~100，表示按下深度百分比）→ 按下/松开 → 报文第 1 字节 bit0/bit1 → EP1 → 电脑**。
2. 这条线**每 1 ms 走一遍**，节拍来自 CT16B0 中断（1-7 课）。
3. “段数”是**相对量**：软件一直在学习“松开时是多少（top 基线）”和“按到底是多少（bottom 基线）”，然后把当前值换算成 0~100。所以不同按键、不同温度下，同样的 AP 设置手感一致。
4. 判定用的是 **RT（Rapid Trigger）状态机**：松开状态下，从最低点往下压 ≥ RT按下值 且 ≥ AP → 判定按下；按下状态下，从最高点往上抬 > RT松开值 → 判定松开。**实际的第一次触发点 = max(AP, 谷底 + RT按下)**，不是单纯的 AP。
5. 要改成 T1A 的霍尔芯片，**只需要换“取数据”的那一段**（`LR_GetState()` 前半部分），从段数开始的所有算法都不用动。

## 三、每一站

### ① 光 → 电压（硬件）⚠️

**一句话**：每个按键下面有一个“小灯 + 光敏元件”。按键往下走，照到光敏元件上的光就变了；光敏元件把“光的变化”变成“电压的变化”；MCU 用 ADC 读这个电压。

**三个零件**

| 零件 | 打个比方 | 作用 |
|---|---|---|
| 红外发射管（IR LED） | 电视遥控器头上那颗灯，发的光人眼看不见 | 一直亮着，提供光 |
| 光电三极管 | 一个**被光控制的水龙头**：光越强，开得越大，流过的电流越大 | 把“光强”变成“电流” |
| 电阻 | 电流流过它会产生电压：U = I × R | 把“电流”变成“电压”，送给 ADC 引脚 |

```
     3.3V                                   按键（往下按）
      │                                         │
   [IR_EN 开关]◄── PIO0_19 输出高电平             ▼
      │                                    ┌─────────┐
   红外发射管 ~~~~~~~~ 红外光 ~~~~~~~~~~~► │ 光电三极管 │──► 电阻上的电压 ──► PIO0_13 (AD2) 左键
                       ▲                   └─────────┘                    PIO0_14 (AD3) 右键
                 按键位置改变了这束光的多少
                 （挡住一部分，或者反射回来更多）
```

**代码里能确定的两件事** ✅

1. `IR_EN`（PIO0_19）在开机初始化时被设成输出高电平（`src/GPIO.c:496~499`，注释 “high: enable, open power”），也就是**打开红外灯的电源**。之后代码里再也没有动过它，所以灯一直亮，挂起时也不关。
2. `PRESS_KEY_AND_VALUE_INCREASE = 0`（`inc/my_misc.h`，IRPT_V4 分支）。这是一个**告诉算法“方向”的配置开关**：0 表示“按下时 ADC 读数变小”。算法默认按“变大 = 按下”写，所以看到 0 就先做 `1023 − ADC` 倒过来（Q3 讲的“反转”）。

**不能确定的** ⚠️

- 没有 IRPT_V4 的原理图，所以不知道是“按下挡住光”还是“按下反射更多光”，也不知道电阻接在光电管的哪一边。这两件事组合起来决定了“按下时电压变高还是变低”，代码只告诉我们结果是**变低**。
- 照片里板子正面左上角（D3、D4 附近）和右上角（D5 附近）的黑色小方块，位置正好在左右键下方，很可能就是红外对管。
- 仿真里用的 ADC 数值（松开 ≈ 820，按到底 ≈ 320）是我假设的。真实数值用 `hid_tool.py watch LR` 读出来就知道了。

### ② 电压 → 数字：ADC ◆

**硬件配置**（`MyADC_HwInit` / `MyADC_Init`，`src/my_adc.c:46~77`，在 `Device_Init()` 最后调用，`src/device.c:485~486`）

| 做了什么 | 寄存器 | 手册 |
|---|---|---|
| 给 ADC 上电 | `PDRUNCFG` bit4 清 0 | UM Table 47 |
| 开 ADC 时钟 | `SYSAHBCLKCTRL` bit13 置 1 | UM Table 24 |
| ADC 时钟 = 48 MHz ÷ (15+1) = **3 MHz** | `CR` CLKDIV[15:8] = 15 | UM Table 352，要求 ≤ 4.5 MHz ✅ |
| 11 个时钟 / 10 位 | `CR` CLKS[19:17] = 0 | UM Table 352 |
| 引脚：无上下拉、模拟模式、功能 2 | IOCON `MODE`=0, `ADMODE`=0, `FUNC`=2 | UM Table 89 / 90 |

引脚：左键 **PIO0_13 = AD2**，右键 **PIO0_14 = AD3**（`inc/my_board.h:262~267`）✅。这两个脚开机默认是 JTAG 的 TDO / TRST（1-3 课讲过 FUNC=0 是 JTAG）。

**一次转换**（`MyADC_GetValue`，`src/my_adc.c:79`）

```
CR.START = 0            停
CR.SEL  |= (1<<ch)      选通道
读一次 DR[ch]           清掉旧的 DONE
CR.START = 1            “现在开始转换”
  ── 硬件：11 个 ADC 时钟 × (1/3 MHz) = 3.67 µs ──
每 2 µs 看一次 DR[ch].bit31 (DONE)，最多看 10 次（20 µs 超时 → 返回 -2）
结果 = (DR[ch] >> 6) & 0x3FF     ← 数据在 bit15:6（UM Table 355）
CR.SEL &= ~(1<<ch)      取消选通道
```

例：读到 `DR2 = 0x8000 4F40` → DONE=1，`0x4F40 >> 6 = 0x13D = 317` → 317 / 1023 × 3.3 V ≈ **1.02 V**。

两个通道各一次，总共约 **10 µs**，在 1 ms 里只占 1%。

> 小细节 ⚠️：ADC 超时的时候 `LR_GetState()` 直接 `return 0`（`app/button.c:322~325`），等于这一毫秒报告“左右键都松开”。如果当时键是按着的，会出现一次误松开。正常情况下 3.67 µs 就转完，不会超时，所以只是理论上的风险。

### ③ 数字 → 段数 ★

`ProcessRecvSampleRawData()`（`src/my_misc.c:418`）对左右两个键各做 4 步：

**1. 拆包 + 反转**

```c
temp = (buf[2k] << 8) | buf[2k+1];      // k=0 右键，k=1 左键（注意顺序！）
temp = 1023 - temp;                      // PRESS_KEY_AND_VALUE_DECREASE：让“按下 = 变大”
```

反转之后：松开 ≈ 203，按到底 ≈ 703（仿真）。

**2. 滤波**（`length_filter_bit = 4`，`FILTER_SKIP_VALUE = 10`）

```
如果 新值 和 上次滤波值 差 > 10   → 直接用新值（手在动，要快）
否则                            → 滤波值 = 旧值 × 15/16 + 新值 × 1/16（手没动，要稳）
```

这是一个“**动的时候不滤、静止的时候滤**”的滤波器：按键快速移动时一毫秒变化几十，不加延迟；静止时只有 ±3 的噪声，被平滑掉。

**3. 换算成段数**（`Hall_CalculateNode`，`:288`）

```
            temp − top
  tmp = ─────────────────── × 255        （0~255，用定点数算，避免除法）
          bottom − top

  段数 = nodeCaliTable[tmp]              （查表，0~255 → 0~100）
```

- `top` = 松开时的值（top 基线），`bottom` = 按到底的值（bottom 基线）。
- 如果 `bottom − top < 100`（还没学到行程），**直接返回 0**：这时按键不可能被判定按下。
- IRPT_V4 的表基本是线性的（`tmp × 100 / 250`）；Hall 板用另一张非线性表（`#else` 分支）。

**4. 基线学习**（`Hall_InitBaseline` / `CalibrateTop` / `CalibrateBottom`）

| 基线 | 什么时候学 | 怎么变 |
|---|---|---|
| 上电初始化 | 前最多 600 ms（`cali_init_cnt = 600`） | 连续 100 次读数稳定在 ±20 内 → 完成，top = bottom = 平均值 |
| top（松开位置） | 只在**松开状态**下 | 低于 top 超过 20 并持续 300 ms → −20；略低持续 100 ms → −5；略高（≤20）持续 100 ms → +2 |
| bottom（按到底） | 每次按下的**前 100 ms** | 比 bottom 高 80 以上持续 30 ms → +60；高 20 以上持续 30 ms → +10 |

`MAGNETIC_NOISE = 20`（IRPT_V4，`inc/my_hallkey_func.h:22`）。名字里有 “MAGNETIC” 是因为这套代码原来是为霍尔（磁）写的。

> 💡 **仿真发现**（`./key_sim` 输出，实物待验证 ⚠️）
> - **上电后第一次按键要“学”**：bottom 从 202 开始，每 30 ms 才 +60。第一次按到底后约 18 ms 才判定按下（仿真 450 ms 按到底，468 ms 才按下）。
> - bottom 只在每次按下的前 100 ms 增长，所以要**按好几次**才学到完整行程（仿真结束时 bottom 从 202 涨到 642，而真实按到底是 703）。
> - **bottom 只会变大、从不变小**：代码里没有往下调 bottom 的分支。

### ④ 段数 → 按下/松开：RT 状态机 ★

`Hall_HandleKeyRapidTrigger()`（`src/my_misc.c:330`）。每个键记一个“参考点” `current_node_update`。

```
               ┌───────────────────────────────────────────────┐
               │                 松开状态                        │
               │  参考点 = 见过的最低段数（谷底），往下走就跟着降低    │
               └───────────────────────────────────────────────┘
                   │ 段数 ≥ 100                    ▲ 段数 == 0
                   │ 或 段数 ≥ 谷底+RT按下 且 ≥ AP    │ 或 峰顶 − 段数 > RT松开
                   ▼                               │
               ┌───────────────────────────────────────────────┐
               │                 按下状态                        │
               │  参考点 = 见过的最高段数（峰顶），往上走就跟着升高    │
               └───────────────────────────────────────────────┘
```

默认值（`inc/my_misc.h`）：**AP = 10，RT按下 = 30，RT松开 = 20**，单位都是“段”（1 段 ≈ 1% 行程）。GUI 下发新值后由 `Hall_UpdateParam()`（`:101`）更新。

仿真里的 4 个典型时刻（AP=10，RTP=30，RTR=20）：

| 时刻 | 发生了什么 | 段数 | 为什么 |
|---|---|---|---|
| 468 ms | 第 1 次按下 | 100 | 段数到 100（满行程）直接按下；之前一直是 0，因为 bottom 还没学到 |
| 627 ms | 松开 | 78 | 峰顶 100 − 78 = 22 > 20 |
| 809 ms | 第 2 次按下 | 30 | 谷底 0 + 30 = 30，且 30 ≥ AP 10 |
| 917 ms | 只抬起一点就判定松开 | 79 | 峰顶 100 − 79 = 21 > 20（**RT 的意义**：不用完全抬起） |
| 974 ms | 停在 60% 后再下压，判定按下 | 100 | 谷底 72 + 30 = 102，段数到 100 才满足（满行程规则先生效） |

**关键理解**：AP 不是“按到 10% 就触发”。AP 只是一个下限；从完全松开开始，第一次触发点是 **max(AP, 0 + RT按下) = 30**。如果想让按键在 10% 就触发，要把 RT按下 也调到 ≤ 10。

**振动期间冻结**：`USE_HALL_VALUE_DURING_VIBRATION = 0`（`inc/my_electromagnet.h:31`）⇒ 线圈正在振动的时候（`Ele_IsVibrating()`），这个键的状态保持上一次的值，不读新数据。原因：线圈振动会让按键机械抖动，读数不可信。（L3 课详细讲。）

### ⑤ 状态 → 报文 ◆

`ProcessRecvSampleRawData()` 返回：**bit0 = 左键（k=1），bit1 = 右键（k=0）**。

> ⚠️ **左右编号陷阱**：`my_misc.c` 里 `k=0` 是**右键**、`k=1` 是**左键**（`hall_spi_rx[0..1]` 放的是右键）；返回值 bit0 是**左键**；`Hall_SyncParam()` 又把 index 反过来一次。改代码前一定先确认你手里的 index 指的是哪个键。

`Button_Scan()` 对左右键**不做软件消抖**（那两行 `debounce` 被注释了），因为 RT 状态机本身有迟滞（RT松开 = 20 段），不会抖。中键、侧键是机械开关，有 5 ms / 8 ms 消抖。

`Custom_HandleKey()` 按 `key_function[i].usb_registration.id` 映射（`app/custom.c:106~118` 是默认值）：

| 物理键 i | 默认 id | 报文第 1 字节 |
|---|---|---|
| 0 左 | 0xB0 | `|= 0x01` |
| 1 右 | 0xB1 | `|= 0x02` |
| 2 中 | 0xB2 | `|= 0x04` |
| 5 K4 | 0xB3 | `|= 0x10` |
| 6 K5 | 0xB4 | `|= 0x08` |

所以 GUI（老协议）可以把左键改成键盘按键、宏等，这就是“按键映射”功能。

### ⑥ 报文 → 电脑（L1 课）

```
按下：01 01 00 00 00 00 00 00      松开：01 00 00 00 00 00 00 00
      ID 键  X低 X高 Y低 Y高 滚轮 横滚
```

`Device_Report()` 先等 EP1 空（最多 600 µs），然后 `USB_LoadInEP_Data(EP_1_MOUSE, …, 8)` 放进 EP1。电脑下一次 IN 令牌（≤ 1 ms）就把它取走。L1 图解页第 4 节就是这一包的完整波形。

**总延迟估算**：越过触发点 → 下一次扫描（≤ 1 ms）→ 组包放进 EP1（几十 µs）→ 下一次 IN 令牌（≤ 1 ms）。**最坏约 2 ms**。

## 🎓 和 T1A 的关系（需求①）

T1A 用 GTRY164 霍尔芯片，挂在 SSP1 上（03 适配清单）。要改的只有：

1. **取数据**：`LR_GetState()` 里的 `MyADC_GetValue()` 换成 SPI 读霍尔芯片。代码里 `#else` 分支已经有老霍尔板的写法（`hall_get_sample()` + `ana_phy_bit_error_checker2()` 的 14 位 + 校验），GTRY164 的帧格式要看它的数据手册 ⚠️。
2. **数据方向和量程**：`PRESS_KEY_AND_VALUE_INCREASE`、`MAX_VALUE_14BIT`、`MAGNETIC_NOISE`、滤波参数、`nodeCaliTable` 都有 `#if (defined(IRPT_V4))` 分支，T1A 要加自己的分支。
3. **PIO0_13/14** 在 T1A 上改做线圈 PWM，ADC 就不用了。

④ 状态机、⑤ 组包、⑥ USB **一行都不用改**。

## 补充问答

### Q1 松开状态下的“最低点”、按下状态下的“最高点”是什么？

两个都是同一个变量 `current_node_update[k]`（`src/my_misc.c:332`），代码里叫“参考点”。它记录的是**手指上一次掉头的位置**：

| 状态 | 参考点记录什么 | 怎么更新 | 什么时候切换 |
|---|---|---|---|
| 松开 | 松开以来段数**到过的最小值**（谷底） | 段数比它小 → 跟着变小；比它大 → 不动 | 段数 ≥ 谷底 + RT按下（且 ≥ AP） |
| 按下 | 按下以来段数**到过的最大值**（峰顶） | 段数比它大 → 跟着变大；比它小 → 不动 | 峰顶 − 段数 > RT松开 |

每次切换状态时，参考点重置为当时的段数。

**一句话**：RT 不看“手指在哪个位置”，看“手指**掉头之后**往反方向走了多远”。

仿真里的一段（AP=10，RTP=30，RTR=20）：

| 时刻 | 段数 | 状态 | 参考点 | 说明 |
|---|---|---|---|---|
| 800 ms | 0 | 松开 | 谷底 0 | 完全松开 |
| 809 ms | 30 | **按下** | 峰顶 30 | 0 + 30 = 30，判定按下，参考点重置为 30 |
| 830 ms | 100 | 按下 | 峰顶 100 | 继续往下压，峰顶跟着升 |
| 910 ms | 96 | 按下 | 峰顶 100 | 开始抬，峰顶不动；100 − 96 = 4，不够 20 |
| 917 ms | 79 | **松开** | 谷底 79 | 100 − 79 = 21 > 20，判定松开（手指还在 79% 深度！） |
| 930 ms | 72 | 松开 | 谷底 72 | 继续往上抬一点，谷底跟着降 |
| 974 ms | 100 | **按下** | 峰顶 100 | 再往下压，需要 72 + 30 = 102，到不了，段数 100 时“满行程”规则生效 |

和普通按键比较：普通按键是“过了某个**固定位置**就触发”，抬起时也必须回到固定位置以上；RT 是“**往回走够了**就切换”，所以连点时手指不用完全抬起，速度更快。这就是游戏鼠标卖 RT 的原因。

### Q2 “上电后第一次按键要先学”，学的是什么？

学的是**这一个按键**的两个数：

- **top 基线**：松开时 ADC（反转后）是多少；
- **bottom 基线**：按到底时是多少。

为什么不直接写死？因为每个按键的光电管、挡光片位置、装配公差、温度都不同。写死一个数，有的鼠标按到一半就满了，有的按到底还不够。所以软件只认“相对位置”：段数 = (当前 − top) / (bottom − top) × 100。

**怎么学的**（仿真数值）：

```
0~101 ms   上电，手不碰按键。连续 100 次读数都在 ±20 内 → top = bottom ≈ 202
           （此时 bottom 不知道，只能先等于 top）
           bottom − top < 100 → Hall_CalculateNode 直接返回 0 → 怎么按都是 0 段

400 ms     开始往下按（50 ms 按到底）
           规则（Hall_CalibrateBottomBaseline）：读数比 bottom 高 80 以上，连续 30 次（30 ms）→ bottom += 60，计数清零重来
408 ms     读数 283，比 bottom 202 高 81 > 80 → 计数开始：1   ← 计时从这里开始，不是从按到底开始
437 ms     计数到 30 → bottom 202 → 262，计数清零
438 ms     读数 583，比 bottom 262 高 321 > 80 → 重新计数：1
450 ms     按到底（读数 ≈ 704），计数继续
467 ms     计数又到 30 → bottom 262 → 322    现在 bottom − top = 121 ≥ 100，开始算段数
468 ms     当前 704 ≥ bottom 322 → 段数 100 → 判定按下   ← 比按到底晚了 18 ms

468~568 ms 按下后的前 100 ms 内继续学：322 → 382 → 442 → 502，然后停止
后面每次按下，前 100 ms 都会再学一点：502 → 622 → 642 …
```

**带来的现象**（仿真，实物待验证 ⚠️）：

1. 上电后**第一次**按键必须按得比较深，而且会晚十几毫秒才触发。
2. 前几次按键时 bottom 还偏小，按到 60% 左右段数就已经是 100，“段数”被压缩了。按几次之后才接近真实行程。
3. top 也会慢慢跟着修正（比如温度变化让松开值漂移），但只在松开状态下修正。

用 `hid_tool.py watch L` 插上板子后第一次慢慢按左键，就能看到 bottom 一步步涨。

### Q3 图里的“反转后的 ADC”和“滤波后”是什么？

两条线是 `ProcessRecvSampleRawData()` 里**同一个数据先后两步处理的结果**：

```
ADC 原始值 ──①反转──► 反转后的 ADC ──②滤波──► 滤波后 ──► 段数计算、基线学习
  317         1023 − 317     706                704
```

**① 反转**：`temp = 1023 − ADC`。IRPT_V4 按下时 ADC 变小（松开 ≈ 820，按到底 ≈ 317），反转后变成“按得越深数越大”（松开 ≈ 203，按到底 ≈ 706），后面的算法都按“变大 = 按下”写的。没有任何平滑，所以带着 ±3 的噪声。

**② 滤波**：根据“新值和上次滤波值差多少”二选一（`FILTER_SKIP_VALUE = 10`，`length_filter_bit = 4`）：

| 情况 | 做法 | 仿真例子 |
|---|---|---|
| 差 > 10：手在动 | 直接用新值，不平滑 | 441 ms：新 612，旧 594，差 18 → 输出 612 |
| 差 ≤ 10：手没动 | 输出 ≈ 旧值 × 15/16 + 新值 × 1/16 | 440 ms：新 600，旧 594，差 6 → 输出 594 |
| | | 700~707 ms：新值在 201~206 跳，输出一直 203 |

图上两条线几乎重合，是因为按压时每毫秒变化十几到几十，滤波器直接跟随；只在静止时能看出区别：灰线抖、绿线平。0~101 ms 只有灰线，因为初始化基线阶段不输出滤波值（`Hall_SyncParam` 还没被调用）。

为什么要这样设计：静止时噪声会让段数在 0、1 之间跳，也会干扰基线学习；但按压时如果也平滑，就会增加延迟。所以“动的时候不滤，静的时候滤”。
