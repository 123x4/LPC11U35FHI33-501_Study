## 1-7 `MyDebug_Init()`：其实什么都没做

`inc/my_debug.h`：

```c
#define MYDEBUG_ENABLE          0          // 第 19 行
#if MYDEBUG_ENABLE
  ……（调试打印相关的定义）
#endif
……
#if MYDEBUG_PRINTF_ENABLE
void MyDebug_Init(void);                   // 打开调试时：是一个真函数
#else
#define InfoLog(format, ...)      do{}while(0)
#define MyDebug_Init()            do{}while(0)   // 第 73 行：关闭调试时，是一个“空宏”
#define MyDebug_Task()            do{}while(0)
#endif
```

`MYDEBUG_ENABLE = 0`，所以 `MYDEBUG_PRINTF_ENABLE` 没有定义（预处理器把它当 0），走 `#else`：`MyDebug_Init()` 被替换成 `do{}while(0)`，**编译后一条指令都没有**。

验证：在 `List/Sample.map` 里搜 `MyDebug_Init`，**找不到**，说明它根本不是一个函数。

> 💡 **`do{}while(0)` 是什么？** 一个“执行一次、什么也不做”的语句。用它而不是空着，是为了让 `MyDebug_Init();` 后面那个分号仍然合法，并且在 `if (...) MyDebug_Init(); else ...` 这种写法里不会出语法问题。这是 C 语言写宏的常见技巧。

打开调试时它会做什么：用 SWDIO 脚（PIO0_15）软件模拟串口，或者通过 USB 端点打印日志。`study_notes/tools/README.md` 里提到的 USB 日志模式就是这个。**打开 UART 模式会占用 SWD 调试脚**，要注意。

## 1-8 `InitCT16B0()`：系统的 1 ms 心跳

### 一、为什么需要 1 ms 节拍

程序里有大量“等多少毫秒”“每隔多少毫秒做一次”的需求：按键消抖、USB 挂起判断、传感器扫描周期、线圈振动之间的间隔……这些都需要一个**统一的毫秒时钟**。

这一课用 16 位定时器 **CT16B0** 做一个每 1 ms 产生一次中断的“心跳”。每跳一次，全局计数 `mySysTickMs` 加 1，其他模块用它来计时。

> 和 1-4 课的 CT32B0 对比：CT32B0 是“一直往前走、靠匹配寄存器定闹钟”（而且当前没用上）；CT16B0 是“数到 999 自动清零、每圈产生一次中断”——**周期性中断**。

### 二、参数

`inc/Timer.h`：

```c
#define TIME_CT16B0_COUNT       999      //0 To 999 = 1000
#define TIME_CT16B0_PR          47       //0 To 47 = 48
```

### 三、逐行讲解（`src/Timer.c` 第 160~172 行）

```c
void InitCT16B0(unsigned int PR ,unsigned int Time)    // PR = 47, Time = 999
{
    LPC_SYSCON->SYSAHBCLKCTRL |= (1<<7) ;   // ① 开 CT16B0 时钟
    LPC_CT16B0->PR = PR ;                  // ② 预分频 47
    LPC_CT16B0->MR0 = Time ;               // ③ 匹配值 999
	LPC_CT16B0->MR1 = Time ;
	LPC_CT16B0->MR2 = Time ;
	LPC_CT16B0->MR3 = Time ;
    LPC_CT16B0->MCR = ( 3 << 0 ) ;         // ④ MR0 匹配：中断 + 清零 TC
    LPC_CT16B0->TCR = 1 ;                  // ⑤ 开始计数
    NVIC_EnableIRQ(TIMER_16_0_IRQn) ;      // ⑥ NVIC 打开中断 16
    return ;
}
```

**① 开时钟**：📖 UM p32 Table 24 bit7 **CT16B0**；📖 UM p333 15.2 节：“Power: In the SYSAHBCLKCTRL register, set bit 7 and 8”。这次是**先开时钟再写寄存器**，顺序正确（对比 1-4 课 CT32B0 的第 995 行）。

**② PR = 47**：和 1-4 课一样，48 MHz ÷ (47+1) = 1 MHz，TC 每 **1 µs** 加 1。

📖 **UM p338 Table 301**：CT16B 的 PR 只有 **bit 15:0**（16 位），TC 也只有 16 位（📖 p335 Table 295：“The **16-bit** TC”）。所以 PR 和 MR 都不能超过 65535。

**③ MR0 = 999**：MR1~MR3 也写了 999，但 MCR 只用到 MR0，另外三个**写了没用**（复制粘贴留下的）。

**④ MCR = 3**：📖 **UM p339 Table 303**：

| 位 | 名字 | 写入 | 含义 |
|---|---|---|---|
| 0 | MR0I | 1 | MR0 匹配时产生中断 |
| 1 | MR0R | 1 | MR0 匹配时 **TC 清零** |
| 2 | MR0S | 0 | 不停止 |

这就是和 1-4 课最大的区别：**MR0R = 1**，TC 匹配后自动回到 0，形成周期：

```
TC:  0 → 1 → 2 → … → 998 → 999 ─┐ 匹配！置 IR.MR0INT，TC 清零
     ┌────────────────────────────┘
     0 → 1 → … → 999 ─┐ 匹配！
     …                 │
     每圈 1000 个 µs = 1 ms，产生一次中断
```

为什么是 999 而不是 1000？TC 从 0 数到 999 一共是 **1000 个数**（0、1、…、999），匹配后下一拍回到 0。注释 “0 To 999 = 1000” 说的就是这个。

**⑤ TCR = 1**：📖 p337 Table 299 TCR bit0 CEN，开始计数。

**⑥ NVIC_EnableIRQ(16)**：📖 **UM p69 Table 59**：中断号 16 = CT16B0。

三道门的状态（1-1 课）：

```
外设开关 MCR.MR0I = 1   ✓
NVIC ISER0 bit16  = 1   ✓
PRIMASK           = 允许 ✓（0-4 课：进 main 时中断是开的）
```

三道门全开 → **从这一行执行完开始，每 1 ms 就会进一次 `TIMER16_0_IRQHandler`**。这时 USB 还没初始化，主循环还没开始，但心跳已经跳起来了。

### 四、中断优先级：CT16B0 比 USB 还高

下一行（第 448 行，1-9 课）是 `NVIC_SetPriority(USB_IRQn, 1)`。而 CT16B0 **没有设置优先级**，保持复位值。

📖 **UM p78 Table 70 / 71**（IPR4 / IPR5）：

> Each interrupt can have one of 4 priorities, where **0 is the highest priority**.

| 中断 | 优先级字段 | 值 | 谁设的 |
|---|---|---|---|
| CT16B0（16） | IPR4 bit 7:6 IP_CT16B0 | **0（最高）** | 复位值，没人改 |
| USB（22） | IPR5 bit 23:22 IP_USB_IRQ | 1 | device.c:448 |

所以**1 ms 心跳中断可以打断 USB 中断**，反过来不行。心跳中断很短（只是一堆计数器加减），这样设计保证计时不会被 USB 拖慢。（1-9 课细讲优先级。）

> 💡 手册小错误：Table 70 的标题是 IPR4（0xE000 E410），但上面那句话写的是 “The IPR6 register controls…”。以表格标题和地址为准。

### 五、中断函数做了什么（`src/Timer.c` 第 65~123 行）

```c
void TIMER16_0_IRQHandler(void)
{
    if ( LPC_CT16B0->IR & (0x1<<0) )        // MR0 匹配了吗？（📖 p337 Table 297 bit0）
    {
        LPC_CT16B0->IR = (0x01<<0) ;        // 写 1 清标志（不清的话退出后会立刻再进来）
        MyTick_IncreaseSysTickMs();         // mySysTickMs += 1   ← 最重要的一行
        if(Debounce_cnt!=0) Debounce_cnt--;
        if(one_ms_cycle) one_ms_cycle--;
        ……USB 挂起计时 suspend_UsbActive_timerOut……
        if (tm_usb_sof) tm_usb_sof--;
        if (timer_1s) timer_1s--;
        if (optical_scan_cycle) optical_scan_cycle--;
        if (dpitimerdelay) dpitimerdelay--;
        ……
    }
}
```

两种计时方式同时存在：

| 方式 | 例子 | 用法 |
|---|---|---|
| **递减计数器** | `optical_scan_cycle`、`timer_1s` | 主循环给它赋一个值，中断每 1 ms 减 1，主循环看到它变成 0 就知道时间到了（例如 `device.c:786`） |
| **全局时间戳** | `mySysTickMs`（`src/my_tick.c`） | 记下开始时刻 `t0 = MyTick_GetTickMs()`，之后用 `MyTick_GetTickMs() - t0 >= N` 判断过了多久。全工程有 32 处调用 |

1-4 课线圈的 `leftEle.debounceBeginTick = MyTick_GetTickMs();` 就是第二种。

**中断向量核对**：中断 16 → 向量表第 16+16 = 32 项，地址 0x4000 + 32×4 = 0x4080。`List/Sample.map` 第 898 行：`TIMER16_0_IRQHandler 0x00004d05`。反汇编开头：

```
4d06: ldr  r0, [pc, #0x310]     ; r0 = LPC_CT16B0->IR 的地址
4d08: ldr  r1, [r0]             ; 读 IR
4d0a: lsls r1, r1, #0x1f        ; 把 bit0 移到最高位，看是不是 1
4d0c: beq  …                    ; 是 0 就直接退出
4d0e: movs r1, #0x1
4d10: str  r1, [r0]             ; IR = 1，清标志
4d12: bl   MyTick_IncreaseSysTickMs
```

### 六、顺带确认：CT16B1 没有中断

`src/Timer.c` 里还有 `InitCT16B1()`（会打开 CT16B1 的中断、优先级设为 2），但**全工程没有任何地方调用它**（只有 `my_debug.c` 里调试用的版本，也被 `MYDEBUG_ENABLE=0` 关掉了）。所以 CT16B1 只被 `CT16B1_DelayUs()` 当作“秒表”轮询使用，**没有中断**。`TIMER16_1_IRQHandler` 定义了但永远不会执行。

更新到路线图第 3 部分：

| 中断 | 状态 |
|---|---|
| `TIMER16_0_IRQHandler` | ✅ 1-8 课使能，每 1 ms 一次，优先级 0 |
| `TIMER16_1_IRQHandler` | 不会触发（`InitCT16B1` 没被调用） |

## 小结

```
1-7  MyDebug_Init()   MYDEBUG_ENABLE=0 → 空宏 do{}while(0)，map 里都找不到
     SPI 初始化        IRPT_V4 分支为空
1-8  InitCT16B0(47, 999)
      ├─ 开 CT16B0 时钟（bit7）
      ├─ PR=47 → 1µs/拍；MR0=999；MCR=MR0I|MR0R → 每 1000µs 中断一次并清零
      ├─ TCR=1 开始，NVIC 开中断 16（优先级保持 0，最高）
      └─ 中断里：mySysTickMs++，以及一串递减计数器
```
