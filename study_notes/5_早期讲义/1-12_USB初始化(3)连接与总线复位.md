# 1-12 USB 初始化（3）：`NDrv_USB_Connect(TRUE)` —— 电脑是怎么“看见”鼠标的

> 📍 **位置**：`main()` → `Device_Init()` → 第 449 行 `nsAPI_USB_Init()` → **`usbhw.c:327` `NDrv_USB_Connect(TRUE);`**（`nsAPI_USB_Init()` 的最后一行）

## 一、代码只有 4 行（`src/usbhw.c:338~344`）

```c
void NDrv_USB_Connect(U8 con)
{
	if(con)
	LPC_USB->DEVCMDSTAT |= USB_DCON;      // con = TRUE：DCON = 1，“我要连接”
	else
	LPC_USB->DEVCMDSTAT &= ~USB_DCON;     // con = FALSE：DCON = 0，“我要断开”
}
```

`USB_DCON = BIT16`（`inc/usbhw.h:111`）。📖 **UM p226 Table 214 bit16 DCON**：

> The connect bit must be set by SW to indicate that the device must signal a connect. The pull-up resistor on USB_DP will be enabled when this bit is set and the VbusDebounced bit is one.

这一行是整个 USB 初始化里**最后、也是最关键的一步**：前面所有准备（时钟、引脚、登记表、中断）都做完了，现在才“告诉电脑我插上了”。这就是 1-10 课说的 SoftConnect 的意义。

## 二、这一行之后，硬件上发生了什么

```
软件：DEVCMDSTAT.DCON = 1
          │
          ▼  同时 VBUSDEBOUNCED = 1？（PIO0_3 是高电平，1-10 课；T1A 上一直是 1）
          │  是
          ▼
USB 控制器把 USB_CONNECT（PIO0_6）拉低
          │
          ▼  T1A：PNP 三极管 Q1 的基极经 R47 被拉低 → Q1 导通
          │
          ▼
3.3V ─ Q1 ─ R38 1.5kΩ ─ D+        D+ 被拉到约 3.3V
          │
          ▼
电脑那边的 USB 口看到“D+ 变高了” → 判断：插上了一个全速设备
```

（前两课的知识在这里全部串起来了：1-10 讲 VBUS 和 USB_CONNECT 引脚、1-10 Q1 讲电源、1-11 讲登记表。）

## 三、电脑看见设备之后做什么：总线复位

下面的流程和时间来自 **USB 2.0 规范**（不是 LPC11U35 手册），时间是规范规定的大致值：

```
时间          电脑（主机）                              鼠标（本程序）
──────────────────────────────────────────────────────────────────────
t = 0       看到 D+ 被拉高 → 有全速设备插入              DCON = 1（本课这一行）
                                                         nsAPI_USB_Init() 返回，
                                                         Device_Init() 继续往下执行
t ≈ 100 ms  等设备电源稳定（至少 100 ms）
            发出“总线复位”：把 D+、D- 都拉低            
            至少 10 ms
                                       ──────▶         USB 硬件检测到总线复位
                                                         → DEVCMDSTAT.DRES_C = 1
                                                         → INTSTAT.DEV_INT = 1
                                                         → 三道门都开着 → 进 USB_IRQHandler
复位结束     开始“枚举”：通过 EP0 发 SETUP 包，           EP0 收到 SETUP → EP0 中断
            问“你是什么设备？”                           → 1-13 课
```

📖 **UM p227 Table 214 bit26 DRES_C**：

> This bit is set when the device received a bus reset. On a bus reset the device will automatically go to the default state (unconfigured and responding to address 0).

也就是说，总线复位后**硬件自己**回到“地址 0、未配置”的状态，软件要做的是把登记表重新摆好。

## 四、第一个 USB 中断：`USB_IRQHandler` 的“设备状态”部分（`src/usbhw.c:1331~1375`）

```c
void USB_IRQHandler (void)
{
  disr = LPC_USB->INTSTAT;          // ① 读出“发生了哪些事”
  LPC_USB->INTSTAT = disr;          // ② 写回去 = 把这些标志清掉（INTSTAT 是写 1 清零，1-11 课）

  if (disr & DEV_STAT_INT) {        // ③ 是“设备状态”中断吗？（bit31）
    val = LPC_USB->DEVCMDSTAT;      //    读设备状态，看具体是哪种

    if (val & USB_DRESET_C) {       // ④ 总线复位（bit26）
      NDrv_USB_Reset();             //    重新摆登记表、清中断、开中断（1-11 课的函数）
      USB_Reset_Event();            //    USB_RESET_EVENT = 1 → 调用 nsAPI_USB_ResetCore()，复位软件里的 USB 状态
    }
    if (val & USB_DCON_C) { … }     // ⑤ 连接变化（bit24）：USB_POWER_EVENT = 0，什么都不做
    if (val & USB_DSUS_C) { … }     // ⑥ 挂起/恢复（bit25）：2-11 课
    goto isr_end;                   //    设备状态处理完直接结束
  }
  ……（SOF 帧中断、端点中断：1-13 课）
}
```

| 位（DEVCMDSTAT） | 名字 | 什么时候置 1 | 本程序怎么处理 |
|---|---|---|---|
| 24 | DCON_C | VBUS 消失导致上拉被断开 | `USB_POWER_EVENT = 0`，不处理 |
| 25 | DSUS_C | 进入/退出挂起（电脑睡眠、唤醒） | `USB_Suspend()` / `USB_Resume()`（2-11 课） |
| 26 | DRES_C | 收到总线复位 | `NDrv_USB_Reset()` + `USB_Reset_Event()` |

这就是 1-11 课说的“`NDrv_USB_Reset()` 不只调用一次”：**开机初始化调一次，每次总线复位再调一次**。插上电脑时至少会有一次总线复位。

## 五、一个重要的认识：枚举是在“后台”完成的

`NDrv_USB_Connect(TRUE)` 执行完就返回了，**它不会等电脑枚举完**。

```
主程序（前台）                                     中断（后台）
Device_Init()
  ├─ nsAPI_USB_Init() 返回
  ├─ 三个 Pointer_Init()（1-14）
  ├─ TimerDelayMsec(500)（1-15）  ◀── 这 500 ms 里 ──▶  总线复位中断
  │                                                     EP0 中断 × 很多次（枚举）
  ├─ ……                                                 帧中断每 1 ms 一次
  └─ PAW3950_Init()、MyADC_Init()
main 主循环 …
```

USB 的所有“对话”都在 `USB_IRQHandler` 里一问一答地完成，主程序完全不用管。`Device_Init()` 后面那个 `TimerDelayMsec(500)`，很可能就是给枚举留时间（1-15 课确认）。

## 六、一个细节：对 DEVCMDSTAT 用 `|=` 的“副作用”

DEVCMDSTAT 里有些位是 **RWC**（Read / Write-1-to-Clear，读出来是状态，写 1 清零），比如 bit24~26 的 DCON_C、DSUS_C、DRES_C（📖 Table 214 Access 列）。

`LPC_USB->DEVCMDSTAT |= USB_DCON;` 实际是三步：

```
读出 DEVCMDSTAT → 把 bit16 置 1 → 整个值写回去
```

如果读出来时 DRES_C 恰好是 1，写回去时它也是 1 → **顺手把 DRES_C 清掉了**。

- 本课这一行执行时，还没连接，这些“变化”位都是 0，没有影响。
- 但这个现象在中断里很重要：`USB_IRQHandler` 只清了 INTSTAT，**没有专门清 DRES_C**；它是在紧接着调用的 `NDrv_USB_Reset()` 里，`DEVCMDSTAT |= USB_EN`（1-11 课）这一句“顺手”清掉的。
- ⚠️ 挂起/恢复的 DSUS_C：我查了 `USB_Suspend()`（`usbhw.c:441`）和 `USB_Resume()`（`usbhw.c:548`），**里面都没有写 DEVCMDSTAT**，所以 DSUS_C 可能不会被及时清掉，下一次设备状态中断时可能再次走进挂起/恢复分支。是否真的有影响，2-11 课讲挂起时再细查。

这种写法能工作，但比较“巧合”。以后自己写代码时，对带 RWC 位的寄存器要特别小心 `|=`、`&=`：它可能清掉你不想清的标志。

## 七、小结

```
NDrv_USB_Connect(TRUE)：DEVCMDSTAT.DCON = 1
  → 硬件：DCON=1 且 VBUSDEBOUNCED=1 → USB_CONNECT 拉低 → D+ 经 1.5kΩ 上拉
  → 电脑：发现全速设备 → 等约 100 ms → 总线复位
  → 鼠标：DRES_C → DEV_INT → USB_IRQHandler → NDrv_USB_Reset() + USB_Reset_Event()
  → 电脑：通过 EP0 开始枚举（1-13）
这一切都在中断里“后台”完成，Device_Init() 不等它，继续往下执行
```

## 🔁 回顾题答案

1. 0x2000 4000（USB RAM 开头）；寄存器 **EPLISTSTART**（1-11 课）。
2. 状态（Active/Disabled 等）、能放多少字节（NBytes）、柜子位置（Address Offset）。柜子位置只要 16 位：最高 10 位所有柜子都一样，存在 DATABUFSTART 里；最低 6 位因为 64 字节对齐永远是 0（1-11 课 Q1~Q3）。
3. 因为 DCON 还是 0，D+ 没有上拉，电脑看不到设备，总线上没有任何活动，也就不会产生任何 USB 事件（1-11 课）。
