Button_GetState()：给 6 个键拍一张快照

截图里选中的这一句 button = Button_GetState(); 是 Button_Scan() 的第一步。这一页只讲它：它从哪里读、怎么把分散在各个引脚和 ADC 上的状态，整理成一个 32 位的数。

1/7🧭 本质

Button_GetState() 是采样层：把“此刻每个键按没按”拍成一张快照，1 个位代表 1 个键，1 = 按着。

它和外面的 Button_Scan() 分工很清楚：

函数回答的问题记不记得过去
Button_GetState()“现在哪些键按着？”GPIO 键不记；左右键会记（滤波、基线，第 5 节）
Button_Scan()“什么时候算真的按下 / 松开？”（消抖、找变化）记（scan_result_cur、scan_result_pre、倒计时）

它也是一道抽象边界：在它下面，代码要关心第几个引脚、低电平有效、ADC 通道；从它往上，大家只认“第 9 位 = DPI 键”。所以 T1A 换引脚，只要改它下面这层。

在“按下 DPI 键的完整流程”里，它就是第 4 步。

2/7场景：谁调用它、多久一次

调用者什么时候
Button_Scan()（button.c:599）主循环里每 1 ms 一次（定时器举手 → Device_Button_Scan() → Button_Scan()）
Device_Manually_Enter_RestoreDefault()（device.c:365）开机时一次（看右键 + 后侧键是不是同时按着），这时 ADC 还没初始化（第 6 节）

3/7动手：拍一次快照

动手 · 按键勾“按着”，左右键拖滑块（红外 ADC 原始值，按下时电压会降低）

左右键这里做了简化：真实代码先滤波、算出 0~100 的“按下程度”，再用触发点 + 回弹的状态机判断（L2“一次点击”讲过）。这里只用“按下程度 ≥ 50”示意。

4/7逐段看：GPIO 的 4 个键

原始代码（button.c:551~590，IRPT_V4 走第一个分支）：

UINT32 Button_GetState(void)
{
	UINT32 button_port_state = 0;
	UINT32 button_port0_state=0;

  #if (defined(HAPTIC_V2) || defined (HAPTIC_V3) || defined (HAPTIC_V4) || defined (IRPT_V4) || defined(V4_HALL_HPTIC_V4))
  button_port0_state = BUTTON_PORT0;

  button_port_state |= Button_Location_Data(button_port0_state,DPI_CYCLE_BUTTON_MASK,DPI_CYCLE_BUTTON_POSITION,DPI_CYCLE_BUTTON_REPORT_BIT);

  button_port_state |= Button_Location_Data(button_port0_state,K5_BUTTON_MASK,K5_BUTTON_POSITION,K5_BUTTON_REPORT_BIT);
  #elif ...（其他板型）
  #endif

	button_port_state |= LR_GetState();
	return button_port_state;
}

① BUTTON_PORT0 宏展开

#define BUTTON_PORT0 (U32)((~LPC_GPIO->PIN[0])& (MIDDLE_BUTTON_MASK | DPI_CYCLE_BUTTON_MASK | K5_BUTTON_MASK | K4_BUTTON_MASK))   // button.h:149

展开后：
(U32)((~(*(volatile uint32_t*)0x50002100)) & ((1u<<12) | (1u<<11) | (1u<<23) | (1u<<1)))
                     ↑ GPIO 端口 0 的 PIN 寄存器                ↑ = 0x00801802
  • 一次读 32 个引脚：LPC_GPIO->PIN[0] 在 0x5000 2100（LPC11Uxx.h:592，LPC_GPIO_BASE = 0x50000000 + 偏移 0x2100），读一次就拿到 PIO0_0~PIO0_31 全部电平（第 6 课）。
  • 取反 ~：这 4 个键都是内部上拉、按下接地，按下 = 0。取反后变成“按下 = 1”。
  • 与掩码 &：只留第 1、11、12、23 位，其余 28 个引脚（USB、SPI、线圈……）清 0。

② Button_Location_Data()：把引脚位挪到键位位

UINT32 Button_Location_Data(UINT32 port,UINT32 mask,UINT32 position,UINT32 reportPosition)   // button.c:277
{
	reportMask = port & mask;            // 只看这一个键的那一位
	if (reportPosition > position)
		reportMask <<= (reportPosition - position);   // 往高位挪
	else
		reportMask >>= (position - reportPosition);   // 往低位挪
	return reportMask;
}
键引脚（position）键位（reportPosition）怎么挪
中键PIO0_12 → 第 12 位第 2 位右移 10
DPI 键PIO0_11 → 第 11 位第 9 位右移 2
前侧 K4PIO0_1 → 第 1 位第 5 位左移 4
后侧 K5PIO0_23 → 第 23 位第 6 位右移 17

引脚号来自 my_board.h（IRPT_V4 那段，MIDDLE_BUTTON_PIN 12 等），键位号来自 button.h:100~107。这个函数的好处：引脚换了，只改 my_board.h 里的数字，挪多少位它自己算。

5/7逐段看：左右键（红外 + ADC）

左右键不是开关，是红外对管：按下时挡光多少，电压就变多少（第 7 课）。所以它们走另一条路：LR_GetState()（button.c:298）。

#if (defined(IRPT_V4))
  ret = MyADC_GetValue(pLeftAdcHandle, &leftVal);      // AD2 = PIO0_13，左键
  ret |= MyADC_GetValue(pRightAdcHandle, &rightVal);   // AD3 = PIO0_14，右键
  if(ret) return result;                               // 任何一路失败 → 返回 0（两个键都当“松着”）

  hall_spi_rx[0] = (uint8_t)(rightVal >> 8);           // 名字叫 hall / spi，其实装的是 ADC 值
  hall_spi_rx[1] = (uint8_t)(rightVal);
  hall_spi_rx[2] = (uint8_t)(leftVal >> 8);
  hall_spi_rx[3] = (uint8_t)(leftVal);
#endif
  result = ProcessRecvSampleRawData((uint8_t *)(&hall_spi_rx), 4);   // my_misc.c:418
  return result;
  1. 1
    两次 ADC 转换（my_adc.c:79）：选通道 → 启动 → 每 2 µs 看一次 DONE 位，最多看 10 次（约 20 µs）；拿到 10 位结果（0~1023）。超时返回 −2。
  2. 2
    装进 4 字节数组：先右后左，各占 2 字节（高字节在前）。这个数组和格式是从霍尔板型沿用来的：霍尔芯片走 SPI，一次读回的就是这 4 个字节。
  3. 3
    ProcessRecvSampleRawData()（本项目 chengjie 写的）：
    • 取反：1023 − 原始值（IRPT_V4 按下时电压降低，翻过来变成“按得越深数越大”）；
    • 滤波：变化小于 10 时做滑动平均，变化大就直接跟上；
    • 算出 0~100 的“按下程度”（Hall_CalculateNode()，用顶部 / 底部基线）；
    • 触发点 + 回弹状态机得出 gbKeyState[0]（右）、[1]（左）；
    • 顺手校准基线、把数值存给 GUI 查询（Hall_SyncParam()）、告诉线圈当前段位（Ele_UpadteSegment()）；
    • 线圈正在震的那一侧，沿用上一次的状态（震动会干扰读数）。
  4. 4
    返回：右键 → 第 1 位，左键 → 第 0 位（注意 k = 0 是右键，顺序是交叉的）。

6/7坑和要注意的地方

问题后果
任何一路 ADC 超时，LR_GetState() 直接返回 0左右键在这 1 ms 里被当成“松开”；左右键不消抖，可能报出一次误松开。概率低（20 µs 一般够），没实测过
开机时 Device_Manually_Enter_RestoreDefault() 调它，ADC 还没初始化ADC 读不出来 → 右键永远是 0 → “右键 + 后侧键恢复默认”大概率失效（待上板验证）
变量名 hall_spi_rx、函数名 Hall_*IRPT_V4 用的是红外 + ADC，名字是霍尔板型留下的，读的时候别被骗
右键在数组前面、却放到第 1 位左右交叉，改代码时容易弄反
名字叫 Get，却每 1 ms 做 2 次 ADC 转换 + 滤波 + 校准不是“只读一下寄存器”那么便宜；而且有副作用（见下面 💡）
💡 想法上：名字叫 Get 的函数，也要查它有没有“副作用”
按常理，GetXxx() 应该只读、不改任何东西，调几次都一样。可 LR_GetState() 每调一次都会更新滤波值、校准基线、改按键状态机。
所以“多调一次”不是没代价：开机那次额外调用，就会推动滤波器和状态机走一步。
读别人的代码时，看到 Get 不要默认它是“干净”的，进去看一眼它改了哪些全局变量；自己写代码时，把“读数”和“处理”分成两个函数，名字就不会骗人。

7/7T1A 要改什么

  • GPIO 键：T1A 的中键、侧键、DPI 换了引脚（中键 PIO0_7、前侧 PIO0_11、后侧 PIO0_12、DPI PIO0_23）。改 my_board.h 的引脚号，Button_Location_Data() 自动算挪多少位；BUTTON_PORT0 的掩码跟着宏变。外部已有 47k 上拉，仍是按下 = 0。
  • 左右键：LR_GetState() 的数据来源从“两次 ADC”换成“SSP1 菊花链读两颗 GTRY164”，正好回到这个 4 字节数组本来的设计（霍尔 SPI）。ProcessRecvSampleRawData() 的 #else 分支（14 位、带校验）就是给霍尔用的，可作参考。
  • 不用改：Button_Scan() 和上面所有层，因为它们只认键位号。

小测

记住：Button_GetState() 一次读 LPC_GPIO->PIN[0]（0x5000 2100）拿到 4 个 GPIO 键，取反、掩码、挪到键位号（2、5、6、9）；再调 LR_GetState() 做两次 ADC 转换并经过滤波和状态机，得到左右键（第 0、1 位）。它只回答“现在哪些键按着”，消抖和找变化交给 Button_Scan()。
