# 阶段 0 第 1 课：芯片规格与启动引脚

> 资料：DS = `materials/mcu_reference/LPC11U3X.pdf`，UM = `materials/mcu_reference/LPC11U3x2x1x User Manual.pdf`（页码均为 PDF 页码）

## 1. 存储器规格（DS p6，Table 2 Ordering options）

| 列名 | LPC11U35FHI33/501 | 说明 |
|---|---|---|
| Flash | 64 KB | 程序存储 |
| EEPROM | 4 KB | 参数存储（本项目用来保存 AP/RT/振感参数） |
| SRAM0 | 8 KB | 主 RAM，地址 0x1000 0000 |
| USB SRAM | 2 KB | 地址 0x2000 4000（表注 [1]：也可作通用 RAM） |
| SRAM1 | 2 KB | 地址 0x2000 0000 |
| **合计 SRAM** | **12 KB** | = 8 + 2 + 2，**但这 3 块地址不连续** |
| I/O Handler | no | 这个型号没有 I/O Handler（UM 第 23 章不适用） |
| GPIO 引脚数 | 26 | HVQFN33 封装 |

**和项目的对应**：`Sample.uvproj` 里 IRAM1 = 0x1000 0000 / 8KB（SRAM0），IRAM2 = 0x2000 4000 / 2KB（USB SRAM）。SRAM1（0x2000 0000）目前没有分配给链接器。
所以“12KB SRAM”这个说法本身没错，但程序里的一个数组**最大只能占 8KB**，因为它必须放在一块连续的内存里。

## 2. PIO0_13 / PIO0_14（DS p14）

| 引脚 | HVQFN33 脚号 | 复位后默认功能 | 其他功能 |
|---|---|---|---|
| TDO/PIO0_13/AD2/CT32B1_MAT0 | 23 | **TDO**（JTAG 数据输出），带上拉 | GPIO、**AD2**、定时器匹配输出 |
| TRST/PIO0_14/AD3/CT32B1_MAT1 | 24 | **TRST**（JTAG 复位），带上拉 | GPIO、**AD3**、定时器匹配输出 |

引脚名称里**排在最前面的就是复位后的默认功能**（表中 “Reset state” 一列写的是 `I; PU`，即输入、上拉）。

切换成 ADC 需要改 IOCON 寄存器的两个地方（UM 第 7 章，阶段 4 详讲），对应 `src/my_adc.c` 中的 `MyADC_Init()`：
1. `FUNC[2:0] = 2` → 选择 AD 功能（`MYADC_SET_FUNC(..., MYADC_FUNC_AS_AD)`）；
2. `ADMODE`（bit 7）`= 0` → 模拟输入模式，断开数字输入电路（`*(p->pFuncReg) &= ~(1U << 7)`）；
3. 同时关闭上下拉（bit 4:3 = 0），否则内部上拉电阻会影响模拟电压。

## 3. PIO0_1 / PIO0_3：芯片启动时的“岔路口”

### 3.1 芯片里其实有两个“Bootloader”

| | 位置 | 谁写的 | 能否修改 |
|---|---|---|---|
| **ROM Bootloader** | 0x1FFF 0000，16KB（UM p391） | NXP 出厂固化 | 不能，**永远不会坏** |
| 公司 Bootloader | 用户 Flash 0x0000~0x3FFF | 公司 | 可以（被擦就没了） |
| 应用程序（本工程） | 用户 Flash 0x4000 起 | 我们 | 可以 |

### 3.2 上电后 ROM Bootloader 的判断流程（UM p390~392，Figure 69）

```
上电/复位
  │  （约 3ms 后采样引脚）
  ▼
看门狗溢出标志？ ──是──▶ 跳过引脚检查，直接找有效用户代码
  │否
  ▼
PIO0_1 的电平？
  ├─ 高（正常情况，内部上拉）──▶ 检查 0x0000 处是否为“有效用户代码”
  │                                 ├─ 有效 ──▶ 执行用户代码（公司 Bootloader → 应用程序）
  │                                 └─ 无效 ──▶ 进入 ISP（同下）
  └─ 低（有人把它拉到地）──────▶ 直接进入 ISP，不管 Flash 里有什么
                                       │
                                       ▼
                              PIO0_3 的电平？
                               ├─ 高（插着 USB，VBUS 有电）──▶ USB ISP：电脑上出现一个 U 盘
                               └─ 低 ──▶ UART ISP：等待串口命令（表面上看就是“没反应”）
```

- **PIO0_1** 决定“要不要进 ISP”（DS p12：A LOW level on this pin during reset starts the ISP command handler）。
- **PIO0_3** 决定“用 USB 还是串口做 ISP”（DS p12、UM p391）。它的另一个功能 USB_VBUS，本来就是用来检测 USB 有没有插上的。

### 3.3 什么是“有效用户代码”（UM p392）

向量表前 8 个字（32 字节）加起来必须等于 0，第 7 个字（偏移 0x1C）专门用来凑这个和。实测 `materials/Z_M300S FW Update/merge_firmware.bin`：

| 地址 | 前 8 个字之和 | 第 7 个字 |
|---|---|---|
| 0x0000（公司 Bootloader） | **0x0** ✅ | 0xEFFFF095 |
| 0x4000（应用程序） | 0x10019959 | 0x0 |

ROM 只检查 0x0000 处，所以只有 Bootloader 需要这个校验和；应用程序不需要（也没有）。Keil 不会自动填这个字，通常由烧录工具计算后写入。

### 3.4 为什么这和“救砖”有关

ROM Bootloader 固化在芯片里，Flash 里的程序怎么坏都影响不到它。只要能让 PIO0_1 在复位时为低电平，就一定能进入 ISP 重新写 Flash。

在 IRPT_V4 板上，PIO0_1 正好接前侧键（`inc/my_board.h`：`FRONT_BUTTON = PIO0_1`）。按键按下时引脚接地（`inc/button.h` 中 `BUTTON_PORT0` 是 `~LPC_GPIO->PIN[0]`，说明按下为低电平）。所以：

> **按住前侧键再插 USB → 芯片进入 ROM ISP。**
> 如果 PIO0_3 接了 VBUS，电脑上会出现一个 U 盘；如果没接，就是 UART ISP，鼠标表现为“没反应”。

这块板没有原理图，PIO0_3 有没有接 VBUS 无法确认，**所以这只是根据手册推出来的结论，没有验证**。

⚠️ **日常使用中的提醒**：如果不小心按着前侧键插上 USB，鼠标会没反应，或者电脑上冒出一个 U 盘。**这不是坏了**，松开按键重新插拔就恢复正常。出现那个 U 盘时，**不要删除或修改里面的文件**，否则会擦写芯片里的程序。
