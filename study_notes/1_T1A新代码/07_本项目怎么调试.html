本项目怎么调试：想看程序在干什么，有哪几扇窗

调试就是想办法“看见”芯片里正在发生的事：某个变量现在是多少、某段代码有没有走到、某个信号是什么波形。这个项目里能用的办法有八种，各有各的线、各有各的代价。这一课把它们画在一张图上，再一个个讲：怎么打开、能看到什么、在 T1A 上有什么限制、会踩什么坑。

🧭 先记住三句话
  • 不改代码就能看：GUI（MouseTest.exe）和 hid_tool.py，通过 USB 读霍尔读数、段号、配置。最安全，最常用。
  • 要看程序内部流程：打开 MYDEBUG_ENABLE，用 InfoLog() 打日志，默认走 USB 发到电脑。
  • 要单步、看寄存器：Keil + J-Link 走 SWD。但 T1A 上 SWCLK 脚开机约 0.5 秒后会被光学传感器借走当 SPI 时钟，之后调试器就连不上了（第 5 节）。

3. 日志：InfoLog() 从代码走到电脑屏幕

3.1 怎么打开

全部开关在 inc/my_debug.h。默认是关的（第 19 行 MYDEBUG_ENABLE 0），这时 InfoLog(...) 被定义成空语句 do{}while(0)，编译后一个字节都不占。

#define MYDEBUG_ENABLE          1            // inc/my_debug.h:19   0 → 1
...
#define MYDEBUG_PRINTF_ENABLE   (MYDEBUG_USB_PRINTF_MASK)    // :24   走 USB（默认就是这个）
//                            (MYDEBUG_UART_PRINTF_MASK)   //       走串口（PIO0_15，115200）
//   两个都要就写 (MYDEBUG_USB_PRINTF_MASK | MYDEBUG_UART_PRINTF_MASK)

打开后 InfoLog("%u", tick) 展开成 printf("[I]%s: " "%u" "\r\n", __func__, tick)：自动加上 [I]、所在函数名和换行。printf 每输出一个字节就调一次 fputc()，而 my_debug.c:150 把 fputc 改写成“把字节塞进队列”。打开后还会多编译进去一些调试代码（第 6 节的计时、第 3.4 节的打印点）。

3.2 USB 这条路：先排队，主循环再分批发

打日志的地方不会等：字节先进一个 400 字节的环形队列，主循环每圈调一次 MyDebug_Task()（device.c:529），端点空闲时最多取 64 字节，不够 64 的补 0，从 USB 端点 3（接口 2，和 GUI 用的是同一个）发出去。下面可以自己操作一遍。

3.3 串口这条路：用软件“掰”出 115200 波特率

这块板子没有把硬件串口引出来，所以 my_debug.c 用软件模拟串口：把 PIO0_15（25 脚，也就是 SWDIO）当普通 GPIO，用 CT16B1 计时（48 MHz ÷ 6 = 8 MHz，每格 0.125 µs），一位一位地拉高拉低。每圈主循环只发 1 个字节（MyDebug_UartTask，my_debug.c:93），发一个字节要占住 CPU 约 86 µs。输入一个字符看它在线上的样子：

4. 不改代码就能看：GUI 和 hid_tool.py

两者都通过 USB 接口 2（自定义 HID，64 字节一包）按第 6 课第 7 节那套协议问答。不能同时开：同一个接口只能被一个程序占着。打开 USB 日志时，日志和协议回答也挤在同一个端点上，GUI 可能显示乱。

hid_tool.py 命令（study_notes/tools）用的协议T1A 上

watch LR反复发 GET_INFO / 0x01（霍尔原始）+ 0x02（段号）能用，相当于 GUI 的 RowData 面板

5. Keil + J-Link 在线调试（SWD）

5.1 线怎么接

原理图第 2 页右边有一块 “JTAG Program Interface”：5 个焊盘 3V3、SWDIO、SWCLK、nRESET、GND。nRESET 上有 R61 10 kΩ 上拉和 C57 0.1 µF。工程里调试器选的是 J-Link（Sample.uvproj:166 Segger\JL2CM3.dll），勾了 “Run to main()”。

焊盘MCU 脚这只脚在程序里还被用来干什么
SWDIO25 脚 PIO0_15打开串口日志时被设成 GPIO 发数据（my_debug.h:32）
SWCLK19 脚 PIO0_10光学传感器 PAW3950 的 SPI 时钟 SCK0：原理图上这根线同时叫 SWCLK 和 SCLK；PAW3950_Init() 里把它切成 SCK0（PAW3950.c:298~299）
nRESET2 脚 RESET/PIO0_0只当复位用（原理图上这个网络也连到光学传感器的 NRESET 脚）

5.2 开机过程中，SWD 什么时候断

SWD 只靠两根线：SWDIO 和 SWCLK。哪一根被程序改成别的功能，调试器就连不上了（Keil 报通信失败）。按开机顺序看（间隔不按比例）：

所以在 T1A 上
  • 能做：用 J-Link 烧录（复位后脚先回到 SWD 功能，见 5.4 第三条）；在 Device_Init() 里 PAW3950_Init() 之前打断点、单步，看开机初始化。
  • 做不到：程序跑进主循环以后再连上去、在按键算法或线圈代码里打断点。这部分只能靠日志、GUI 和示波器。
  • 如果确实要在主循环里打断点，得临时让光学传感器不初始化（不切 PIO0_10），鼠标移动就没了。这样改之前先问杰哥他平时怎么调。

5.3 停在断点上时要小心（推断）

  • 线圈可能一直通电：CT32B1 的 PWM 是硬件自己出的，CPU 停住它照样输出；而关 PWM 的是 CT32B0 中断（第 6 课第 5 节），CPU 停住就不会执行。所以断点如果正好停在线圈通电的那 500 µs 里，Q4 会一直导通、线圈一直通 7 V，可能发烫。别在 MyWaveform_Start() 之后、中断结束之前停住。
  • USB 会掉线：CPU 停住后不回应电脑的 USB 请求，电脑可能认为设备出错、重新枚举。
  • 看门狗：开机 wwdt_config(0xFFFF)（device.c:419），主循环里喂狗。断点停住时它会不会继续计数、把芯片复位，要实际试。

这三条是按代码和硬件推出来的，没有上板验证。

5.4 用 J-Link 烧录前看一眼这三处

  • 程序放在 0x4000 起：工程里程序区是 0x4000 ~ 0xFFFF（Sample.uvproj:316~319，48 KB），0x0000 ~ 0x3FFF 是公司 bootloader。Keil 的 Utilities → Settings 里擦除方式要是 “Erase Sectors”（只擦用到的扇区）；如果选成 “Erase Full Chip”，会把 bootloader 一起擦掉，之后 USB 升级工具就不能用了。
  • 器件型号：工程选的是 LPC11U37/501（Sample.uvproj:17，128 KB，烧录算法 LPC1xxx_128，Sample.uvopt:145），板上实际是 LPC11U35FHI33/501（64 KB）。因为程序区本身限制在 0x4000 ~ 0xFFFF，超了链接器会报错，所以目前不影响；程序约 44.6 KB，离 48 KB 上限不远。
  • 芯片已经在跑主循环时再连：SWCLK 已经被光学传感器占着，正常方式连不上，要在 Debug → Settings 里把 Connect 改成 “under Reset”（先拉低 nRESET 再连，焊盘里的 nRESET 就是干这个的）。这一条按原理推的，没试过；你们平时一直用 USB 升级工具烧，可以先问杰哥用不用 J-Link。

6. 测一段代码花了多少时间

项目里有现成的写法：20 µs 中断（my_waveform.c:87）开头和结尾各读一次 CT32B0 的 TC（1 µs 一格），相减存进 costTime。

void TIMER32_0_IRQHandler(void)
{
  #if MYDEBUG_ENABLE
  timeStartTc = LPC_CT32B0->TC;                // 进门记一下（:90）
  #endif
  ...  // 正常的中断内容
  #if MYDEBUG_ENABLE
  costTime = LPC_CT32B0->TC - timeStartTc;     // 出门再记，差就是用了几 µs（:110）
  #endif
}

要点：被测的代码里不要打印，打印本身就很费时（串口一个字节约 86 µs），只把结果存进变量；再到别处（比如每 300 ms 那段）用 InfoLog 打出来，或在 J-Link 连着时看变量。CT32B0 只在线圈代码里用来定闹钟，TC 一直在走，主循环里也能这样借来测时间。这个中断每 20 µs 进一次，它本身必须远小于 20 µs，所以值得测一下。

更准的办法是示波器：看 TP35（PWM1），每 20 µs 占空比换一次的时刻，就是中断里 MyPWM_SetDuty 执行的时刻。

8. 不用板子：PC 仿真 key_sim

study_notes/sim/ 里有一个小程序：把仓库里原版的 src/my_misc.c 和一些“替身”头文件一起用 gcc 编译，在电脑上模拟一次按压曲线，每 1 ms 调一次 ProcessRecvSampleRawData()，把滤波值、基线、段号、按键状态全部打印出来。

sh study_notes/sim/build.sh            # 编译（Windows 用 MSYS2 或 WSL）
./study_notes/sim/key_sim 10 30 20 1   # 参数：AP、RT 按下、RT 松开、是否模拟“震动期间冻结”

这次用新代码重新编译过，能编过、能跑。限制：替身里的板型宏是 IRPT_V4（study_notes/sim/stubs/my_board.h），走的是 ADC 板的输入路径，不是 T1A 的霍尔 SPI 路径；算法核心（滤波、分段、RT 判断）两块板是同一份代码，所以用来理解算法没问题。

10. 调试时容易踩的坑

  1. 开了日志忘了关：日志代码占 Flash、占时间，USB 日志还会挤占 GUI 的通道。调完把 MYDEBUG_ENABLE 改回 0 再交给别人。
  2. 日志丢字：队列只有 400 字节（USB）/ 256 字节（串口），满了 MyQueue_Write 直接返回 -3，这个字节就没了。在中断里打日志，如果主循环正好在写队列（mutex = 1），也会丢。一次别打太多，中断里尽量不打。
  3. 开了串口日志，J-Link 就连不上了（SWDIO 被占）。两者只能选一个。
  4. 在被测代码里打印，测出来的时间全是打印的时间。
  5. GUI 和 hid_tool.py 同时开，后开的打不开接口。
  6. 用 setcoil 或 GUI 改配置会写 EEPROM，断电不丢。调完记得改回来，或者心里有数。
  7. 板型宏：编译前确认 my_board.h 选的是 GT_LINA_T1A_H5_PWM（现在是 HAPTIC_V4_PWM）。
  8. 断点停在线圈通电期间，线圈可能一直通电（5.3）。

11. 练习

① 想知道左键每次按下时 wfPeriodUs 实际是多少（开了动态导通时间以后会变），用哪种办法？要改哪几行？

用 USB 日志。my_debug.h:19 改成 1（:24 默认已经是 USB），在 my_electromagnet.c:1022 之后加一行 InfoLog("wf: %u", wfPeriodUs);，编译烧录，电脑上 python hid_tool.py log，关掉 GUI。按下函数不在中断里，打印不会打乱 500 µs 的波形（波形由中断和硬件做）。

② 为什么在 T1A 上不能在 Hall_HandleKeyRapidTrigger() 里打断点单步？

这个函数在主循环里跑，而进主循环前 PAW3950_Init()（device.c:491）已经把 SWCLK 脚（PIO0_10）切成光学传感器的 SPI 时钟（PAW3950.c:298~299），J-Link 和芯片之间的 SWD 连接断了。

③ 一行 35 个字符的日志（含 \r\n），走 USB 要几包？走串口大约多久发完？

USB：35 < 64，一包，后面补 29 个 0。串口：每圈主循环发 1 个字节，每个约 86 µs，至少 35 圈主循环、CPU 被占约 3 ms。
