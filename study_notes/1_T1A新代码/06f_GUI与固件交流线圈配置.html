GUI 改一个振动时长，两边各发生了什么

从“在 GUI 上把左键按下强度拖到 800”开始，一路跟到“下次按左键震 800 µs”。GUI 这一侧只说它做了什么、发了什么包；固件 · C 这一侧逐行读代码。

固件行号以仓库代码为准，你编辑器里一般大 1。

0. 一句话和一张图

GUI 把“哪个键、改哪一项、改成多少”打成一个 64 字节的包，通过 USB 发给鼠标；固件收包、核对校验和、按包里的命令号找到 xgAllParam 里对应的那一格，原样写进去，立刻回一个“成功”包；主循环随后把 xgAllParam 整块存进 EEPROM，再把新值抄进 leftEle。下次按键就用新值。

1. 一个包长什么样

所有命令都用同一种格式。点下面的格子看每个字节是什么。上面的小字是 GUI 数组下标，下面的小字是固件下标：GUI 多一个第 0 字节（HID 报告号，USB 驱动会把它拿掉），所以 GUI 下标 = 固件下标 + 1。

点一个格子。

颜色：报告号 包头 校验和 长度 小标题：类型 / 命令 / 子命令 / 哪个键 数据

决定“改哪一项”的是红色那 4 个字节：类型（请求还是回复）、命令（读还是写）、子命令（按下振动、松开振动、驱动方式…）、哪个键。绿色的数据部分就是 xgAllParam 里那个结构体的原样字节。

2. GUI 端做了什么

GUI 用户松开强度滑条（或点“设置”“增加”“减少”）时，GUI 依次做四件事：
  1. 读出滑条的值 800，拆成低字节 0x20、高字节 0x03；开关固定填 0x80（新版 GUI 把“生效 / 失效”选项隐藏了，默认生效）。
  2. 按上一节的格式拼出包 ①：命令 0x03（设置）、子命令 0x02（按下振动）、键 0x01（左键），后面跟 4 字节数据 00 80 20 03。
  3. 算校验和填进去（见下），通过 USB 发给鼠标。
  4. 记下“我在等‘设置按下振动’的回复”，回复到了再按这个去核对（3.5 节）。

校验和怎么算

除了包头 0x55 和校验和自己，其余字节全部相加，只留低 8 位。GUI 发之前算一次，固件收到后用 my_protocol.c:41 再算一次，两边一致才处理。

例：包 ①（设左键按下 = 800）的校验和：0x02 + 0x01 + 0x08 + 0x00 + 0x02 + 0x03 + 0x02 + 0x01 + 0x00 + 0x80 + 0x20 + 0x03，十进制 2+1+8+0+2+3+2+1+0+128+32+3 = 182 = 0xB6。固件收到后按 my_protocol.c:41 再算一遍，也是 0xB6，对上了才处理。

3.5 GUI 收到回复后做什么

GUI 收到包 ②后，核对它是不是在等的那条回复：子命令是 0x02、键对得上、结果字节 = 1。对上了就在界面上显示绿色“设置成功”，然后马上发“读”命令把参数读回来（第 6 节），确认鼠标里真的是 800。结果字节是 0，或者一直收不到回复，界面就不会显示成功。

7. 静音挡位：4 条命令接力

点挡位 2（2000 µs）时，GUI 不是发一条“挡位 2”，而是发 4 条普通的设置命令：左按下、左松开、右按下、右松开，每条都是 2000。固件根本不知道有“挡位”。

GUI 的做法：按“左按下 → 左松开 → 右按下 → 右松开”的顺序一条一条发，每发一条就等鼠标回“成功”再发下一条；300 ms 没等到就重发一次，还不行就跳过这一条。4 条都发完后再把参数读一遍。按下那两条保持原来的开关位，松开那两条开关固定 0x80。从静音切回正常模式时，先用同样的方式发 4 条时长 0，再发“驱动方式 = 0”。
