一次左键点击全程：读 → 判 → 震 → 报

如果这一页看不太懂：先学 第 3 课（上）读一次霍尔芯片，那里把第 ① 站拆开，每个零件、每个变量都讲了。
这一课只走主线：每一站讲“它干什么、交出什么”，不深挖。后面每一课再把其中一站放大。数字是举的例子（读数、基线都是假设的，各步的微秒时间是粗略估计），算法和代码路径都是真实的。

🧭 本质：一次点击是一场接力。接力棒是数据：霍尔芯片的 4 个字节 → 一个“按下”结论 → 一个“左键位” → USB 报告里的一个字节。每 1 ms 由定时器发令，主循环里的函数一棒传一棒。

学全程时，盯住“数据现在在谁手里、长什么样”，比记住每个函数名更重要。

1. 四站

① 读每 1 ms 通过 SPI1 读两颗霍尔芯片，拿到 4 个字节 ② 判按键算法把读数变成“按着 / 松着” ③ 震刚变成“按着”：左线圈按波形震 0.5 ms ④ 报组成 8 字节鼠标报告，交给 USB 发给电脑

谁来发令？1 ms 定时器中断（TIMER16_0_IRQHandler，Timer.c:65）每 1 ms 把计数 one_ms_cycle 减到 0；主循环里的 Device_Scan()（device.c:878）看到 0，就把它设回 1，并扫描一次按键。所以 ①~③ 每 1 ms 走一遍。

2. 一步一步走一遍

点“下一步”。每一步写着：在哪个函数、干了什么、数据现在长什么样。

3. 每站要点

第 ① 站 · 读

读两颗霍尔芯片

问题左右两颗霍尔芯片串成一条链（第 1 课框图），只有一组 SPI 线。怎么一次把两个读数都拿回来？

一句话：先在时钟线上打一个“命令脉冲”，然后 SPI 连续收 4 个字节。因为数据是从左键芯片流到右键芯片、再从右键芯片出来回到 MCU，所以先到的是右键：hall_spi_rx[0]、[1] 是右键，[2]、[3] 是左键。

每个键 2 字节 = 2 位校验 + 14 位读数：高字节的最高 2 位是校验位，剩下 6 位和低字节拼成 14 位（0 ~ 16383）。
例：左键收到 0xE2 0xE7 → 0xE2 & 0x3F = 0x22 = 34 → 34 × 256 + 0xE7(231) = 8935。

你来算：左键收到 0xA4 0x54，14 位读数是多少？
对上代码：LR_GetState()、hall_get_sample()（app/button.c:311、800、858） 
858  void hall_get_sample(void)
859  {
860    Hall_CLK_Command_SET(TD1_DELAY_US, TD2_CONTIUNS_DELAY_US);   // 时钟脚当 GPIO：拉高约 4 µs、拉低约 4 µs
862    SSP_Send_Receive(hall_spi_tx, hall_spi_rx, 4);              // SPI1 收发 4 字节，收到的放进 hall_spi_rx
863  }

Hall_CLK_Command_SET()（button.c:800）在 T1A 上把 PIO1_15 临时切成 GPIO 打脉冲，打完切回 SCK1，期间关掉 USB 中断。命令脉冲的意义、为什么是 4 µs，第 3 课讲。

第 ② 站 · 判

按键算法：读数 → 按着 / 松着

问题读数只是一个数，怎么知道按没按？每只鼠标、每颗磁铁的数都不一样。

一句话：ProcessRecvSampleRawData()（my_misc.c:418）对每个键：校验 → 取反（16383 − 读数，T1A 上按下读数变小，取反后变成“按得越深数越大”）→ 滤波 → 换算成段位 0~100（当前值在“没按”和“按到底”两条基线之间的位置）→ 快速触发判断按下 / 松开 → 结论写进 gbKeyState[k]。最后返回一个字节：第 0 位 = 左键，第 1 位 = 右键。

例：左键读数 8935 → 取反 7448。假设两条基线是 7083（没按）和 8883（按到底），段位 = 31。松着时从最浅点 0 按到 31，超过了按下距离 30 → 判“按下”。

你来算：读数 8935，取反后是多少？
左键按着、右键松着，这个函数返回几？
对上代码：骨架（my_misc.c:418~668） 
uint8_t ProcessRecvSampleRawData(uint8_t* pData, uint16_t length)
{
  if(cali_init_cnt)            // 开机后最多 600 ms：只学“没按”的基线，不判断
  { ... Hall_InitBaseline() ... }
  else
  {
    for(k = 0 右键, 1 左键)
    {
      线圈在震 → 沿用上次结论，跳过            // 震动会干扰读数
      校验（2 位）→ 14 位读数 → 16383 − 读数
      滤波（变化 ≤ 60 时只走 1/64）
      段位 = Hall_CalculateNode()              // 0~100
      Hall_HandleKeyRapidTrigger()             // → gbKeyState[k]
      校准两条基线
    }
  }
  左键按着 → 返回值第 0 位 = 1；右键按着 → 第 1 位 = 1
}

每一步怎么算，第 4 课细讲（ADC 串讲第 5~10 关是同一个算法，只是那边的数是 10 位）。

第 ③ 站 · 震

刚变成“按着”：左线圈震一下

问题算法每 1 ms 都会说“按着”。线圈只该在刚按下那一下震，怎么区分？

一句话：Button_Scan()（button.c:605）记着上一次的状态 scan_result_pre。这次和上次不一样、而且这次是“按着” → 调 Ele_LeftKeyPressProcess()（button.c:639）。它算出震动时长（默认 500 µs），启动波形：MyWaveform_StartGenerate(通道 0, 波形表, 500 µs, 1 遍)。之后 CT32B0 中断每 20 µs 改一次 PIO0_13 上 PWM 的占空比（60% → 100% → 60%），放完 25 个点就停。

震动期间读数会被干扰，所以算法在线圈震动、以及震完后 8 ms 内不看这个键的读数，结论沿用上一次。

你来算：震动时长 500 µs，每 20 µs 改一次力度，一共改几次？
对上代码：Ele_LeftKeyPressProcess()（src/my_electromagnet.c:982） 
if(leftEle.pressVibrateDurationUs)                      // 时长不为 0 才震（默认 500 µs，来自 EEPROM 参数）
{
  if(右线圈正在震) { 先记下来，稍后再震; return; }        // 同一时间只震一个线圈（SINGLE_COIL_AT_A_TIME）
  wfPeriodUs = Ele_CalculateDuration(ELE_POS_LEFT, nowHallSegment[0], leftEle.pressVibrateDurationUs);
  leftEle.status = ELE_PRESS_VIBRATING;                 // 状态：按下在震
  leftEle.vibrateBeginTick = MyTick_GetTickMs();        // 记下开始时间
  MyWaveform_StartGenerate(CHANNEL_0, pLeftWf, wfPeriodUs, 1);   // 启动波形，之后在中断里自己跑
}

主循环里的 Ele_PollingTask() 负责看时间：震完 → “震后消抖”8 ms → 回到“不震”。PWM、波形、状态机分别是第 5、6、7 课。

第 ④ 站 · 报

告诉电脑：8 字节鼠标报告

问题电脑怎么知道左键按下了？

一句话：Button_Scan() 返回“有变化” → Device_Button_Scan()（device.c:952）把按键结果写进 wheel_button_status，挂一个“按键事件”；Device_Pack() 通过 Custom_HandleKey()（键位映射）把它变成鼠标报告；Device_Report() 把 8 字节放进 USB 端点 1，电脑来取时拿走。
字节[0][1][2] [3][4] [5][6][7]
含义报告编号 0x01按键：第 0 位左、第 1 位右、第 2 位中……X 位移Y 位移滚轮横向滚轮

你来算：左键和右键同时按着，报告的第 [1] 字节是几？

4. 松开的时候

路线完全一样，只是方向反过来：② 判出“松开”（从最深点往回抬超过 20 段）→ ③ 调 Ele_LeftKeyReleaseProcess()，松开也震一下（模拟机械按键弹起的“咔”）→ ④ 报告第 [1] 字节第 0 位变回 0。

补充：霍尔芯片是哪颗（已和杰哥确认）
inc/button.h:16 写着 USE_HALL_SENSOR 5（注释：GTRY12: 2, GTRY15: 5, GTRY16: 6）。杰哥确认这块板按 H5 设计：H5 = 第 5 代霍尔 = GTRY154（手册 materials/GTRY154_Magnetic_Keyboard_Sensor_and_LED_Driver_V1.1_20240719.pdf 第 1 节写着 “5rd generation”）。原理图上标的 GTRY164 是第 6 代。手册第 7.7 节的时序（命令脉冲 td1 = 5 µs、写寄存器 td4 = 24 µs……）和代码里 5 号那组常数一致。
本课第 ① 站的校验规则也来自这份手册第 7.2 节：CRC0 = D0^D2^…^D12（偶数位异或），CRC1 = D1^D3^…^D13（奇数位异或）。代码里的 bit_error 表就是把这两个式子提前算好了，我用全部 16384 个值核对过，完全一致。
💡 想法上：读“全程”时容易陷进去：看到一个函数就想把它读懂，结果读了半天还没走到 USB。更好的办法是先只问每一站“输入什么、输出什么”，把整条线走通，再回头一站一站深挖。这和读长函数时“先画骨架”是同一个道理：先有地图，再看街道。
