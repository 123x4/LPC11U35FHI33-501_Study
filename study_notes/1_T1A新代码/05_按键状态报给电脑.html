按键状态怎么变成 USB 包发给电脑

第 4 课的 ProcessRecvSampleRawData() 最后返回 2 位：第 0 位左键、第 1 位右键。这一课接着往下追：这 2 位怎么和其他按键拼在一起、怎么按“键位设置”翻译成鼠标按钮、怎么和光学传感器的移动量一起装进一个 8 字节的鼠标报告、放进 USB 的端点缓冲区，最后被电脑取走。还会讲清楚：没有新数据时发什么（答案：什么都不发）。

🧭 本质：鼠标不是“每 1 ms 把状态报一遍”，而是有变化才报：按键变了，或者光学传感器测到移动，才拼一个 8 字节的包放进 USB 缓冲区。电脑每 1 ms 来问一次“有新数据吗”，缓冲区里有就取走，没有就得到一个“没有”（NAK）。电脑那边会一直记着上一次的按键状态，所以按住不动时不需要重复发。

1. 全程：从 2 位到电脑

每一个方框是一个“数据容器”（变量），方框之间的箭头是做搬运的函数。主循环 Device_Active()（device.c:495）每圈依次调用 Device_Scan() → Device_Pack() → Device_Report()。

点任意一个方框看它装的是什么。

2.2 button_port_state / wheel_button_status：所有物理按键的“现在按着没有”

Button_GetState()（button.c:564）把中键、DPI 键、两个侧键（从 GPIO 读）和左右键（从霍尔算法来）拼成一个 32 位数，每个键占固定的一位（button.h:100~107，scroll.h:8~9）：

b9b8b7b6b5b4b3b2b1b0 DPI 键GPIO音量−T1A 无音量+T1A 无K5 侧键GPIOK4 侧键GPIO滚轮下滚轮暂关滚轮上滚轮暂关中键GPIO右键霍尔左键霍尔

Button_Scan()（button.c:605）比较这次和上次：有一位变了，就记进 buttonScan_stru.scan_result_pre、把 button_changed 置 TRUE，并让线圈振动（按下 / 松开振感，后面的课）。左右键没有消抖，中键、侧键有（按下等 5 次、松开等 8 次）。然后 Device_Button_Scan()（device.c:961~965）：

if(Button_Scan())                                        // 有键变了
{
    wheel_button_status &= ~ALL_BUTTON_REPORT_BIT;       // 清掉所有按键位（保留滚轮位）
    wheel_button_status |= buttonScan_stru.scan_result_pre;  // 换成最新的按键状态
    DEVICE_POST_EVENT(BUTTON_EVENT);                     // 在 deviceEvent 里挂一个“按键事件”标志
}

DEVICE_POST_EVENT 就是在全局变量 deviceEvent 里把 BUTTON_EVENT 这一位置 1，表示“有按键变化，等着打包”。没变化就不挂。

2.4 鼠标报告：8 字节（报告 ID 1）

格式由 HID 报告描述符规定（usbdesc.c:36 HID_ReportDescriptorMouse），电脑一插上就读它，从此知道每个字节是什么意思：

字节 0字节 1字节 2字节 3字节 4字节 5字节 6字节 7 0x01报告 ID按钮5 位 + 3 位填充X 低int16X 高Y 低int16Y 高滚轮int8横滚int8（AC Pan）

字节 1 的每一位：

b7b6b5b4b3b2b1b0 填充(M2 0x80)填充(M1 0x40)填充按钮 5K4 侧键按钮 4K5 侧键按钮 3中键按钮 2右键按钮 1左键
  • 描述符写的是 5 个按钮（Usage 1~5，Report Count 5，每个 1 位），再加 3 位常量填充（usbdesc.c:46~57）。代码里功能 0xBA / 0xBB 会写 0x40 / 0x80，但描述符里那 3 位是“填充”，电脑会忽略。
  • X、Y：有符号 16 位，低字节在前，−32767 ~ 32767，是“这次和上次之间移动了多少”（相对量），来自 PAW3950。
  • 滚轮、横滚：有符号 8 位，+1 / −1 表示滚了一格。T1A 现在滚轮扫描关着（ENABLE_WHEEL_SCAN = 0）。
  • 端点最大包长 16 字节（usbdesc.c 里 wMaxPacketSize = 0x10），8 字节装得下。

5. 端点缓冲区：包放在哪、电脑怎么取、没数据怎么办

步骤谁做代码缓冲区发生什么
① 等缓冲区空软件device.c:694~701：最多问 60 次 nsAPI_USB_EP_Status()，每次之间等 nsAPI_SSP_Delay1us(10)看缓冲区的 ACTIVE 位：1 = 上一个包还没被电脑取走；0 = 空了（usbhw.c:1429~1450）
② 写报告软件device.c:702~704 → USB_LoadInEP_Data()（usb.c:244）→ nsAPI_USB_WriteEP()（usbhw.c:1241）把 8 字节复制进 USB RAM 里端点 1 的缓冲区，写好长度，置 ACTIVE = 1（usbhw.c:1294）
③ 电脑来问电脑 + USB 硬件不用软件参与电脑每 1 ms（bInterval = 1）发一个 IN 令牌问端点 1：ACTIVE = 1 → 硬件把 8 字节发出去，清 ACTIVE；ACTIVE = 0 → 硬件回 NAK（“没有新数据”）
④ 电脑收到Windows—按描述符解包：按钮状态保存下来一直有效；X / Y / 滚轮是“增量”，用一次就没了
没有新数据时会怎样？
  • 软件：deviceEvent 没有事件 → Device_Pack() 第 553 行直接 return；data_type = 0 → Device_Report() 第 674 行直接 return。什么都不写。
  • USB 硬件：缓冲区 ACTIVE = 0，电脑每 1 ms 来问，硬件自动回 NAK。这一来一回不需要 CPU 参与。
  • 电脑：收到 NAK 就当“没变化”，按键状态保持上一次的。所以按住左键不动，只在按下那一刻发一个包，松开那一刻再发一个，中间一个包都不用发，电脑也一直认为左键是按着的。
按住左键的同时移动鼠标，为什么左键状态不会丢？

移动产生的是 OPTICAL_EVENT，打包时（device.c:584~598）manual_mouseReport 是新建的全 0 数组，所以要把按钮字节补回去：manual_mouseReport[1] = mouseReport_back[1]。mouseReport_back（device.c:77）是上一次按键报告的备份（device.c:571~574 每次按键报告后都存一份）。这样每个移动包都带着当前的按钮状态。

如果等了 60 次缓冲区还是满的？

Device_Report() 等完 60 次（每次约 6 ~ 10 µs，估计总共不到 1 ms）不管结果，照样调 USB_LoadInEP_Data()，而它里面也不检查（usb.c:291 的检查被注释掉了）。端点开了双缓冲（usbhw.c:320 EPBUFCFG = 0x3FC），正常情况下来得及；但如果电脑长时间不来取（比如电脑卡住、USB 挂起），新包可能写进还没发出去的缓冲区，覆盖掉上一个包。（推论，没有上板验证。）如果被覆盖的正好是“按下”或“松开”的包，电脑会漏掉一次状态变化。

6. 这只鼠标的三个 USB 接口

接口端点方向装什么代码
0：鼠标（Boot 鼠标）EP1 IN（0x81）鼠标 → 电脑鼠标报告（ID 1，8 字节）；多媒体报告（ID 5，3 字节）也走这里Device_Report() device.c:683、704
1：键盘EP2 IN（0x82）鼠标 → 电脑键盘报告 8 字节：修饰键、保留、6 个键码（键被设成键盘键 / 宏时用）device.c:728
2：自定义（GUI 用）EP3 IN（0x83）/ EP4 OUT（0x04）双向第 4 课（续）讲的 64 字节协议包my_protocol_mouse.c

两种格式：电脑在 BIOS 等简单环境里会把鼠标切到“Boot 协议”（HID_Protocol = 0，hiduser.c:144），这时 Device_Report() 走 else 分支（device.c:706~719），只发 3 字节：按钮（只留低 3 位）、X 低字节、Y 低字节。正常进 Windows 后是“报告协议”（HID_Protocol = 1），发上面的 8 字节。
