开机怎么把霍尔芯片准备好

上一课（①）把 MCU 这边的 SPI1 准备好了。这一课准备线那头的两颗霍尔芯片。一共三件事：① 给芯片通电，② 让芯片把自己的时钟校准，③ 把 25 个设置写进芯片。做完这三件，芯片才会每 124 µs 自己测一次磁场，第 3 课（上）每 1 ms 的读取才读得到有用的数。

这一课为什么这样安排（根据你前面的提问）

你前面问过“写 DR 就启动转换吗”“填的 A7 00 是随意的吗”，说明你会追问“芯片为什么会这样做”。这一课的三件事，每件都先讲不做会怎样，再讲代码怎么做。三件事的“样子”不一样，所以图也画得不一样：通电画成开关和电线，校准画成一把尺子和一张逐次变准的图，写设置画成寄信 + 填表。最上面先放一条“开机路线”，随时知道自己在哪一站。

🧭 本质：霍尔芯片是一颗独立的小芯片，有自己的电源、自己的时钟、自己的一张设置表。刚通电时它用出厂默认设置：只在收到命令时才测一次（单次转换模式），放大倍数也不是我们要的。MCU 要先让它的时钟准（否则它会认错命令），再把设置表改成我们要的值。改完最后一个关键设置（0x18 = 0x8E），它就开始自己每 124 µs 测一次。

3. 第一件事：给芯片通电（GPIO.c:576~584）

两颗芯片的电不是一直接着的，中间有一个电子开关：原理图上 PIO0_16（Hall_PWR_EN）→ 三极管 Q3 → MOS 管 MOS1 → VDD_Hall → 两颗芯片。PIO0_16 输出高，开关闭合，芯片有电；输出低，开关断开，芯片断电。点下面两个按钮试试。

IOCTRL_NoPull(HALL_EN);                         // 576 不要上拉下拉
IOCTRL_LowLevel(HALL_EN_PORT, HALL_EN_PIN);     // 577 先准备输出“低”  → 开关断开 = 断电
IOCTR_PushPull(HALL_EN);                        // 578 推挽输出（能输出高也能输出低）
IOCTRL_CfgAsOutput(HALL_EN_PORT, HALL_EN_PIN);  // 579 设成输出：从这一刻起脚上真的是低
for(uint8_t i = 0; i < 50; i++)                 // 580
{ nsAPI_SSP_Delay1us(1000); }                   // 582 名义 50 × 1000 µs = 50 ms
IOCTRL_HighLevel(HALL_EN_PORT, HALL_EN_PIN);    // 584 输出高 → 开关闭合 = 通电

HALL_EN 在 my_board.h:361~363 定义成 PORT 0、PIN 16，也就是 PIO0_16。

为什么先断电 50 ms 再通电，而不是直接通电？

MCU 可能是在芯片一直有电的情况下重新启动的，比如看门狗复位、从 bootloader 跳过来、USB 重新插拔。这时两颗芯片还保持着上一次写的设置，甚至正在连续转换。先断电，等电源上的电容放完电，再通电，芯片就一定是从出厂默认状态开始的，后面的校准、写设置都从一个确定的起点出发。厂商参考代码 Hall_Power_Reset()（materials/H5_Sample_code_20260210/ana_sw_hal.c）也是这样做的：先放电，等 20 ms，再通电。

50 ms 准不准：nsAPI_SSP_Delay1us()（device.c:1363）不是用定时器，而是空转一个小循环。反汇编看，每“1 µs”大约转 29 个时钟周期，48 MHz 下约 0.6 µs，再加上 Flash 等待会更长一点。所以名义 50 ms 实际估计在 30 ~ 50 ms（没上板量过）。这里只要“够放完电”就行，不需要很准。

4. 第二件事：校准芯片的时钟（button.c:872~907）

4.1 不校准会怎样：芯片是靠“量时间”认命令的

第 3 课（上）讲过：MCU 和芯片之间没有专门的命令线，MCU 用“把 SCK 拉高多久”来告诉芯片要做什么。手册 7.7 节规定了每个命令的高电平宽度，误差只能有 ±5%：

命令SCK 拉高多久芯片收到后做什么
HAL_CONVERTtd1 = 5 µs ± 5%把最新测到的磁场值放进自己的 16 位里，等 MCU 读（第 3 课上）
W_PWM_REGtd3 = 9 µs ± 5%写 LED 的 PWM（本项目不用）
SLEEPtd11 = 15 µs ± 5%进入睡眠（本项目不用）
WR_REGtd4 = 24 µs ± 5%把 16 位里的数据写进设置表（本课第 5 节）
FREQ_Calibratetd7 = 128 µs ± 5%校准自己的时钟（本节）

芯片要量“高了多久”，只能用它自己内部的时钟去数。如果它的时钟偏快 10%，数出来的时间就会偏长 10%：MCU 明明拉高了 5 µs，它以为是 5.5 µs，超出了 5 µs ± 5% 的范围，就认不出这是“读按键”命令。拖动下面的滑块，看芯片时钟偏多少会出问题。

动手：芯片时钟的偏差

绿色竖条 = 手册允许的范围（±5%）。横条 = 芯片用自己的时钟量到的宽度。这是示意：手册只规定了 ±5%，没写芯片内部怎么量；这里按“芯片用自己的时钟数高电平有多长”来画，便于理解为什么要校准。

所以手册第 9 节规定：芯片上电后第一件事就是校准时钟（Step1），然后才能配置参数（Step2）。原文：“Correct the frequency to ensure that the chips on the daisy chain are kept in sync”（校正频率，保证菊花链上的芯片保持同步）。

4.2 一次校准命令长什么样

校准命令就是把 SCK 拉高 128 µs，再拉低一小会儿，然后照常打 32 下时钟，把两颗芯片的“频率值”读回来（手册图 8：读回 16 位，低 8 位有效）。下面是本项目代码发一次校准命令时 SCK 线上的样子（宽度没按比例画）：

void HALL_Read_Instru_cnt(void)                    // 865
{
    Hall_CLK_Command_SET(TD7_DELAY_US, TD10_DELAY_US); // 867 SCK 拉高 ≈128 µs，再拉低 ≈2~3 µs
    SSP_Send_Receive(hall_spi_tx, hall_spi_rx, 4);     // 869 打 32 下，读回两颗芯片的频率值
}

5. 第三件事：把 25 个设置写进芯片（button.c:930~950）

5.1 一条“写设置”的 16 位长什么样

芯片的设置表是一排 8 位的小格子，每格有一个 6 位的地址（0x0A ~ 0x27）。要改某一格，MCU 先把下面这样的 16 位推进芯片的 16 位移位寄存器（和第 3 课上读数据用的是同一个 16 位），再把 SCK 拉高 24 µs（WR_REG 命令），芯片就照着这 16 位去改（手册 7.4 节、图 6）：

b15b14b13b12b11b10b9b8b7b6b5b4b3b2b1b0 WRCRCA5A4A3A2A1A0D7D6D5D4D3D2D1D0 第一个字节第二个字节 = 要写的值
  • WR（b15）：1 = 写，0 = 读。这里写，所以固定是 1，就是代码里的 | 0x80。
  • CRC（b14）：校验位 = 8 个数据位异或起来，也就是“数据里 1 的个数是奇数就是 1，偶数就是 0”。手册：校验位不对，这条命令作废（芯片不写）。
  • A5~A0（b13~b8）：要改哪一格的地址。
  • D7~D0（b7~b0）：要写进去的值。
动手：选一行设置，看这 16 位怎么拼出来 
hall_spi_tx[j*2+0] = sensor_reg_init_array[i][0]       // 945 地址（A5~A0）
                     | 0x80                             //     WR = 1
                     | bit_crc_write_reg[sensor_reg_init_array[i][1]];  // CRC：查表，值是 0x40 或 0
hall_spi_tx[j*2+1] = sensor_reg_init_array[i][1];       // 946 要写的值

bit_crc_write_reg[256]（button.c:23）是一张提前算好的表：下标是要写的值，表里存的是 0x40（1 的个数为奇数，CRC = 1，放在 b6 = 第一个字节的 0x40 位）或 0。我把 256 个值逐个和手册公式核对过，全部一致。

5.2 写一行设置的全过程：寄信 + 填表

每写一行设置，分三拍：① 软件填 tx → ② SPI1 打 32 下，把两封“信”推进两颗芯片 → ③ SCK 拉高 24 µs，两颗芯片同时“拆信、填表”。两颗芯片写一样的值，所以 tx 里两封信内容一样（j 循环 2 次）。先推出去的那封走得最远，进右键芯片；后推的那封停在左键芯片（和第 3 课上读数据时的顺序一样）。

void Hall_write_register(void)                       // 930
{
    SSP_Send_Receive(hall_spi_tx, hall_spi_rx, 4);   // 932 拍②：打 32 下，两封信进芯片
    Hall_CLK_Command_SET(TD4_DELAY_US, TD5_DELAY_US);// 934 拍③：SCK 高 ≈23 µs（WR_REG），再低 >2 µs
}
void ana_hall2_phy_set_mode(unsigned char length)    // 937，HallSensor_INIT 传进来 length = 2（两颗芯片）
{
    for(i = 0; i < REG_CNT; i++)                     // 941 REG_CNT = 25 行（inc/button.h:12）
    {
        for(j = 0; j < length; j++)                  // 943 j = 0、1：两封信
        { hall_spi_tx[j*2+0] = …; hall_spi_tx[j*2+1] = …; }  // 945~946 拍①
        Hall_write_register();                       // 949 拍② + 拍③
    }
}
写设置时 SCK 拉高够不够 24 µs？

TD4_DELAY_US = DELAY_OUT(24) = 23，CT16B1_DelayUs(23) 只数 21 µs，加开销约 1.8 µs，估计 ≈ 22.8 ~ 24 µs。手册要求 24 µs ± 5% = 22.8 ~ 25.2 µs，正好落在下边缘。和“读按键”命令偏短的问题（待确认 0d）是同一个原因，需要用示波器一起量。

5.3 25 行设置一览

数据来自 sensor_reg_init_array[25][2]（button.c:226，T1A 走 GT_LINA_T1A_H5 分支），默认值和含义来自霍尔手册第 8 节。黄色的 6 行是真正改了出厂默认值的，其余 19 行写的就是默认值（写一遍是为了保险：不管芯片之前处于什么状态，写完都确定）。

最关键的是 0x18（第 15 行）：默认 0x0A 的第 2 位是 0（单次转换：MCU 每发一次命令才测一次）。写成 0x8E 后第 2 位 = 1，芯片切到连续转换：从这一刻起它自己每 124 µs（0x0A 定的）测一次，MCU 发“读按键”命令时直接拿最新的值。所以第 3 课（上）里“命令后只要等 td2 > 2 µs（连续模式）”，而不是单次模式要等的 > 80 µs。

5.4 顺便解开第 3 课（上）的一个谜：tx 里的 A7 00 A7 00 是哪来的

第 3 课（上）里，每 1 ms 读按键时发出去的是 A7 00 A7 00，当时只说是“填充的字节”。现在能看出它的来历了：

  • 25 行里最后一行是 {0x27, 0x00}（温度补偿）。
  • 第一个字节 = 0x27 | 0x80 | CRC(0x00)。0x00 里 1 的个数是 0（偶数），CRC = 0，所以 = 0xA7；第二个字节 = 0x00。
  • 写完这一行，hall_spi_tx 就停在 A7 00 A7 00。之后再也没有代码改它（只有调试开关 MYDEBUG_ENABLE 打开时 Hall_ReadReg() 会改），所以主循环每次读按键时，发出去的都是“写设置留下的最后一行”。

它不是特意选的值。读按键时芯片不看 SDI 进来的内容，所以发什么都行。

6. 常见疑问

Q1：校准之前芯片的时钟不准，它怎么认得出 128 µs 的校准命令？

手册没写。可以看到 128 µs 比其他命令长得多（最长的 WR_REG 才 24 µs），就算芯片时钟偏 10% ~ 20%，也不会把它和别的命令搞混。（推测：正因为这样，才选一个特别长的脉冲来做校准。）

Q2：为什么校准完要先等？代码在 device.c:457 等了 500 ms 才开始校准。

500 ms 是在校准之前等的，不是之后。霍尔手册正文没写上电后要等多久；这 500 ms 是代码留的余量，让芯片电源稳定。这段时间 MCU 同时在做 USB 初始化等其他事情。

Q3：写设置时 hall_spi_rx 收到了什么？

收到的是两颗芯片移位寄存器里原来的 16 位（上一封信，或者校准时的读回值），被新的信挤出来了。代码不看它。

Q4：两颗芯片能写不同的值吗？

能。tx[0..1] 进右键芯片，tx[2..3] 进左键芯片，分开填就行。现在 945~946 行两封信填的一样，所以两颗芯片设置一样。如果以后左右键要不同的放大倍数，就改这里。

Q5：写进去的值有没有读回来确认？

开机时没有。代码有读寄存器的函数 Hall_ReadReg()（button.c:917），但只在调试开关 MYDEBUG_ENABLE 打开时，用来把 0x14、0x16 的值打印出来（button.c:415~417）。

Q6：芯片刚通电到 SPI1 准备好之前，SCK 线是什么状态？

推论（没上板验证）：PIO1_15 复位后是普通输入脚、开着内部上拉（芯片手册表 115，复位值 0x90，MODE = 上拉）。在 InitSPI1Master()（device.c:441）把它切成 SCK1 之前，SCK 线可能被这个上拉拉成高电平，持续若干毫秒。芯片看到的是一个“很长的高电平”。后面先等 500 ms、再连发 30 次校准，估计能把芯片拉回正常；但芯片对这种长高电平怎么反应，手册没写。已记进待确认问题。
