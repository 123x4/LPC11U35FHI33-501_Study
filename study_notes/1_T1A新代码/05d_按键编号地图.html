按键编号地图：代码里每一种“这是哪个键”的写法

同一个键，在引脚寄存器里、霍尔缓冲里、按键算法里、按键变量里、消抖数组里、按键映射表里、USB 报告里、线圈和 GUI 参数里，各有各的编号。这一页把每一种都单独画成一张图，图上方是定义它的代码。读代码时看到一个下标或位号拿不准是哪个键，就来这里查。

0. 总览：一个键从“被按下”到“电脑收到”，换了几次编号

代码里描述“哪个键”的方式不止一种。下图是按键信息流动的路线，每个框是一种编号方式，框里写了左键在这里是几号。点框跳到对应那一节的图。

1. GPIO 端口 0 的引脚寄存器：中键、DPI、K4、K5 在第几位

inc/my_board.h:335~346（T1A 引脚号）、inc/button.h:70~90（POSITION、MASK）、:149（BUTTON_PORT0）
#define MIDDLE_BUTTON_PIN   7      // my_board.h:342  中键 = PIO0_7（16 脚）
#define DPI_BUTTON_PIN      23     // :345            DPI  = PIO0_23（27 脚）
#define FRONT_BUTTON_PIN    11     // :336            K4   = PIO0_11（21 脚，原理图 L_FORWARD）
#define BACK_BUTTON_PIN     12     // :339            K5   = PIO0_12（22 脚，原理图 L_BACK）
#define BUTTON_PORT0 (U32)((~LPC_GPIO->PIN[0]) & (MIDDLE_BUTTON_MASK | DPI_CYCLE_BUTTON_MASK | K5_BUTTON_MASK | K4_BUTTON_MASK))  // button.h:149
LPC_GPIO->PIN[0] 是端口 0 的 32 只脚此刻的电平，第 n 位 = PIO0_n。按键按下时脚被拉到地，读到 0，所以先取反 ~，再用 MASK 只留下这 4 位。这里的位号就是引脚号，和后面的按键编号不一样。左右键不在这里：它们没有开关，靠霍尔芯片。

2. 霍尔 SPI 缓冲 hall_spi_rx[4]：前两个字节是右键，后两个是左键

app/button.c:346、:363；第 3 课（两颗霍尔芯片串成一条链）
hall_get_sample();                                               // button.c:346  SPI1 收 4 个字节进 hall_spi_rx[]
result = ProcessRecvSampleRawData((uint8_t *)(&hall_spi_rx), 4); // :363          交给按键算法
两颗霍尔芯片串成一条链：MCU 先收到的是右键那颗（链的末端）的两个字节，再收到左键的。每颗 14 位读数 + 2 位校验，占 2 个字节。

3. 按键算法的下标 k：k = 0 是右键，k = 1 是左键

src/my_misc.c:444~458（取读数）、:657~665（返回值）；inc/my_hallkey_func.h:17（ANA_TOTAL_COUNT = 2）
temp[k] = ana_phy_bit_error_checker2(ana_rd_buff[2*k], ana_rd_buff[2*k + 1]);  // my_misc.c:458  k=0 取 [0][1]，k=1 取 [2][3]
...
if(gbKeyState[0]) { ret |= (0x01 << 1); }   // :657~660  k=0（右）→ 返回值 bit1
if(gbKeyState[1]) { ret |= (0x01 << 0); }   // :662~665  k=1（左）→ 返回值 bit0
return ret;
按键算法里所有两格的数组（temp[]、gbKeyState[]、gwTopBaseline[]、gwBottomBaseline[]、previousKeySta[] …）都按 k 排：[0] 右、[1] 左，跟着霍尔缓冲的顺序来。最后返回时交叉一下，变成 bit0 左、bit1 右，和后面的按键编号对上。

4. 内部按键编号：button / scan_result_cur / scan_result_pre 的 32 位

inc/button.h:100~107（REPORT_BIT）、app/button.c:564~602（Button_GetState 拼出来）
#define LBFT_BUTTON_REPORT_BIT        0u   // 左
#define RIGHT_BUTTON_REPORT_BIT       1u   // 右
#define MIDDLE_BUTTON_REPORT_BIT      2u   // 中
#define K4_BUTTON_REPORT_BIT          5u
#define K5_BUTTON_REPORT_BIT          6u
#define VOLUME_UP_BUTTON_REPORT_BIT   7u   // T1A 没有这两个键
#define VOLUME_DOWN_BUTTON_REPORT_BIT 8u
#define DPI_CYCLE_BUTTON_REPORT_BIT   9u
固件内部统一用这套编号描述“哪个物理键按着”，1 = 按下。button（这一刻）、scan_result_cur（最近看到的）、scan_result_pre（确认过的）三个变量都是这个格式。bit3、bit4 留给滚轮（第 6 节）。名字里有 REPORT，但不是 USB 报告里的位。

5. Button_Location_Data()：把引脚位挪到按键编号位

app/button.c:290~309（函数）、:571~574（四次调用）
reportMask = port & mask;              // :295  只留这一位
if (reportPosition > position) reportMask <<= (reportPosition - position);  // :297~301 往高位挪
else                           reportMask >>= (position - reportPosition);  // :302~306 往低位挪
return reportMask;
从第 1 节的“引脚号”挪到第 4 节的“按键编号”。四个键都是往低位挪。左右键不走这个函数，直接来自第 3 节的返回值（button.c:598 |= LR_GetState()）。

6. wheel_button_status：要交给按键映射的状态（按键 + 滚轮）

src/device.c:51（定义）、:963~964（按键写入）、:996~997（滚轮写入）；inc/scroll.h:8~9
wheel_button_status &= ~ALL_BUTTON_REPORT_BIT;           // device.c:963  清掉所有按键位（bit0,1,2,5,6,7,8,9）
wheel_button_status |= buttonScan_stru.scan_result_pre;  // :964          放进确认过的按键状态
#define WHEEL_UP_REPORT_BIT    (1<<3)                       // scroll.h:8    滚轮上 = bit3
#define WHEEL_DOWN_REPORT_BIT  (1<<4)                       // scroll.h:9    滚轮下 = bit4
和第 4 节同一套编号，只是把空着的 bit3、bit4 填上了滚轮（T1A 上滚轮扫描关着，ENABLE_WHEEL_SCAN = 0，所以这两位一直是 0）。一共 10 位（bit0~9），正好对应第 8 节的 10 个映射格子。

7. debounce[6]：6 个消抖计数器各给谁

inc/button.h:166；app/button.c:673（[i]）、:714（[i − 2]）、:764（[i − 4]）
buttonScan_stru.debounce[i]     = 5;   // button.c:673  中键 i=2 → [2]
buttonScan_stru.debounce[i - 2] = 5;   // :714          K4 i=5 → [3]，K5 i=6 → [4]（T1A 关了）
buttonScan_stru.debounce[i - 4] = 5;   // :764          DPI i=9 → [5]
数组只有 6 格，按键编号最大到 9，所以用“减一个偏移”把用到的键挤进 0~5。左右键不消抖，[0][1] 空着。

9. USB 鼠标报告：最后发给电脑的 8 个字节

app/custom.c:722~770（Custom_Deal_MouseKey：id → 报告的位）；第 5 课
case 0xB0: mouse_temp[1] |= 0x01; break;   // 左  → 第 1 字节 bit0
case 0xB1: mouse_temp[1] |= 0x02; break;   // 右  → bit1
case 0xB2: mouse_temp[1] |= 0x04; break;   // 中  → bit2
case 0xB3: mouse_temp[1] |= 0x10; break;   // K4 → bit4（前进）
case 0xB4: mouse_temp[1] |= 0x08; break;   // K5 → bit3（后退）
case 0xB5: mouse_temp[6] = 0x01;  break;   // 滚轮上 → 第 6 字节 = +1
case 0xB6: mouse_temp[6] = 0xff;  break;   // 滚轮下 → 第 6 字节 = −1
这才是 USB 报告里的位置。注意 K4 / K5 在内部编号里是 bit5 / bit6，到了 USB 报告里变成 bit4（前进）/ bit3（后退），顺序还反过来了。DPI 键（0xC1）不进鼠标报告，由固件自己处理（切换 DPI）。
