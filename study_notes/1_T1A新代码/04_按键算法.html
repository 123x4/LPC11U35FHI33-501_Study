按键算法：一个读数怎么变成“按下了”

第 3 课拿到了两颗霍尔芯片的读数（每 1 ms 一次，14 位，0 ~ 16383）。这一课讲 MCU 拿到读数以后怎么判断左右键是按下还是松开：校验 → 翻转 → 滤波 → 换算成 0 ~ 100 的“段位” → 快速触发判定，旁边还有两条一直在“学习”的基线。全部是软件计算，不涉及新的硬件。

这一课为什么这样安排（根据你前面的提问）

你之前学旧板的滤波时卡了好几次（“为什么差 ≤ 10 就只走 1/16”）。这次每一站都先用图讲清“它要解决什么问题”，再用一步一步的数字算给你看，最后才对代码。每一站的画法按内容来：按键画成剖面图，滤波画成“两条曲线 + 一条宽度为 ±60 的带子”，段位画成一把尺子，快速触发画成“记录最低点 / 最高点的曲线”。最后有一个综合模拟器：用滑块当手指按键，所有数字和曲线实时跟着变。

🧭 本质：读数本身不会告诉你“按没按”。软件要先知道两个参照：松开时读数是多少（顶部基线）和按到底时读数是多少（底部基线），然后看当前读数在两者之间的哪个位置，换算成 0 ~ 100 的“按下深度”（段位）。再根据段位变化的方向和幅度判断按下 / 松开：往下走够 30 就算按下，往回走够 20 就算松开，不用等按到底或者完全松开（这叫“快速触发”）。

2. 按键里发生了什么：为什么要“翻转”

每个键下面有一块磁铁，霍尔芯片在它正下方。按下时磁铁靠近芯片，磁场变强。手册第 12 节：南极靠近时读数变小（无磁场约 8192）。T1A 的磁铁装法是“按下读数变小”，代码用 PRESS_KEY_AND_VALUE_DECREASE = 1（my_misc.h:40~49）表示，于是第一步把读数翻过来：

temp = 16383 − 读数（my_misc.c:531）。翻过来以后，按得越深，temp 越大，后面所有计算都按这个方向来想。
动手：拖动按键，看读数和 temp

读数是示意值：松开时取第 3 课的例子 9300，按到底取 6000。真实数值和磁铁、安装距离有关；磁场随距离不是均匀变化的，越靠近芯片变化越快，所以曲线是弯的。

3. 滤波：小抖动慢慢跟，大变化立刻跟

3.1 它要解决什么问题

手指不动时，读数也会在几个数之间跳（噪声）。如果直接拿来判断，段位会抖，按键可能误触发。但如果滤得太狠，真正按下时又反应慢。代码的办法是分两种情况：

新 temp 和上一次滤波值差多少当作什么怎么处理（my_misc.c:534~545）
差 > 60手指真的在动直接跳到新值：滤波值 = temp，并把“总和”重设成 temp × 64
差 ≤ 60噪声只走 1/64：总和 = 总和 + temp − 滤波值；滤波值 = 总和 ÷ 64；后面用滤波值代替 temp

“只走 1/64”是什么意思：总和始终约等于“滤波值 × 64”。加上 temp、减去旧滤波值，总和就多了 (temp − 滤波值)；再除以 64，滤波值就只往 temp 那边挪了差值的 1/64。比如滤波值 7083，新 temp 7123（差 40，≤ 60）：滤波值只变成约 7083 + 40 ÷ 64 ≈ 7083.6，取整还是 7083。连续很多次都是 7123，才会一点点爬上去。偶尔跳一下的噪声就被“摊薄”了。

为什么“只挪 0.6，取整后没动”也有意义：取整只发生在“滤波值 = 总和 ÷ 64”这一步，总和本身没有丢掉零头。下面工具里可以看到：喂了几个比 7083 大的数以后，滤波值一直显示 7083，但总和从 453312 慢慢涨到 453367，零头攒够 64 时滤波值才 +1。

动手：一个一个喂 temp，看滤波值怎么变
你来算：滤波值 = 7083，总和 = 7083 × 64 = 453312。新 temp = 7100（差 17）。算完后滤波值是多少？（总和 ÷ 64 去掉小数）
接上题：下一个 temp = 7400（真的按了）。滤波值变成多少？

一个副作用（推论）：如果手指非常慢地按，每 1 ms 只变不到 60，滤波值就会一直落在后面（每次只追 1/64）。综合模拟器里可以试“慢慢按”。

4. 段位：把 temp 换算成 0 ~ 100 的按下深度

有了两条基线：顶部基线（松开时的 temp）和底部基线（按到底时的 temp），当前 temp 在它们之间的位置就是“按下了百分之几”。代码分两步（my_misc.c:288~327 Hall_CalculateNode()）：

  1. 线性换算成 0 ~ 255 的格号：格号 = (temp − 顶部) × 255 ÷ (底部 − 顶部)。代码用“先算 step = 2²¹ ÷ 差值，再乘、再右移 21 位”的写法，避免每次做除法（除法在这颗芯片上慢）；结果和直接除基本一样。temp ≤ 顶部 → 0；temp ≥ 底部 → 255。
  2. 查表变成段位：nodeCaliTable[256]（my_misc.c:46）把 0 ~ 255 格号变成 0 ~ 100。表的前 10 格都是 0（顶部有一小段“死区”，轻轻碰一下不算），第 220 格以后都是 100（离底还有一点就算到底）。
“第 220 格以后都是 100”是怎么数出来的

格号就是数组下标，从 0 开始数。代码里这张表每行个数不一样，行尾的注释 //15、//16…… 写的就是这一行有几个数。把前面各行的个数加起来，就知道每行第一个数是第几格：

代码里第几行注释（本行个数）本行第一个数的格号 = 前面各行个数之和格号范围段位

所以最后一行（36 个 100）从第 15 + 16 + 18 + 19 + 20 + 22 + 24 + 26 + 28 + 32 = 220 格开始，到第 220 + 36 − 1 = 255 格结束，正好 256 个。第一行的前 10 个 0 就是第 0 ~ 9 格（死区）。

还有两条保护：底部 ≤ 顶部，或两者差 < 100（基线还没学好）→ 段位一律 0。

5. 快速触发：看段位“往哪走、走了多少”

5.1 它要解决什么问题

普通按键是“过了某个深度就算按下，回到这个深度以上就算松开”。快速触发（Rapid Trigger）更灵敏：按下后只要往回抬一点就算松开，松开后只要再往下按一点就又算按下，不用每次都完全松开。做法是一直记住一个“极点”：

当前状态记住什么什么时候翻转（my_misc.c:330~416）
松开松开以来段位的最低点段位 ≥ 最低点 + 30（按下灵敏度 RTP），并且段位 ≥ 10（触发点 AP）→ 按下；或者段位到 100 → 直接按下
按下按下以来段位的最高点段位 ≤ 最高点 − 20 以下（最高点 > 段位 + 20，松开灵敏度 RTR）→ 松开；或者段位回到 0 → 直接松开

30、20、10 是默认值（my_misc.h:52~54）。开机时 Init_CfgParamToRun()（my_protocol_mouse.c:98）会把 GUI 存的配置交给 Hall_UpdateParam()；配置里“启用”位没开就用默认值。

一个容易看漏的地方：从完全松开（最低点 0）开始，要段位 ≥ 0 + 30 才按下。触发点 10 比 30 小，所以默认参数下第一次按下实际是在段位 30，触发点 10 不起作用。只有 RTP 设得比 AP 小时，AP 才会起作用。
动手：选一种按法，一步一步看极点和状态

9. 常见疑问

Q1：左右键没有“消抖”吗？

中键、侧键这种机械按键有消抖（button.c:673、678：按下等 5 ms、松开等 8 ms）。左右键是霍尔，Button_Scan() 里左右键的消抖被注释掉了（button.c:621、626），因为滤波和快速触发本身已经起到防抖作用：段位要变化 30 / 20 才翻转。

Q2：校验失败（CRC_ERROR）那 1 ms 怎么办？

这个键整段跳过：不滤波、不算段位、不改状态、不学基线，下 1 ms 再读。所以偶尔一次干扰不会造成误按。

Q3：线圈振动时为什么不用读数？

线圈通电会产生磁场，霍尔芯片就在旁边，读数会被干扰。所以振动期间这个键的状态保持振动前的值（my_misc.c:488~512），振动结束再恢复判断。线圈什么时候振动是后面几课的内容。

Q4：开机时手指搭在键上会怎样？

推论：开机学到的“顶部”是半按下的值。松开后 temp 比顶部低很多，顶部每 300 ms 才 − 60；在这之前 temp ≤ 顶部，段位一直 0，这个键按不出来。要等的时间约 (偏了多少 ÷ 60) × 0.3 秒，比如偏 600 就要约 3 秒。模拟器“开机时手指搭着”可以看到。

Q5：为什么 1 ms 才算一次，够快吗？

手指按一下通常几十毫秒，1 ms 一次足够细。代码里 MAGNETIC_SCAN_RATE = 1（my_hallkey_func.h:26）表示 1 kHz，ONE_MS_COUNT 就是 1，所以上面所有“连续 N ms”就是“连续 N 次”。
