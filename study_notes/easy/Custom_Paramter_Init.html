Custom_Paramter_Init()：把设置恢复成出厂值

一句话：把 RAM 里的“鼠标设置”全部填成默认值。老代码里它还会顺手把默认值存进 EEPROM；本项目把“存”注释掉了，于是留下一个小毛病（第 4 节）。

1/6场景：什么时候会调用它

什么时候调用链现在会不会真的发生
每次开机main() → Device_Init() → Custom_Init()（device.c:472）→ 本函数✅ 每次都会。老代码只在“存储里记的编译日期 Code_Compile_Timer 和程序里的不一样”（第一次烧录或换了版本）时才调，本项目把判断注释掉了（custom.c:258~267），变成无条件调用

EEPROM 里的设置校验不对Device_check_Profile()（device.c:468）→ 本函数❌ 不会：校验代码被注释了，Check_mode_flag 永远是 FALSE

EEPROM（老区）

Custom_ModeParamter_Init(mode)（custom.c:172）做的事：nameID = mode；名字 = “配置文件” + (mode+1)；再调 Custom_DefineKey_Init()（10 个键的功能）、Custom_Perform_Init()（4 档 DPI、回报率 1000、默认第 4 档）、Custom_LefEffect_Init()（灯效）。它写的都是 RAM 里那唯一一套 settingMode。

名字是怎么来的
profileName[]（custom.c:42）里存的是 UTF-8 字节：233,133,141 = 配，231,189,174 = 置，230,150,135 = 文，228,187,182 = 件，第 12 个字节 49 = 字符 '1'。profileName[12] = 49 + mode 就把最后一位改成 '1' 或 '2'。

4/6本项目改完后留下的小毛病

⚠️ 循环白跑一遍，RAM 里留下的是“第 2 套”
老代码的循环是：填 RAM 第 0 套 → 存进 EEPROM 槽 0 → 填 RAM 第 1 套 → 存进槽 1；之后 Custom_Load_ModeSetting() 再按 currentMode = 0 从槽 0 读回 RAM。
现在“存”和“读回”都注释掉了：循环把 RAM 填了两遍，第二遍盖掉第一遍，最后 RAM 里是 nameID = 1、名字“配置文件2”，而 currentMode = 0。
影响很小：两套除了编号和名字完全一样（DPI、键位都是默认值），只有老 GUI 读配置名（pc_communicate.c:869）时会显示“配置文件2”。
另外两个“看着不对劲”的地方
① 第 204~207 行：for 和大括号被注释了，但中间那句 FP_ID = 0xff; 没注释，缩进还留着，看起来像在循环里，其实只执行一次。
② sign = 0xAA 现在没人读：读它的“开机判断”已被注释。

小测

记住：这个函数把 RAM 里的设置全部填成默认值。RAM 里只有一套配置，所以现在循环跑两遍等于第二遍盖掉第一遍。老代码靠“每填一套就存一套进 EEPROM，再读回当前那套”避免了这个问题，本项目把存和读都注释了。

本页新词

配置档（profile / mode）一整套设置；这里有 2 套，RAM 里只放当前那套
出厂默认值代码里写死的初始设置，恢复默认时用
“存过”标记（sign）写在存储里的一个固定值，开机看到它就知道存储里的数据有效
