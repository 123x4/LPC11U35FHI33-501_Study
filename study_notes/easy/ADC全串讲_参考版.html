1/8🧭 本质

在这个项目里，ADC 只干一件事：每 1 ms，把左右两个红外接收管上的电压，各变成一个 0~1023 的数。

用 ADC 分三步，和第 3 课的“外设七步”一一对应：① 开电源、开时钟、设分频（只做一次）→ ② 把引脚切成模拟输入（每个通道一次）→ ③ 每次要数时：选通道 → 启动 → 等 DONE → 取结果。这一页的代码全部落在这三步里。

3/8怎么用这个模块（API）

函数什么时候调返回
int32_t MyADC_Init(MyADC_ts *p)每个通道开机调一次。第一次调用时顺带完成整个 ADC 的上电、开时钟、设分频（hwInitFlag 保证只做一次）永远 0
int32_t MyADC_GetValue(MyADC_ts *p, uint16_t *pVal)要数的时候调，阻塞等转换完成（实际约 4 µs，最多等约 20 µs）0 成功；−1 参数错；−2 超时
void MyADC_Poll_Test(void)调试用，函数体整个被 #if 0 关掉，现在是空函数—

加一个新通道的做法（示意，没编译）：比如想读 PIO0_16（功能 1 = AD5）上的电压：

MyADC_ts batAdcInst = {           // 1. 定义一个对象：通道号、引脚、IOCON 寄存器地址

4/8读出来的数之后：按键算法（my_misc.c）

🧭 本质：把“一个电压数”变成“按着 / 松着”。难点在于每只鼠标、每对红外管、每个温度下，没按时和按到底的电压都不一样，所以不能写死一个阈值，而是让程序自己学两条基线，再看当前值落在两条线之间的哪里。

整个模块在 src/my_misc.c（本项目 chengjie 写，2026-03），入口是 ProcessRecvSampleRawData()（418 行），每 1 ms 被 LR_GetState() 调一次，左右两个键各走一遍下面这条流水线（点一格跳到说明；先看函数的整体骨架）：

① 拼数、取反→② 开机学基线（≤ 600 ms）→③ 线圈在震就冻结→④ 滤波→⑤ 算按下程度 0~100→⑥ 快速触发：按着 / 松着→⑦ 校准两条基线→⑧ 交出结果
两条基线（取反之后，数越大 = 按得越深）：
顶部基线 gwTopBaseline = 没按时的数值；底部基线 gwBottomBaseline = 按到底时的数值。
按下程度（段位，0~100） = 当前值在两条线之间的位置：贴着顶部是 0，到底部是 100。下标 0 = 右键，1 = 左键。

先看全局：ProcessRecvSampleRawData() 的宏观结构

它是什么：一个“每 1 ms 被调用一次”的函数。输入是 4 个字节（两个键的原始读数）；输出是一个字节，第 0 位 = 左键按着、第 1 位 = 右键按着。中间做的事情，就是上面那条流水线。

几个关键点：

  • 两个阶段互斥：学习阶段的那一毫秒，只学基线、不判断按键，直接跳到最后返回（这时 gbKeyState 都是 0，返回 0）。cali_init_cnt 一旦变成 0，以后每次都走工作阶段，再也不回学习阶段。
  • 左右两个键完全独立：for 循环里每个键用自己的那一份数据（下标 k），互不影响。唯一的联系是学习阶段“一个学好就一起结束”（见 ②）。
  • 工作阶段每个键的顺序是固定的：先“能不能信”（③）→ 再“读多少”（①④）→ 再“按到哪”（⑤）→ 再“算不算按下”（⑥）→ 最后“顺手更新基线、通知别人”（⑦⑧）。先判断、再校准：这一次的校准，要到下一毫秒才起作用。
  • 真正干活的是 5 个小函数：Hall_InitBaseline、Hall_CalculateNode、Hall_HandleKeyRapidTrigger、Hall_CalibrateTopBaseline、Hall_CalibrateBottomBaseline。这个大函数本身只负责“按顺序调用它们”和“搬数据”。
为什么源码看起来比这复杂得多
这个函数 251 行，但 IRPT_V4 真正编译的只有大约一半。剩下的是：#else 里给霍尔板型的分支（14 位、校验）、#if 0 里注释掉的老代码、MYDEBUG_ENABLE 的调试打印、PUSH_VIBRATING_HALL_VALUE_TO_GUI 的另一种推 GUI 方式。这些都是“IRPT_V4 下不存在”的代码，读的时候先在脑子里把它们划掉。在 VS Code 里，如果 IntelliSense 认得 IRPT_V4，不生效的 #if 分支会显示成灰色。

几个值得注意的地方
• 10000 / 6000 是霍尔板型留下的数：霍尔芯片是 14 位（0~16383），没按 / 按到底大约就在这个量级。对 IRPT_V4 的 10 位红外来说，这两个数只起“不可能值”的作用。
• 这些都是普通全局变量（没加 static）：任何文件 extern 一下就能改。实际上除了 my_misc.c，只有没编译的 my_hallkey_func.c 碰过它们，所以加上 static 会更安全（gbKeyState 在 my_misc.h 里声明了 extern，但也只有 my_misc.c 在用）。
• 手感参数改了以后立刻生效、也存 EEPROM：GUI 改参数 → Task_ParamGuard() 把 xgAllParam 写进 EEPROM（第 11 课），再调 Hall_UpdateParam() 更新这三个数组。下次开机 Param_Init() 从 EEPROM 读回。
• Hall_UpdateParam() 的两个细节：GUI 那边 bmEnableMask 第 7 位没开时，用回默认值 10 / 30 / 20；按下 / 松开距离传来 0 时改成 1，避免“距离为 0 一碰就切换”。

① 拼数、取反（my_misc.c:516~523）

两个字节拼成 0~1023，再用 1023 减，变成“按得越深，数越大”。 
temp[k] = ana_rd_buff[2*k];          // 高字节
temp[k] <<= 8;
temp[k] |= ana_rd_buff[2*k + 1];     // 低字节 → 0~1023
#if PRESS_KEY_AND_VALUE_DECREASE      // IRPT_V4 = 1
  temp[k] = MAX_VALUE_10BIT - temp[k];   // 1023 − 原始值
#endif

hall_spi_rx[4] 里每个键 2 字节，先拼回一个 16 位数。IRPT_V4 的红外管按下时电压变低，所以 PRESS_KEY_AND_VALUE_DECREASE = 1（my_misc.h:28 设 INCREASE = 0，39 行取反），用 1023 减一下，变成“按得越深数越大”。这样后面的算法和霍尔板型（按下数变大）共用一套。

② 开机学顶部基线：Hall_InitBaseline()（my_misc.c:135~160，调用在 441~456）

开机最多 600 ms：读数稳定 100 ms，就把它当成“没按”的位置；任意一个键学好，学习阶段就结束。

场景：鼠标刚插上，程序还不知道“这一只鼠标、这一对红外管，没按时读数是多少”。开机后的头几百毫秒，先假设手指没按，把读数学下来当作顶部基线。学好之前，左右键都不判断，一律当松着。

135  int32_t Hall_InitBaseline(uint16_t keyIndex, uint16_t rawData,
                               uint16_t *const pTopBaseline, uint16_t *const pBottomBaseline)
136  {
137    static uint16_t counter[ANA_TOTAL_COUNT] = {0};          // 每个键一个“连续稳定了几毫秒”
138    uint16_t upperLimit = *pTopBaseline + (MAGNETIC_NOISE);  // 当前顶部基线 + 20
139    uint16_t lowerLimit = *pTopBaseline - (MAGNETIC_NOISE);  // 当前顶部基线 − 20
140
141    if((rawData > upperLimit) || (rawData < lowerLimit))     // 新读数跳出 ±20 的范围
142    {
143      *pTopBaseline = rawData;                              // 不稳：从这个新读数重新开始
144      *pBottomBaseline = rawData;
145      counter[keyIndex] = 0;                                // 稳定计数清零
146      return -1;                                            // −1 = 还没学好
147    }
148    else                                                    // 在 ±20 以内
149    {
150      *pTopBaseline = (*pTopBaseline + rawData) / 2;        // 和新读数平均一下
151      *pBottomBaseline = *pTopBaseline;                     // 底部先跟顶部一样
152      counter[keyIndex] += 1;                               // 又稳定了 1 毫秒
153      if(counter[keyIndex] >= (100 * ONE_MS_COUNT))         // ONE_MS_COUNT = 1 → 100 次 = 100 ms
154      {
155        counter[keyIndex] = 100;
156        return 0;                                           // 0 = 学好了
157      }
158    }
159    return -1;
160  }
行讲解

④ 滤波：小抖动磨平，大动作放行（my_misc.c:534~545）

第 1 步：为什么要滤波

手指没碰按键，ADC 每毫秒读出来的数是这样的：300, 304, 297, 303, 306, 299 …… 手没动，数却在跳。后面的程序靠这个数判断“按没按”，数一跳，它可能以为手动了。所以先把这个数弄稳。

第 2 步：规则只有一句话

程序记着一个“结果”（稳定后的数）。每来一个新读数：

差 ≤ 10：只往新读数走 1/16
结果 300，新读数 308，差 8 → 走 0.5 → 300.5
结果 300，新读数 306，差 6 → 走 0.375 → 300.375
差 > 10：直接跳过去
结果 300，新读数 325，差 25 → 325
结果 300，新读数 360，差 60 → 360

第 3 步：为什么只走 1/16

两个极端都不行：每次走 100%，结果就是读数本身，等于没滤；完全不走，结果永远 300，读数真的变了也跟不上。走一小部分，会出现两种效果：

① 抖动：一会儿往上推、一会儿往下推，推不动
新读数304296304296
结果300.25299.98300.23299.96
② 真变化（读数一直是 306）：一直往一个方向推，最后推过去
第几次1231640
结果300.375300.73301.06约 303.9约 305.5

1/16 是取舍：走得越少（1/64）越稳但越慢；走得越多（1/2）越快但抖动也漏过来。而且 ÷16 在代码里就是右移 4 位，M0 做起来最便宜。
差 > 10 为什么直接跳：按 ② 的速度，要 40 ms 左右才跟上。真按键时读数一下变几十上百，等 40 ms 手感就迟钝了。变化大到不可能是抖动，就直接跳。

第 4 步：对上代码——sum 是干什么的

问题：结果要存 300.375 这种小数，但代码里全是整数。办法：不存结果，存“结果 × 16”，叫 sum。300.375 × 16 = 4806，是整数，小数就不会丢。

把第 2 步的规则两边都乘 16：

结果 = 结果 + (读数 − 结果) ÷ 16
  ↓ 两边 × 16
sum  = sum  + 读数 − 结果

⑤ 算按下程度：Hall_CalculateNode()（my_misc.c:288~327）

当前值落在两条基线之间的哪里，换算成 0~100 段。 
if(顶部 ≥ 底部 || 底部 − 顶部 < 100) return 0;   // 两条线还没拉开，一律当 0
if(值 ≤ 顶部) tmp = 0;
else if(值 ≥ 底部) tmp = 255;
else
{

  tmp = ((值 − 顶部) * step * 255) >> 21;          // = (值 − 顶部) × 255 ÷ (底部 − 顶部)

return nodeCaliTable[tmp];                         // 0~255 查表成 0~100

本质就是一个比例：(值 − 顶部) ÷ (底部 − 顶部)，换算成 0~255，再查表变成 0~100。两个工程技巧：

  • 定点数代替除法：Cortex-M0 没有硬件除法指令，每次除法都要调库函数（几十个时钟）。这里把 1/(底部 − 顶部) 预先算成 step = 2²¹ / 差，存在 static 里；之后每毫秒只做乘法和右移 21 位。基线不变就不再除。
  • 查表：nodeCaliTable[256]（my_misc.c:16~44）IRPT_V4 版接近一条直线（每 2.55 格 +1）；霍尔板型那版是弯的，用来修正磁场的非线性。想调整“按到一半算几段”，改这张表就行。

⚠️ 两条线没拉开（差 < 100）时永远返回 0，这时怎么按都不会触发。开机学完顶部基线后正是这种状态，要靠 ⑦ 的底部基线学习把它拉开。

⑥ 快速触发：Hall_HandleKeyRapidTrigger()（my_misc.c:330~396）

看段位相对“最近的最浅 / 最深点”走了多少，决定按下还是松开。 
if(现在是按着)
{
  if(段位 == 0)                                      → 松开
  else if(段位 > 记录的最深)  记录的最深 = 段位;     // 还在往下按，跟着记
  else if(记录的最深 > 段位 + rt_release)            → 松开（从最深处回弹够多）
}
else // 现在是松着
{
  if(段位 ≥ 100)                                     → 按下（按到底）
  else if(段位 < 记录的最浅)  记录的最浅 = 段位;     // 还在往上抬，跟着记
  else if(段位 ≥ 记录的最浅 + rt_press 且 段位 ≥ ap)  → 按下（从最浅处按下去够多，且过了触发点）
}

普通按键是“过了某个固定深度就算按下”。快速触发（Rapid Trigger）是电竞鼠标 / 键盘的做法：只看“相对最近的最浅 / 最深点移动了多少”。好处：按住不放、稍微抬一点就能松开，再稍微压一点又能按下，连点更快。

三个参数（段位单位，0~100）：ap_value 触发点（默认 10）、rt_press_value 按下距离（默认 30）、rt_release_value 松开距离（默认 20）。默认值在 my_misc.h:42~44，实际值开机由 Hall_UpdateParam()（my_misc.c:101）从 EEPROM 参数 xgAllParam 覆盖，GUI 能改。current_node_update[] 是函数内 static，记着“最深 / 最浅”。

⑦ 校准两条基线（my_misc.c:162~286）

松着时让顶部基线慢慢跟着漂移；刚按下的 100 ms 里让底部基线往深处学。

顶部基线 Hall_CalibrateTopBaseline()：只在松着的时候调。当前值 比 顶部 低 20 以上、持续 300 ms → 顶部 −20；比顶部低一点、持续 100 ms → −5；比顶部高一点（≤ 20）、持续 100 ms → +2。按着时三个计数器清零。作用：温度、环境光慢慢变化时，“没按”的数值会漂，顶部基线慢慢跟着走。

底部基线 Hall_CalibrateBottomBaseline()：当前值 比 底部 高 80 以上、持续 30 ms → 底部 +60；高 20 以上、持续 30 ms → +10。只会往大走，不会往回缩；按住超过 100 ms 后就不再学（避免长按时乱改）。作用：学出“按到底”是多少。
由此推出：每次按下，只有被判定按下后的前 100 ms 在学，所以底部基线要点好几次才学到真正的“按到底”。学到之前，底部偏浅，段位会偏大（按一半就显示 70、80）。模拟器“开机 + 第一次点击”里可以看到底部基线一次次往上走。

⚠️ 由此推出：开机后的第一次点击要“按住一会儿”
开机学完后底部 = 顶部，⑤ 一律返回 0，不会触发。第一次按下去，当前值比底部高很多，每持续 30 ms 底部 +60；大约 60 ms 后两条线拉开到 ≥ 100，⑤ 开始算出段位，此时当前值已经 ≥ 底部，段位 = 100，⑥ 判定按下。所以开机后第一下快速轻点可能不响应，按住约 60 ms 以上才行；之后的点击都正常。模拟器里选“开机 + 第一次点击”能看到。这是从代码推出来的，要上板验证。

6/8T1A

T1A 的左右键换成 GTRY164 霍尔芯片（SPI），不再需要 ADC 读按键；PIO0_13 / 14 改作线圈 PWM，PIO0_19 改作滚轮信号（T1A 适配清单）。所以 T1A 上：MyADC_Init() 的两次调用、IR_EN 的初始化、LR_GetState() 里的 ADC 分支都要去掉。my_adc.c 这个驱动本身可以留着，以后如果要量电池电压之类的模拟量，按第 3 节的做法加通道。

7/8💡 想法上

1. 读驱动代码，一行对一个寄存器字段
这一页的方法可以用在任何外设上：每看到一句 XXX->REG |= / &= …，就问三件事：哪个寄存器？哪几位？手册里这几位是什么意思？把答案写在旁边。读完一个驱动，你就有了一张“这个外设被设成了什么样”的表。
2. 错误处理的路径，最容易漏掉收尾
上面第一个坑就是典型：正常路径最后会清 SEL，超时提前 return 的路径却没清。以后写“中途可能返回”的函数，检查一下：每一个 return 之前，该恢复的东西都恢复了吗？

8/8小测

记住：开机 MyADC_Init()：PDRUNCFG bit4 清 0（上电）、SYSAHBCLKCTRL bit13 置 1（时钟）、CLKDIV = 15（48 MHz ÷ 16 = 3 MHz）；引脚 IOCON 去上下拉、ADMODE 清 0（模拟）、FUNC = 2（AD）。每次 MyADC_GetValue()：停 → 选 SEL → 读一次 DR 清 DONE → START = 001 → 每 2 µs 看 DONE → 取 DR 第 15~6 位 → 清 SEL。

本页新词

CLKDIVADC 时钟分频：ADC 时钟 = 系统时钟 ÷（CLKDIV + 1），不能超过 4.5 MHz
SELCR 低 8 位，选哪个通道
STARTCR 第 26~24 位，写 001 = 立刻开始转换
DONEDR 第 31 位，转换完成；读一次 DR 自动清掉
ADMODEIOCON 第 7 位：0 = 模拟（断开数字输入电路），1 = 数字
BURST连续转换模式（本项目没用）
