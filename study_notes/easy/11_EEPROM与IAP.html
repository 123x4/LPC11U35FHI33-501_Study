1/9为什么要专门“存”：变量断电就没了

程序里的变量（比如 xgAllParam）都放在 RAM 里。RAM 读写快，但一断电就清空。想让设置断电后还在，就要把它抄一份到“断电不丢”的地方。这颗芯片里有两种断电不丢的存储：

次数和时间来自数据手册 10.1 节的 Flash characteristics 表和 EEPROM characteristics 表。EEPROM 能改单个字节、寿命长，所以设置放这里。

EEPROM：电可擦除只读存储器，名字里有“只读”但其实能写；这里专门用来存断电不丢的小数据。
擦除：Flash 和 EEPROM 只能把 1 改成 0；想把 0 改回 1，要“擦”。Flash 必须整页擦，EEPROM 由芯片自动处理。
擦写寿命：同一个位置反复写的次数有上限，超过可能写不进去。

3/9IAP：芯片里自带的“写入程序”

EEPROM 和 Flash 不能像变量那样直接赋值，要用芯片出厂时就写在 ROM 里的一段程序来写，这段程序叫 IAP。我们的代码只需要“打电话”给它：

ROM：芯片出厂就固化好的程序区，不能改。里面有启动程序（bootloader）和 IAP。
IAP（In-Application Programming，在应用中编程）：程序运行时，自己改写 Flash / EEPROM。
ISP（In-System Programming）：用串口或 USB 从外面烧程序。和 IAP 是同一套 ROM 程序，入口不同。

“打电话”的方法很固定：准备两个数组，command[] 放命令号和参数，result[] 接结果，然后跳到 ROM 地址 0x1FFF 1FF1。原始代码（IAP_CMD.c:27~70，中间省略了几行）：

#define LPC_IAP_EEPROM_WRITE            61	/*!< EEPROM Write command */
#define LPC_IAP_ENTRY_LOCATION        0X1FFF1FF1

static __inline void lpc_iap_entry(unsigned int cmd_param[], unsigned int status_result[])
{
	__disable_irq();
	((LPC_IAP_ENTRY_T) LPC_IAP_ENTRY_LOCATION)(cmd_param, status_result);
	__enable_irq ();
}

uint8_t Chip_EEPROM_Write(uint32_t dstAdd, uint8_t *ptr, uint32_t byteswrt)
{
	uint32_t command[5], result[5];

	command[0] = LPC_IAP_EEPROM_WRITE;
	command[1] = dstAdd;
	command[2] = (uint32_t) ptr;
	command[3] = byteswrt;
	//command[4] = SystemCoreClock / 1000;
	command[4] = MCU_OSC / 1000;
	lpc_iap_entry(command, result);

	return result[0];
}
数组位置放什么例：保存按键参数
command[0]命令号：61 写 EEPROM，62 读 EEPROM61
command[1]EEPROM 地址0xF06（EEPROM_ADDR_PARAM）
command[2]RAM 里数据的地址&xgAllParam
command[3]几个字节88（sizeof(xgAllParam)）
command[4]CPU 时钟，单位 kHz宏展开：MCU_OSC = 12 MHz × (3+1) = 48 MHz → 48000
result[0]结果：0 成功，4 / 5 地址不对函数把它返回出去

函数指针那行 ((LPC_IAP_ENTRY_T) 0x1FFF1FF1)(…) 的意思是“把这个数字当成一个函数的地址，调用它”。地址末尾是 1 而不是 0，是 Cortex-M0 的规矩（表示 Thumb 指令），手册 20.14 有解释。

4/9EEPROM 地图：4 KB 里都放了什么

下面每个小格是 1 个字节，一行 64 个，一共 64 行 = 4096 字节。点下面的按钮看每一块是谁的：

两套代码各用一块，没有重叠：旧代码用 0x000~0xB84（2949 字节），新协议用 0xF00~0xF5D（94 字节）。最上面 64 字节（0xFC0~0xFFF）芯片保留，写不进去。

顺便看一眼 Flash（64 KB）
0x0000~0x3FFF：公司自己的 bootloader（升级用，第 20 课）· 0x4000 起：我们的程序 · 0xF000~0xF0FF：每个配置的校验码（MCU_inside_Flash，gtech_flash.c:34）· 后面是程序的初始数据。
Flash 每页 256 字节、每个扇区 4 KB。改 0xF000 这一页要先擦掉整页，所以旧代码先把整页读到 RAM，改完再整页写回（gtech_flash.c:123~201）。

5/9EEPROM 的一生：生命周期图

一句话来龙去脉
开机时 Param_Init() 用 IAP 命令 62 从 EEPROM 0xF00 读出版本号、校验码和 88 字节参数；版本或校验码对不上，就写一份默认值进去。之后 GUI 改参数只改 RAM 并立标志，主循环的 Task_ParamGuard() 看到标志，用 IAP 命令 61 把整份参数和新校验码写回 EEPROM。每次调 IAP 都会先关掉全部中断，写完再打开。

为什么要关中断

手册原文（20.8.7）：“The on-chip flash memory and EEPROM are not accessible during erase/write operations.” 擦写期间 Flash 读不了。可是中断来的时候，CPU 要去 Flash 里的向量表找中断函数，一读就出错，程序会卡死。所以：

谁关的怎么关关得全不全
⬜ lpc_iap_entry()（EEPROM 用）__disable_irq()：一次关掉所有中断，回来再全开✅ 全关
⬜ Gtech_MCUFlash_WriteBytes()（Flash 用）用 NVIC_DisableIRQ 一个个关了 7 个：GINT0、CT16B0、CT16B1、I2C、SSP0、SSP1、USB⚠️ 不全：其他中断如果开着，擦 Flash 时来了就会出问题

代价：写 88 字节 EEPROM 大约要几毫秒，这期间 1 ms 定时器中断和 USB 中断都会被推迟。所以只在设置真的变了才写，平时不碰。

8/9容易出错、你能改什么、T1A

在中断里写 EEPROM会让所有中断停几毫秒，USB 和定时器都受影响。保持“中断/命令里立标志，主循环里写”的做法。
反复写同一个位置EEPROM 至少 10 万次。如果每 1 ms 写一次，不到 2 分钟就用完了。只在设置变了的时候写。
改了结构体没改地址AllParam_ts 变大后，0xF06 + 大小不能超过 0xFBF。代码里有调试打印提醒（my_protocol_mouse.c:196）。
改了结构体没改版本号 ⚠️开机时版本号对不上才会写默认值。结构体变了却没改 MY_MAIN_VERSION / DEBUG_VER，旧数据会被按新格式读出来。不过校验码多半也对不上，会兜底写默认值。
写 EEPROM 的返回值没人看 ⚠️my_protocol_mouse.c:120~121、261~263。失败了不会重试，也不会告诉 GUI。
旧设置开机不读回 ⚠️旧协议的设置（DPI 等）会写进 EEPROM 0x000 起，但开机时读回的代码被注释掉了（app/custom.c:220~272），开机总是用默认值。是有意的还是遗留，问杰哥。
Flash 擦写只关了 7 个中断 ⚠️gtech_flash.c:135~141。比 EEPROM 那条路危险。第 13 课核对开着哪些中断。
Chip_IAP_ReadUID() 小越界它往 uid 后面写 4 个字，但 device.c:496 只给了 1 个字。只在 MYDEBUG_ENABLE = 1 时编译，现在是 0。

你能改什么

  • 新增要保存的参数：加进 AllConfig_ts / AllInfo_ts（inc/my_protocol_common.h），在 Param_Init() 里给默认值，改一下版本号。
  • 默认值：Param_Init() 里那一大段（my_protocol_mouse.c:222~255），比如 DEFAULT_AP。
  • 保存时机：Task_ParamGuard()，比如加“改完 1 秒后再写”，避免拖动滑块时连续写。

T1A 上

EEPROM 和 IAP 是芯片内部的，换板子不用改。要改的是“存什么”：新协议 + GUI 如果加了参数（比如 R-DIP 编码器的设置、充电相关设置），就按上面“新增要保存的参数”来，注意总大小别超过 0xFBF。

小测验

这一课你只需要记住：变量在 RAM，断电就没；设置要存进 EEPROM。EEPROM 不能直接赋值，要调芯片 ROM 里的 IAP 程序：填 command[]（61 写 / 62 读、地址、数据、字节数、时钟 kHz），跳到 0x1FFF 1FF1，看 result[0]。调用期间必须关中断。项目里开机 Param_Init() 读，GUI 改了立标志，主循环 Task_ParamGuard() 写。
