固定题 已答对 0 / 0 题

第 1 关

ADC 干什么：把电压变成一个数

问题CPU 只认数字。红外接收管给出的是一个电压，按得越深挡光越多，电压越低。要知道“按了多深”，就得知道电压具体是多少。

一句话：10 位 ADC 把 0 ~ 3.3 V 按比例变成 0 ~ 1023。数 = 电压 ÷ 3.3 × 1023
电压0 V1.65 V3.3 V
数0约 5111023

本项目：左键接 PIO0_13（ADC 的 2 号通道 AD2），右键接 PIO0_14（AD3）；红外发射管的电由 PIO0_19（IR_EN）控制。

第 2 关

用之前：开电、开时钟、设分频

问题为了省电，芯片刚上电时 ADC 是断电的，也没有时钟（时钟就是让电路一步步干活的节拍）。不打开它，什么也读不到。

一句话：拨三个开关。
① PDRUNCFG 第 4 位写 0 → ADC 通电（注意：这个寄存器是 0 = 开）
② SYSAHBCLKCTRL 第 13 位写 1 → 给 ADC 时钟
③ CR 第 15~8 位 CLKDIV → ADC 时钟 = 48 MHz ÷ (CLKDIV + 1)，手册要求不超过 4.5 MHz

本项目写 CLKDIV = 15：48 ÷ 16 = 3 MHz。转换一次要 11 个时钟，约 3.7 µs。

你来算：CLKDIV 最小写几，ADC 时钟才不超过 4.5 MHz？

第 3 关

把引脚切成“模拟输入”

问题一个引脚能干好几种事：PIO0_13 默认是调试口 TDO，还能当普通 GPIO、AD2、定时器输出。要告诉芯片：这只脚现在给 ADC 用。

一句话：改这只脚的 IOCON 寄存器三处。
① FUNC（第 2~0 位）= 2 → 选 AD 功能
② MODE（第 4~3 位）= 0 → 去掉上拉 / 下拉电阻，不然电阻会把电压拉偏
③ ADMODE（第 7 位）= 0 → 模拟模式，断开数字输入电路
你来想：如果忘了去掉上拉电阻（上拉 = 用电阻接到 3.3 V），读数会偏大还是偏小？
对上代码：MyADC_Init()（my_adc.c:67~76）

68  {

第 4 关

读一次：选通道 → 开始 → 等完成 → 取结果

问题只有一个 ADC 电路，左右两个键要轮流用它。每次读，先告诉它读哪个通道，再让它开始，等它做完再拿结果。

一句话：
① 选通道：CR 的第 ch 位置 1
② 读一次 DR，把上次留下的“完成”标志清掉
③ 开始：CR 第 24 位置 1
④ 每 2 µs 看一次 DR 第 31 位 DONE，最多看 10 次
⑤ 取结果：结果在 DR 的第 15~6 位，(DR >> 6) & 0x3FF
⑥ 取消选通道

例子：读到 DR = 0x8000 7FC0。第 31 位是 1 → 做完了；0x7FC0 >> 6 = 0x1FF = 511。

你来算：DR = 0x8000 C800，结果是多少（十进制）？

谁来调：LR_GetState()（app/button.c:320~321）每 1 ms 读左右各一次，把两个数各拆成 2 个字节放进 hall_spi_rx[4]（327~330 行），交给 ProcessRecvSampleRawData()（350 行）。这里就是上半和下半的交接处。名字里的 hall、spi 是霍尔板型留下的，IRPT_V4 里装的是 ADC 的数。

第 6 关

两条基线和段位：按到了几成

问题每只鼠标、每对红外管都不一样：这只没按是 223，那只可能是 260。所以不能写死“超过 400 算按下”。

一句话：程序记两个数：顶部基线 = 没按时的数，底部基线 = 按到底时的数。段位 = 当前值在两者之间的位置，0 ~ 100：
段位 = (当前 − 顶) ÷ (底 − 顶) × 100
顶 = 223，底 = 603
当前223413603
段位050100
你来算：顶 223、底 603，当前 318，段位是多少？
底 − 顶 < 100 时，段位一律是 0：两条线还没拉开，算不准，干脆不算。开机刚学完时正是这样（下一关）。
对上代码：Hall_CalculateNode()（my_misc.c:288~327） 
if(顶 >= 底 || 底 − 顶 < 100) return 0;          // 两条线没拉开
if(当前 <= 顶) tmp = 0;
else if(当前 >= 底) tmp = 255;
else
{
  if(基线变了) step = (1 << 21) / (底 − 顶);      // 只在基线变时做一次除法
  tmp = ((当前 − 顶) * step * 255) >> 21;          // = (当前 − 顶) × 255 ÷ (底 − 顶)
}
return nodeCaliTable[tmp];                        // 0~255 查表变成 0~100

和公式是一回事，只是先换成 0~255 再查表变 0~100。用 step 和右移，是因为这颗芯片（Cortex-M0）没有除法指令，除法很慢，所以只在基线变化时除一次。

第 7 关

开机怎么学顶部基线

问题顶部基线从哪来？开机时一般没人按，那时的读数就是“没按”。但读数会抖，要等它稳了再记。

一句话：开机后每 1 ms 看一次读数：
• 在基线 ±20 以内 → 基线 = (基线 + 读数) ÷ 2，稳定次数 +1
• 跳出 ±20 → 基线直接换成这个读数，稳定次数清 0
连续稳定 100 次（100 ms）就算学好。学好时底部基线 = 顶部基线（还没拉开，要等以后按键时再学）。

基线初值是 10000，一个不可能的数（10 位 ADC 最大 1023），所以开机第一个读数一定“跳出”，直接拿来当起点。

你来算：基线 223，新读数 229。基线变成多少？（除法只留整数）
基线 223，新读数 250。基线变成多少？

第 8 关

滤波：抖动抹掉，真变化放行

问题手没动，数也在 300、304、297、303 之间跳。后面的步骤会被这种抖动干扰。

一句话：程序记着一个“结果”。每来一个新读数：
差 ≤ 10：只往读数走 1/16
结果 300，读数 308 → 走 0.5 → 300.5
差 > 10：直接跳过去
结果 300，读数 360 → 360

为什么只走 1/16：抖动是一会儿往上推、一会儿往下推，推不动；真变化是一直往一个方向推，最后推过去。差 > 10 为什么直接跳：真按键时读数一下变几十上百，慢慢走要 40 ms 才跟上，手感会迟钝。

你来算：结果 300，新读数 306。新结果是多少？

代码怎么存小数：整数存不下 300.375，所以代码存“结果 × 16”，叫 sum（300.375 × 16 = 4806，是整数）。在 sum 上走一步，就是加上差（走“差的 1/16”，按 1/16 来数正好是“差”那么多个）。交出去时 sum ÷ 16，只交整数部分，小数留在 sum 里慢慢攒。

你来算：sum = 4800（结果 300），新读数 308。sum 变成多少？
对上代码（my_misc.c:534~545） 
534  if((raw_data_filter[k] > (temp[k] + 10)) || ((raw_data_filter[k] + 10) < temp[k]))   // 差 > 10
535  {
536    raw_data_filter[k] = temp[k];                 // 直接跳：结果 = 读数
537    raw_data_filter_sum[k] = temp[k] << 4;        //         sum  = 读数 × 16
538  }

第 9 关

快速触发：按着还是松着

问题普通按键是“过了某个深度就算按下”。可是手指按住不放，只抬一点点再按下去想连点，固定深度就判不出来。

一句话：只看相对最近的转折点走了多少段。
• 松着时：记着最近的最浅点。从最浅点往下按 ≥ 30 段（而且段位 ≥ 10）→ 按下。
• 按着时：记着最近的最深点。从最深点往回抬 超过 20 段 → 松开。段位回到 0 也算松开。
30、20、10 是三个手感参数（rt_press、rt_release、ap），GUI 可以改。
段位02035709075696090
记着的转折点最浅 0最浅 0最深 35最深 70最深 90最深 90最浅 69最浅 60最深 90
状态松松按下按按按松开松按下
为什么20 < 0+3035 ≥ 0+30更深更深只抬 15抬了 21更浅按了 30

注意最后一下：手指没抬到顶（只回到 60），又按下去了。这就是“快速触发”的好处。

你来想：现在按着，记着的最深是 80，段位回到 62。松开了吗？
对上代码：Hall_HandleKeyRapidTrigger()（my_misc.c:330~396）

第 10 关

合起来：每 1 ms 真实的顺序

前面按“好理解”的顺序讲，代码里的真实顺序是这样的（ProcessRecvSampleRawData()，my_misc.c:418）：

if(还在开机学习)            // cali_init_cnt 不为 0，最多 600 ms
{
    左右键各：取反（第 5 关） → 学顶部基线（第 7 关）
}
else                        // 正常工作
{
    左右键各：
      线圈在震？ → 沿用上次结论，跳过下面所有步骤      ← 新的
      取反（第 5 关）
      滤波（第 8 关）
      段位（第 6 关）
      快速触发（第 9 关）
      校准两条基线                                   ← 新的
      段位告诉线圈、数据存给 GUI                       ← 新的
}
返回：左键按着 → 第 0 位 = 1，右键按着 → 第 1 位 = 1

三个没单独讲的步骤，各一句话：

  • 线圈在震就冻结：判定按下时线圈会震一下，震动会让读数乱跳。所以震动和震后约 8 ms 内，这个键不看读数，结论沿用上一次。
  • 校准两条基线：松着时，顶部基线跟着温度、环境光慢慢挪；刚按下的 100 ms 内，底部基线往更深处学。开机时底 = 顶，第 6 关说过差 < 100 段位一律 0，所以要靠按几次把底部学开。由此推出：开机后第一下快速轻点可能不响应（待上板验证）。
  • 交出结果：段位告诉线圈（调震动强度），数据存给 GUI（实时曲线），两个键的结论拼成一个字节返回。
