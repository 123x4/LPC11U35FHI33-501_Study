ADC：从上电到每 1 ms 读出两个数

把项目里所有和 ADC 有关的代码按执行顺序串起来，每一行都讲：它改了哪个寄存器的哪几位、手册在哪一页、为什么这么写。第 7 课讲过 ADC 的原理，这一页专讲代码。

1/8🧭 本质

在这个项目里，ADC 只干一件事：每 1 ms，把左右两个红外接收管上的电压，各变成一个 0~1023 的数。

用 ADC 分三步，和第 3 课的“外设七步”一一对应：① 开电源、开时钟、设分频（只做一次）→ ② 把引脚切成模拟输入（每个通道一次）→ ③ 每次要数时：选通道 → 启动 → 等 DONE → 取结果。这一页的代码全部落在这三步里。

3/8怎么用这个模块（API）

函数什么时候调返回
int32_t MyADC_Init(MyADC_ts *p)每个通道开机调一次。第一次调用时顺带完成整个 ADC 的上电、开时钟、设分频（hwInitFlag 保证只做一次）永远 0
int32_t MyADC_GetValue(MyADC_ts *p, uint16_t *pVal)要数的时候调，阻塞等转换完成（实际约 4 µs，最多等约 20 µs）0 成功；−1 参数错；−2 超时
void MyADC_Poll_Test(void)调试用，函数体整个被 #if 0 关掉，现在是空函数—

加一个新通道的做法（示意，没编译）：比如想读 PIO0_16（功能 1 = AD5）上的电压：

MyADC_ts batAdcInst = {           // 1. 定义一个对象：通道号、引脚、IOCON 寄存器地址
  .ch = 5,
  .port = 0,
  .pin = 16,
  .pFuncReg = &(LPC_IOCON->PIO0_16),
};
MyADC_Init(&batAdcInst);          // 2. 开机调一次

uint16_t v;
if(MyADC_GetValue(&batAdcInst, &v) == 0)   // 3. 要用时读
{
  // v: 0~1023，对应 0~3.3 V（VDD 就是参考电压）
}

⚠️ MYADC_SET_FUNC(…, MYADC_FUNC_AS_AD) 写死了 FUNC = 2，注释也写着“只适用于 PIO0_13 和 PIO0_14”。PIO0_16 当 AD5 时 FUNC 是 1，所以真要加通道，MyADC_ts 里还得多存一个“AD 功能号”。这正是上一页“面向对象”说的：差异放进对象里。

4/8读出来的数之后去哪

LR_GetState()（button.c:298）拿到两个数后：按“右、左”装进 hall_spi_rx[4] → ProcessRecvSampleRawData()：1023 − 原始值（按得越深数越大）→ 滤波 → 按顶部 / 底部基线换算成 0~100 的按下程度 → 快速触发状态机得出“按着 / 松着”。这部分在“一次左键点击全程”第 5、6 步，这里不重复。

5/8坑和值得注意的地方

位置问题影响
my_adc.c:113 vs 108、117超时返回 −2 的那条路，既没停止转换（108 行），也没把 SEL 位清掉（117 行）。下一次读另一个通道时，SEL 里会同时有两位是 1；手册要求软件启动模式下只能选一个通道只有超时才发生，概率低；但一旦发生，下一次读数可能读错通道。修法：超时返回前也清 SEL
my_adc.c:56CR &= ~(0x7U << 17) 设 CLKS = 0。按手册 Table 352，CLKS 只在 BURST（连续转换）模式下决定转换位数本项目用软件启动、不用 BURST，这句不起作用，也无害
device.c:463 vs 485开机“右键 + 后侧键”检测在 MyADC_Init() 之前就读 ADC。这时 ADC 没上电、没时钟读不到 DONE，超时 −2，右键永远当松开（待上板验证）
my_adc.c:17MyADC_DelayUs 就是 CT16B1_DelayUs：忙等，和线圈震动共用同一个定时器两者都在主循环里顺序执行，不会冲突；但 ADC 等待期间 CPU 什么也干不了（每次约 4 µs）
GPIO.c:497IR_EN 开机后一直是高电平红外发射管一直通电，挂起时也是（引脚总表记过），费电
device.c:529主循环每圈都调 MyADC_Poll_Test()，函数体是空的浪费一次函数调用，可以删

6/8T1A

T1A 的左右键换成 GTRY164 霍尔芯片（SPI），不再需要 ADC 读按键；PIO0_13 / 14 改作线圈 PWM，PIO0_19 改作滚轮信号（T1A 适配清单）。所以 T1A 上：MyADC_Init() 的两次调用、IR_EN 的初始化、LR_GetState() 里的 ADC 分支都要去掉。my_adc.c 这个驱动本身可以留着，以后如果要量电池电压之类的模拟量，按第 3 节的做法加通道。

7/8💡 想法上

1. 读驱动代码，一行对一个寄存器字段
这一页的方法可以用在任何外设上：每看到一句 XXX->REG |= / &= …，就问三件事：哪个寄存器？哪几位？手册里这几位是什么意思？把答案写在旁边。读完一个驱动，你就有了一张“这个外设被设成了什么样”的表。
2. 错误处理的路径，最容易漏掉收尾
上面第一个坑就是典型：正常路径最后会清 SEL，超时提前 return 的路径却没清。以后写“中途可能返回”的函数，检查一下：每一个 return 之前，该恢复的东西都恢复了吗？

8/8小测

记住：开机 MyADC_Init()：PDRUNCFG bit4 清 0（上电）、SYSAHBCLKCTRL bit13 置 1（时钟）、CLKDIV = 15（48 MHz ÷ 16 = 3 MHz）；引脚 IOCON 去上下拉、ADMODE 清 0（模拟）、FUNC = 2（AD）。每次 MyADC_GetValue()：停 → 选 SEL → 读一次 DR 清 DONE → START = 001 → 每 2 µs 看 DONE → 取 DR 第 15~6 位 → 清 SEL。

本页新词

CLKDIVADC 时钟分频：ADC 时钟 = 系统时钟 ÷（CLKDIV + 1），不能超过 4.5 MHz
SELCR 低 8 位，选哪个通道
STARTCR 第 26~24 位，写 001 = 立刻开始转换
DONEDR 第 31 位，转换完成；读一次 DR 自动清掉
ADMODEIOCON 第 7 位：0 = 模拟（断开数字输入电路），1 = 数字
BURST连续转换模式（本项目没用）
