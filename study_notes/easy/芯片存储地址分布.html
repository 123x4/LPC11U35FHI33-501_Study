① ROM · 16 KB

0x1FFF 0000 ~ 0x1FFF 3FFF · 芯片出厂固化，不能改

② Flash · 64 KB

0x0000 0000 ~ 0x0000 FFFF · 放程序，断电不丢

③ RAM（SRAM0）· 8 KB

0x1000 0000 ~ 0x1000 1FFF · 放变量和栈，断电就清

④ USB RAM · 2 KB

0x2000 4000 ~ 0x2000 47FF · USB 专用：柜子表和柜子

四块之间怎么配合：上电到程序跑起来

顺序发生什么用到哪块
1上电。芯片先跑 ROM 里的启动程序：看 PIO0_1 要不要进 ISP，不进就去 Flash 找程序ROM
2跑 Flash 0x0000 的公司 bootloader：看 Flash 0xFE00 和 RAM 0x1000 1F00 两个标志，决定升级还是跳到我们的程序Flash、RAM
3bootloader 把 Flash 0x4000 起的 512 字节（我们程序的向量表）拷到 RAM 0x1000 0000，把 SYSMEMREMAP 设成 1（“中断向量从 RAM 找”），再跳到 0x4004 里写的地址Flash → RAM
4我们的启动代码把 Flash 0xF100 起的变量初值解压拷到 RAM 0x1000 0100，其余变量清 0，然后进 main()Flash → RAM
5nsAPI_USB_Init() 在 USB RAM 里画柜子表；之后 USB 数据都在这里进出USB RAM
6要存设置时，调 ROM 里的 IAP，写 EEPROM（EEPROM 不在地址空间里，只能通过 IAP 读写）ROM、EEPROM
为什么第 3 步要把向量表拷到 RAM？
Cortex-M0 发生中断时，固定去地址 0x0000 0000 附近找中断函数的地址。可是 0x0000 放的是 bootloader 自己的向量表，不是我们的。LPC11U35 有一个寄存器 SYSMEMREMAP（手册 Table 7，p.23）：设成 1 后，CPU 去 0x0 找向量时会改去 RAM 0x1000 0000 找。所以 bootloader 先把我们的向量表搬过去，再打开这个开关。
这也是为什么工程设置里 RAM 从 0x1000 0100 才开始放变量（Sample.uvproj），前面 256 字节留给向量表。
证据：bootloader 二进制里 0x2478 那段代码：关中断 → 从 0x4000 拷 0x200 字节到 0x1000 0000 → 往 0x4004 8000 写 1 → 开中断 → 读 0x4000 设栈 → 跳到 0x4004 里的地址。

顺带发现：Flash 余量比之前说的多

⚠️ 更正
之前第 5 课和 T1A 清单里说“Flash 只剩约 2.9 KB”，这是错的。我当时用 Total ROM Size = 45716 当成了“程序真正占用”。仔细看 List/Sample.map 才发现：代码和常量其实在 0xC514 就结束了，0xC514~0xEFFF 那 10988 字节是链接器为了把 0xF000 那一页放到固定位置而补的空白（map 里标的是 PAD），也算进了 45716。
所以真正还能用的大约是：0xC514~0xEFFF 约 10.7 KB + 0xF28C~0xFDFF 约 2.9 KB ≈ 13.6 KB。代码继续变大时，最先碰到的界线是 0xF000 那一页。第 5 课页面和 T1A 清单已经一起改正。
一句话：ROM 是芯片自带的启动程序和 IAP；Flash 下 16 KB 是公司 bootloader、0x4000 起是我们的程序；RAM 前 256 字节是向量表、然后是变量、再上面是 512 字节的栈；USB RAM 前面是柜子表、后面是每个柜子 64 字节的数据区。
