USB：鼠标怎么把数据交给电脑

鼠标算好的“移动了多少、按了哪个键”，最后都要通过 USB 交给电脑；GUI 软件发来的设置，也是从 USB 进来的。USB 是这个项目里最复杂的外设，但好消息是：最难的部分芯片硬件和现成例程都做好了。这一课的目标是让你分清三件事：芯片自己做什么、例程替你做了什么、项目代码只需要碰哪几个口子。手册看第 11 章（第 10 章是另一套用不到的驱动，只翻一下）。

1/9先记住一句话：电脑是老板，鼠标只能等着被问

USB 上永远是电脑先开口。鼠标不能主动“喊”电脑，只能把要发的数据先放好，等电脑来问。这个项目里，电脑每 1 ms 来问一次鼠标：“有新数据吗？”

  • 放好了 → 芯片把数据发出去，电脑回一句“收到”（ACK）。
  • 没放 → 芯片自动回一句“没有”（NAK），电脑过 1 ms 再来问。
主机（Host）：电脑。所有通信都由它发起。
设备（Device）：鼠标。只能回答。
ACK / NAK：“收到 / 现在没有”，由芯片硬件自动回答，代码不用管。
帧（Frame）：电脑把时间切成 1 ms 一格，每格开头发一个 SOF（帧开始）信号。
线作用IRPT_V4 引脚谁在管
VBUS（5 V）给鼠标供电；芯片看它有没有电，判断线插没插3 号脚 PIO0_3 → 功能 USB_VBUS🟦 芯片自己判断
D+ / D−两根数据线，一起传一个信号（第 1 课的“差分”）14 号 USB_DP、13 号 USB_DM（专用脚）🟦 芯片收发，代码碰不到
CONNECT控制 D+ 上的 1.5 kΩ 上拉电阻：拉上了，电脑才“看见”有设备插进来15 号脚 PIO0_6 → 功能 USB_CONNECT代码写 1 个位打开
GND地——

芯片硬件已经包办了：把 0/1 变成 D+/D− 上的电压、加校验码（CRC）、检查收到的包对不对、回 ACK/NAK。这些在代码里一行都看不到。

2/9端点：芯片里的几个“小柜子”

电脑和鼠标之间不是一根管子，而是好几个“柜子”，叫端点（Endpoint）。每个柜子有编号和方向，各管一类数据。方向永远站在电脑的角度说：

IN：数据进电脑（鼠标 → 电脑）。
OUT：数据出电脑（电脑 → 鼠标）。
ACTIVE 位：每个柜子上的一个“已放好 / 等着收”标记，存在 USB 专用内存里。这一位是整个 USB 代码的核心。
动手 · 端点 1（IN，发鼠标数据）：先点“电脑来问”，再试试“项目放数据”

记住这条规则就够用了：

ACTIVE = 1ACTIVE = 0
IN 端点（发给电脑）数据已放好，等电脑来取已经被取走了 → 可以放下一包
OUT 端点（电脑发来）柜子空着，等电脑放东西电脑放东西进来了 → 去读

代码设 1，芯片清 0。代码放好数据（或读完数据）就把 ACTIVE 设成 1；芯片发完（或收完）自动清成 0。项目里的 nsAPI_USB_EP_Status() 就是去看这一位：返回 TRUE = ACTIVE 是 0（IN：可以放；OUT：有新数据）。

3/9枚举：插上线以后，电脑和鼠标的“自我介绍”

插上 USB 线后，电脑不知道这是什么东西，要先问一大堆问题，这个过程叫枚举。点“下一步”，看每一步是谁在干活：

动手 · 从插线到开始工作，10 步
枚举（Enumeration）：电脑认识新设备的过程。
端点 0（控制端点）：每个 USB 设备都必须有的“前台”，专门用来回答电脑的问题。
SETUP 包：电脑在端点 0 上提的问题，固定 8 个字节。
描述符（Descriptor）：鼠标的“自我介绍”，是一串写死在代码里的字节。

结论：枚举全部由现成代码完成（usbcore.c 回答问题，usbdesc.c 提供答案）。项目要关心的只有“答案”的内容，也就是描述符。

inc/usb.h:282~283：EP_3_CUSTION_OUT 实际是 IN 端点（0x83），EP_4_CUSTION_IN 实际是 OUT 端点（0x04）。起名的人是站在鼠标的角度（“鼠标往外发 / 鼠标往里收”），而 USB 规定站在电脑的角度。看代码时以 inc/hiduser.h:39~46 的数字为准：最高位 1（0x8_）= IN。
HID（人机接口设备）：USB 里专门给鼠标、键盘这类设备的一套规矩。电脑自带 HID 驱动，所以鼠标插上就能用，不用装驱动。
报告（Report）：HID 设备每次发给电脑的那一包数据。报告描述符（usbdesc.c:36 起）告诉电脑每个字节代表什么。

5/9USB 的一生：生命周期图

一句话来龙去脉
Device_Init() 先调 InitUSBOSC() 让 USB PLL 输出 48 MHz，再设 USB 中断优先级为 1，然后调 nsAPI_USB_Init()：开时钟、设两个引脚、在 USB 专用内存里画好“柜子表”、打开中断、拉上 D+ 上拉。之后枚举全部在 USB 中断里由现成代码完成。平时主循环做两件事：Device_Report() 等 EP1 空了就把鼠标数据放进去；PC_Communicate() 看 EP4 有没有 GUI 发来的命令。电脑 3 ms 不来问，芯片报“挂起”，主循环的 Suspend_Check() 让单片机睡觉。
项目代码只需要碰的 3 个口子
① 描述符（usbdesc.c）：告诉电脑“我是谁、有几个柜子、每包长什么样”。
② 发：USB_LoadInEP_Data(端点, 数据, 长度)（usb.c:244）。
③ 收：Usb_Read_Bytes(EP_4_CUSTION_IN, buf, 64)（usb.c:50），在 PC_Communicate() 里调。
其余的 usbhw.c、usbcore.c、usbuser.c、hiduser.c 都可以当成黑盒。

7/9📖 手册导读：第 11 章 USB（只给名字，先自己找）

任务 1：找到第 11 章开头的 Basic configuration，数一数要做几件事，和第 6 节的七步表对一对。
答案11.2，p.221。5 件事：设 IOCON 引脚；SYSAHBCLKCTRL 开 bit14（USB 寄存器）和 bit27（USB 内存）；PDRUNCFG 给 USB PHY 和 USB PLL 通电；设 USB 主时钟（Table 29）；需要的话设 USB 唤醒。代码全做了，唯一“需要的话”的唤醒也做了（REMOTE_WAKEUP_ENABLE = 1）。
任务 2：找 DEVCMDSTAT 的表。看 Access 列：哪几位是 RWC？bit7、bit16、bit17 分别是什么？
答案Table 214，p.226~228。
RWC（读 / 写 1 清）：bit8 SETUP、bit24 DCON_C、bit25 DSUS_C、bit26 DRES_C。
bit7 DEV_EN：打开设备，芯片才会回应。bit16 DCON：置 1 且 VBUS 有电，D+ 上拉就接上，电脑发现设备。bit17 DSUS：3 ms 没动静芯片置 1 = 挂起；挂起时写 0 = 主动叫醒电脑（远程唤醒）。
原文 bit8：“As long as this bit is set all received IN and OUT tokens will be NAKed by HW. SW must clear this bit by writing a one.”
任务 3：找 INTSTAT 和 INTEN 的表。bit0~9、bit30、bit31 各是什么？例程往 INTEN 写的是 DEV_STAT_INT | 0x3FF | FRAME_INT，等于多少？
答案Table 222（p.231~232）、Table 223（p.232）。bit0~9：10 个物理端点（EP0 OUT、EP0 IN、EP1 OUT、EP1 IN … EP4 IN），某个端点的 ACTIVE 被芯片清 0 时置 1。bit30 FRAME_INT：每 1 ms 一次。bit31 DEV_INT：设备状态变化（复位、挂起、断开）。全部是 R/WC。
0x8000 0000 | 0x3FF | 0x4000 0000 = 0xC000 03FF，正好和 usbhw.c:370 清 INTSTAT 用的数一样。
任务 4：找 EPLISTSTART 和 DATABUFSTART。为什么柜子表地址 0x2000 4000 可以用？再查 SYSAHBCLKCTRL 的 bit27 看看这个地址是什么。
答案Table 216、217，p.229。EPLISTSTART 低 8 位固定是 0，所以表必须放在 256 字节对齐的地址；0x2000 4000 低 8 位是 0，可以。DATABUFSTART 只有 bit31:22 能写，所有柜子的数据必须在同一个 4 MB 范围里。
SYSAHBCLKCTRL bit27（Table 24，p.31）：“Enables USB SRAM block at address 0x2000 4000.” 这是芯片里专门给 USB 的 2 KB 内存。
任务 5：搜 Endpoint command/status list（11.7.1），找到那张大图和紧接着的命令表。A 位是什么？软件能不能把它写成 0？
答案Figure 22（p.234）、Table 227（p.235）。每个柜子一个 32 位的字：bit31 A（Active）、bit30 D（Disabled）、bit29 S（Stall）……bit25:16 NBytes（字节数）、bit15:0 地址偏移。
A：“Software can only set this bit to ‘1’. As long as this bit is set to one, software is not allowed to update any of the values in this 32-bit word.” 软件只能置 1，不能写 0；ACTIVE 是 1 的时候连这个字都不能改。想取消要用 EPSKIP 寄存器。这就是为什么发数据之前要先查 nsAPI_USB_EP_Status()。
任务 6：找 USBPLLCTRL，用代码里的 MSEL = 3、PSEL = 1（inc/OSC.h:24~25）和晶振 12 MHz 算 USB 时钟。再搜 Clocking（11.4.7）看看 USB 时钟要求多少。
答案Table 11，p.25：M = MSEL + 1 = 4，输出 = 12 MHz × 4 = 48 MHz。PSEL 只影响 PLL 内部，不改输出。
11.4.7，p.225：USB 主时钟必须是 48 MHz ± 500 ppm，而且全速模式必须来自外部晶振（不能用内部 IRC）。所以 USB 设备必须焊晶振。
任务 7：找 PIO0_3 和 PIO0_6 的 IOCON 表。代码写的是 PIO0_3 |= (BIT3|BIT0)、PIO0_6 |= BIT0，翻译成中文。
答案Table 79（p.88）、Table 82（p.90）。PIO0_3：FUNC = 1 → USB_VBUS；bit4:3 MODE = 01 → 下拉。PIO0_6：FUNC = 1 → USB_CONNECT。
为什么 VBUS 要下拉？usbhw.c:131~133 的注释说：没有下拉的话 VBUS 内部会悬空，检测会出错（NXP 自己的评估板上遇到的问题）。
任务 8：搜 Suspend and resume（11.4.5）。多久没动静算挂起？挂起时鼠标最多能用多少电？
答案11.4.5，p.224：总线上超过 3 ms 没动静进入挂起；挂起的设备最多只能用 500 µA（原文“500 A”是 PDF 丢了 µ 字）。所以挂起时要关传感器、关线圈、让单片机深度睡眠，这就是 wnApi_Events_Suspend_Handler() 做的事。
第 10 章翻一下就行：第 10 章 “USB on-chip drivers” 是芯片 ROM 里自带的另一套 USB 驱动。这个项目没用它，用的是第 11 章的寄存器直接操作（usbhw.c）。知道有这回事即可。

8/9容易出错、你能改什么、T1A

DEVCMDSTAT 用 |= 会顺手清标志 ⚠️DEVCMDSTAT 里 RWC 位和普通位混在一起。DEVCMDSTAT |= X 会先读出来（某个 _C 位可能是 1），再原样写回去 → 那个 _C 位被清掉了。例程正是靠这一点“顺手”清 DRES_C 等位的。你自己改 DEVCMDSTAT 时要知道：任何一次 |= 或 &= 都可能清掉还没处理的状态变化。
端点方向看反EP_3_CUSTION_OUT / EP_4_CUSTION_IN 名字和 USB 方向相反（第 4 节）。
上一包还没被取走就写ACTIVE = 1 时不能改柜子。Device_Report()（device.c:693~700）先最多等 600 µs 查 nsAPI_USB_EP_Status()；但等不到也照样写 ⚠️。USB_LoadInEP_Data() 本身不检查（usb.c:291 那行检查被注释掉了）。
中断里做太多事USB 中断优先级 1，只做设标志、回答枚举。真正的活（发报告、处理 GUI 命令）都在主循环里做。改的时候保持这个习惯。
改描述符后电脑不认Windows 会记住 VID/PID 对应的描述符。改了描述符但 VID/PID 没变，电脑可能用旧的缓存。调试时可以在设备管理器里卸载设备再插，或者临时改 PID。
usb.c 里很多“死代码”Usb_Init()、check_usb_and_endpoint()（usb.c:20、89）全仓库没人调用，是从老项目（另一种芯片）搬过来的残留。真正的初始化是 device.c:449 直接调 nsAPI_USB_Init()。

你能改什么

  • VID / PID、产品名字：inc/usbdesc.h:39~40，字符串在 usbdesc.c:358 起。
  • 回报率：端点描述符的 bInterval（现在都是 1 = 1 ms，即 1000 Hz）。全速 USB 最快就是 1 ms。
  • 报告格式：报告描述符（usbdesc.c:36 起）+ 组包代码（第 16 课）必须一起改，两边不一致电脑会解析错。
  • GUI 命令：PC_Communicate()（pc_communicate.c:882）里的 switch(receive_buff[COMMAND])，第 18 课详细讲。

T1A 上

USB 部分基本不用改：PIO0_3（VBUS）、PIO0_6（CONNECT）、D+/D− 在 T1A 上不变（03_T1A适配清单.md）。要改的是：

  • 新协议 + GUI：可能要改自定义接口（EP3/EP4）的报告长度和 PC_Communicate() 的命令表（第 18 课）。
  • VID / PID：新产品是否换号，问杰哥。
  • 充电芯片 BQ21128：USB 线插着时也在给电池充电。描述符里的 400 mA 是向电脑申请的最大电流，要和充电电流一起算，问硬件同事。

小测验
