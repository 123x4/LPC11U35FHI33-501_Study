# L1 USB 是怎么工作的（原理版）

> 🎯 **现象**：鼠标一插上，电脑就认出“这是一个鼠标”；之后你一按左键，电脑立刻知道。
> 这一课**先不看代码**，把 USB 的原理讲清楚。最后一节才把原理对到代码上，而且只对到“函数在干什么”这一层。
> 1-10 ~ 1-13 的讲义变成选读字典，需要细节时再查。

---

## 一、最关键的一条规则：电脑是老板，鼠标只能等着被问

USB 是**主从结构**：

- **电脑是主机（Host）**：所有通信都由电脑发起。
- **鼠标是设备（Device）**：**永远不能主动开口**，只能等电脑来问，然后回答。

这一条规则能解释后面几乎所有现象。比如：

> 鼠标检测到你按下左键，它不能“打电话”告诉电脑。它只能把“左键按下了”这份数据**准备好、放在门口**，等电脑下一次来问“有新消息吗？”时交出去。

电脑多久来问一次？鼠标在“自我介绍”里告诉电脑：**每 1 ms 来问我一次**（就是你听说过的“1000 Hz 回报率”）。所以从你按下到电脑知道，最多差 1 ms。

---

## 二、一次“问答”在线上长什么样

电脑每 1 ms 来问鼠标一次，线上实际发生的是三个小包（USB 规范叫“一次事务”）：

```
时间 →
电脑 ──[IN 令牌：“1 号信箱，有东西给我吗？”]──▶ 鼠标
电脑 ◀──────────[数据：8 字节鼠标报文]────────── 鼠标      （有新数据时）
电脑 ──────────[ACK：“收到了”]───────────────▶ 鼠标

或者：
电脑 ──[IN 令牌：“1 号信箱，有东西给我吗？”]──▶ 鼠标
电脑 ◀──────────[NAK：“没有新东西”]──────────── 鼠标      （没动、没按键时）
```

**整个过程由芯片里的 USB 硬件自动完成**，CPU 不参与：

- 硬件收到 IN 令牌 → 看“1 号信箱”里有没有准备好的数据 → 有就发出去，没有就自动回 NAK。
- 发完收到 ACK → 硬件在 USB 中断里通知 CPU：“你上次放的数据，电脑已经取走了”。

**软件只需要做一件事：有新数据时，把它放进“1 号信箱”，并标记“准备好了”。**（1-11 课讲的“柜子”和“打 ☑”就是这个。）

---

## 三、“信箱”就是端点

一个鼠标要同时干好几件事：报告鼠标动作、报告键盘按键（宏）、和 GUI 通信。USB 用**端点（Endpoint）**把它们分开，就像一栋楼里有好几个信箱：

| 信箱 | 方向（**永远站在电脑的角度说**） | 本项目用来干什么 |
|---|---|---|
| **EP0** | 双向 | **前台**：电脑和鼠标“第一次见面”时的问答（枚举），每个 USB 设备都必须有 |
| **EP1 IN** | 鼠标 → 电脑 | **鼠标报文**：按键、移动、滚轮 |
| EP2 IN | 鼠标 → 电脑 | 键盘报文（宏、快捷键） |
| **EP3 IN** | 鼠标 → 电脑 | 回复 GUI |
| **EP4 OUT** | 电脑 → 鼠标 | GUI 发来的命令（改参数、升级） |

“IN”“OUT”是站在**电脑**角度说的：IN = 进电脑，OUT = 出电脑。所以鼠标往外发的叫 IN。

---

## 四、第一次见面：枚举（用一段“对话”讲）

鼠标刚插上时，电脑对它一无所知。于是在 EP0 上进行一段**固定格式的对话**，叫**枚举**。把它翻译成人话：

```
（鼠标把 D+ 线拉高 → 电脑：“有新设备插进来了”）              ← 1-10、1-12 课的电路

电脑：“先别说话，重新开始。”                                  ← 总线复位
电脑：“你是谁？把你的名片给我。”                              ← 要“设备描述符”
鼠标：“我是 1A81 厂家的 2071 号产品，USB 2.0，版本 0x0011。”    ← 18 字节名片
电脑：“以后你的门牌号是 5 号。”                                ← 分配地址
电脑：“把你的完整简历给我。”                                  ← 要“配置描述符”
鼠标：“我有 3 个功能：
        功能 0 是鼠标，用 1 号信箱发数据，每 1 ms 来取一次；
        功能 1 是键盘，用 2 号信箱；
        功能 2 是自定义的，用 3 号信箱发、4 号信箱收。
        我要用 400 mA 的电。”
电脑：“你叫什么名字？”                                       ← 要“字符串描述符”
鼠标：“Gtech Magnetic Mouse”
电脑：“好，按这份简历开始工作。”                              ← SET_CONFIGURATION
                                                            （鼠标此时打开 1~4 号信箱）
电脑：“功能 0 的数据格式是什么样的？”                          ← 要“HID 报告描述符”
鼠标：“每包 8 字节：第 1 字节是按键，第 2~3 字节是左右移动……”
电脑：“明白了，我会用 Windows 自带的鼠标驱动来读你。”
（之后每 1 ms，电脑来 1 号信箱取一次数据）
```

几个关键点：

1. **名片、简历、名字、数据格式说明书**，在 USB 里统称**描述符（Descriptor）**。它们是鼠标里**写死的几段常量数据**（在 `src/usbdesc.c`），电脑问哪个就原样交出去。
2. **为什么 Windows 不用装驱动就能用这个鼠标？** 因为鼠标在简历里说“我是 **HID 类**（人机接口设备）”，并且交出了“数据格式说明书”（HID 报告描述符）。Windows 自带通用 HID 驱动，看说明书就知道每个字节是什么意思。
3. 这段对话**全部在 USB 中断里自动完成**，主程序完全不参与，几百毫秒内就结束了。

## 五、鼠标报文：8 个字节的含义

数据格式说明书（HID 报告描述符）规定，1 号信箱里每包是 8 字节：

| 字节 | 内容 | 例子：按着左键、向右移 3、向上移 2 |
|---|---|---|
| 0 | 报告编号 = 1 | `01` |
| 1 | 按键：bit0 左键、bit1 右键、bit2 中键、bit3 / bit4 两个侧键（Windows 默认当作“后退 / 前进”；本项目内部按键怎么映射到这两位，L2 课看 `Device_Pack()` 时确认） | `01`（只有左键） |
| 2~3 | X 左右移动（16 位，有符号，右为正） | `03 00` |
| 4~5 | Y 上下移动（16 位，有符号，**下为正**） | `FE FF`（-2） |
| 6 | 滚轮 | `00` |
| 7 | 横向滚动 | `00` |

所以整包是：`01 01 03 00 FE FF 00 00`。

> 多字节数是**低字节在前**（小端）：3 写成 `03 00`；-2 的 16 位补码是 0xFFFE，写成 `FE FF`。

**一次左键点击在 USB 线上的样子**：

```
时间（ms）   电脑来取 1 号信箱    鼠标交出的数据                说明
0           IN                  NAK                          还没按，没有新数据
…           IN                  NAK
100         IN                  01 01 00 00 00 00 00 00      ← 按下左键（按键字节 bit0 = 1）
101         IN                  NAK                          按着不动，没有变化就不发
…
180         IN                  01 00 00 00 00 00 00 00      ← 松开左键（bit0 = 0）
```

Windows 看到 bit0 从 0 变 1，就产生“左键按下”事件；从 1 变 0，就是“左键抬起”。

## 六、把原理对到芯片和代码上

现在回头看，芯片和代码分别负责什么：

| 工作 | 谁来做 | 在哪 |
|---|---|---|
| D+/D- 上的电压、包的收发、ACK/NAK、校验 | **USB 硬件自动完成** | 芯片内部 |
| 把 D+ 拉高“举手” | 软件开个开关，硬件 + 板上三极管完成 | 1-10、1-12 课 |
| 告诉硬件“每个信箱的数据放在内存哪里” | 软件，开机时一次 | 1-11 课（登记表、柜子） |
| 枚举对话：听懂电脑的问题、交出描述符 | 软件，在 USB 中断里自动进行 | `usbcore.c`（○ 黑盒即可） |
| 名片、简历、名字、数据格式说明书 | 软件里写死的常量 | `usbdesc.c`（★ 可能会改） |
| 每次有新动作，组一包 8 字节放进 1 号信箱 | 软件，主循环 | `device.c` 的 `Device_Report()`（★，L2 课讲） |

**你写代码时只会碰到两样东西**：

1. **`usbdesc.c` 里的描述符**：改产品 ID、改名字、改报文格式时才动。
2. **一个“放数据进信箱”的函数**：

   ```c
   USB_LoadInEP_Data(EP_1_MOUSE, report_data.mouse_report, 8);      // src/device.c:701
   //                1 号信箱     8 字节报文的地址              长度
   ```

   调用一次，就等于“把 8 字节放进 1 号信箱，标记准备好”。之后电脑来取、硬件发送、确认，全部自动完成。

至于 `usbhw.c`、`usbcore.c` 里面怎么填登记表、怎么一问一答——那是**通用的 USB 协议栈**，NXP 写好的，本项目和 T1A 都不需要改。你知道“它负责枚举对话和信箱管理”就够了（深度 ○）。

## 七、动手观察（零风险，都在电脑上看）

1. **设备管理器 → 鼠标 → 属性 → 详细信息 → 硬件 ID**：能看到 `VID_1A81&PID_2071`，以及 `MI_00`、`MI_01`、`MI_02`——这就是“名片”上的厂家号、产品号，和“简历”里的 3 个功能。
2. **USB 查看工具（推荐 UsbTreeView，免费、只读）**：在列表里找到这个鼠标，可以看到电脑从它那里拿到的**全部描述符原文**：名片、简历（3 个接口、4 个端点、每 1 ms）、名字 “Gtech Magnetic Mouse”。拿它和本课第四节的“对话”逐条对照。
3. **对比 Bootloader**：升级固件时，设备会变成 `17EF:6155`（0-3 课）——那是 Bootloader 的“名片”。
