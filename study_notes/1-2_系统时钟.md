> 📍 **位置**：`main()` → `Device_Init()`（`src/device.c:415`）→ **第 420 行 `InitSystemOSC( MAIN_SEL , PSEL , MSEL , SYS_AHB_DIV_VAL) ;`**

## 一、这一行要解决什么问题

上一课结束时，CPU 的状态是（0-4 课讲过）：

📖 **UM p19，3.4 节**：

> Following reset, the LPC11U3x/2x/1x will operate from the Internal RC oscillator until switched by software.

也就是说，**复位后 CPU 跑在芯片内部的 IRC（12 MHz RC 振荡器）上**。IRC 的缺点是不准（📖 DS p49：12 MHz ± 1%），而 USB 全速要求时钟误差在 ±0.25% 以内，所以必须换成**外部晶振**。

`InitSystemOSC()` 就干一件事：

```
把 CPU 的时钟从 “内部 IRC 12MHz” 换成 “外部晶振 12MHz × 4 = 48MHz”
```

---

## 二、先看懂时钟树（只画这一课用到的部分）

📖 **UM p20 Figure 7** 是完整的时钟图，里面有很多支路。这一课只走下面这一条，每个方框旁边标了控制它的寄存器：

```
                         ① PDRUNCFG bit5 上电
                         ② SYSOSCCTRL 选频段
   外部 12MHz 晶振 ──▶ [ 系统振荡器 SYSOSC ] ─┐
   (XTALIN/XTALOUT)                         │       ③ SYSPLLCLKSEL=1 选晶振
                                             ├──▶ [ 选择器 ] ──▶ sys_pllclkin = 12MHz
   内部 IRC 12MHz ───────────────────────────┘      (UEN 0→1 生效)
                                                             │
                                                             ▼
                                     ④ SYSPLLCTRL 设 M、P    [ 系统 PLL ]  ×4
                                     ⑤ PDRUNCFG bit7 上电     │
                                     ⑥ 等 SYSPLLSTAT 锁定      ▼
                                                     sys_pllclkout = 48MHz
                                                             │
   IRC 12MHz ──────────┐                                     │
   PLL 输入 ───────────┤                                     │
   看门狗振荡器 ───────┤──▶ [ 选择器 ] ◀───────────────────────┘
                       │   ⑦ MAINCLKSEL=3 选 PLL 输出 (UEN 0→1 生效)
                       │        │
                       │        ▼  main clock = 48MHz
                       │   [ ÷ SYSAHBCLKDIV ]  ⑧ 写 1，不分频
                       │        │
                       │        ▼  system clock = 48MHz
                       │   CPU、存储器、各外设 ──（SYSAHBCLKCTRL 每位一个开关）⑨ 打开 IOCON
```

记住三个名字，后面每一课都会用到：

| 名字 | 是什么 | 本项目的值 |
|---|---|---|
| **sys_pllclkin** | 送进 PLL 的时钟 | 12 MHz（晶振） |
| **main clock** | PLL 之后、分频之前 | 48 MHz |
| **system clock** | CPU 和外设真正用的时钟 | 48 MHz（÷1） |

## 三、参数先代进去

`device.c:420` 传入的 4 个参数都在 `inc/OSC.h`：

| 参数 | 宏 | 值 | 去哪个寄存器 |
|---|---|---|---|
| SysOSC | `MAIN_SEL` | 1 | SYSPLLCLKSEL（选 PLL 的输入） |
| SysPSEL | `PSEL` | 1 | SYSPLLCTRL bit 6:5 |
| SysMSEL | `MSEL` | 3 | SYSPLLCTRL bit 4:0 |
| AHBDiv | `SYS_AHB_DIV_VAL` | 1 | SYSAHBCLKDIV |

还有一个函数内部直接用的宏：`OSC_Freqrange = 0`。

> ⚠️ **名字有误导**：`MAIN_SEL` 的注释写 “Select System OSC (0:IRC_OSC 1:SYSTEM_OSC)”，名字像是 “主时钟选择”，但它实际写进的是 **SYSPLLCLKSEL（PLL 输入选择）**，不是 MAINCLKSEL。真正的主时钟选择在函数里写死成了 3。

## 四、逐行讲解（`src/OSC.c` 第 29~56 行）

### 第 34 行：设置晶振频段

```c
LPC_SYSCON->SYSOSCCTRL |= (OSC_Freqrange<<1) ;   // OSC_Freqrange = 0
```

📖 **UM p25 Table 13**（SYSOSCCTRL，地址 0x4004 8020）：

| 位 | 名字 | 复位值 | 含义 |
|---|---|---|---|
| 0 | BYPASS | 0 | 0 = 正常用晶振；1 = 旁路，用外部方波直接从 XTALIN 输入 |
| 1 | FREQRANGE | 0 | **0 = 1~20 MHz**；1 = 15~25 MHz |

12 MHz 落在 1~20 MHz，所以选 0。

**这一行实际上什么都没改**：`|= (0<<1)` 就是 `|= 0`，读出来原样写回去。看编译产物也能证实，编译器只留下了一读一写：

```
492e: 6a2b   ldr  r3, [r5, #0x20]    ; 读 SYSOSCCTRL（r5 = 0x40048000，偏移 0x20）
4930: 622b   str  r3, [r5, #0x20]    ; 原样写回
```

（反汇编来自 `output/Sample.axf`，`InitSystemOSC` 在 0x4928，见 `List/Sample.map` 第 879 行。）

它之所以“刚好正确”，是因为复位值本来就是 0。如果以后换成 16 MHz 以上的晶振、把宏改成 1，这行能把 bit1 置 1；但反过来从 1 改回 0 是做不到的（`|=` 只能置 1，不能清 0）。

### 第 35 行：给晶振电路上电

```c
LPC_SYSCON->PDRUNCFG &= ~(0x1<<5) ;   // SYSOSC_PD = 0
```

📖 **UM p43 Table 47**（PDRUNCFG，地址 0x4004 8238）：

| 位 | 名字 | 复位值 | 本课是否改 |
|---|---|---|---|
| 0 | IRCOUT_PD | 0（上电） | 不改 |
| 1 | IRC_PD | 0（上电） | 不改 |
| 4 | ADC_PD | 1（断电） | 1-20 课改 |
| **5** | **SYSOSC_PD** | **0（上电）** | **本行写 0** |
| 6 | WDTOSC_PD | 1（断电） | 1-1 课已写 0 |
| **7** | **SYSPLL_PD** | **1（断电）** | **第 45 行写 0** |
| 8 | USBPLL_PD | 1（断电） | 1-5 课改 |

PDRUNCFG 里 **1 = 断电，0 = 上电**，和直觉相反，所以代码用 `&= ~` 清零来“打开”。

注意 bit5 的复位值**已经是 0**（晶振默认就上电），这一行同样是保险写法。Bootloader 跑过之后也不会关它（Bootloader 本身就要用晶振跑 USB），所以无论从哪条路进来都是上电状态。

📖 UM p43：“a write will take effect immediately”，写完立刻生效。

### 第 36 行：粗略延时，等晶振起振

```c
for( OSCI = 0; OSCI < 0x100; OSCI++ ) ;
```

晶振从上电到稳定输出需要一段时间（起振时间）。这里用空循环等一下。

**这个循环到底等了多久？** 看反汇编：

```
493c: 2300   movs r3, #0x0         ; OSCI = 0
493e: 1c5b   adds r3, r3, #0x1     ; OSCI++            1 周期
4940: b29b   uxth r3, r3           ; 截成 16 位         1 周期
4942: 2bff   cmp  r3, #0xff        ;                   1 周期
4944: d9fb   bls  0x493e           ; ≤0xFF 就跳回去     跳转时 3 周期
```

每圈约 6 个时钟周期，共 256 圈 ≈ 1536 个周期。此时 CPU 还跑在 IRC 12 MHz 上，1536 ÷ 12 MHz ≈ **0.13 ms**（再加上取指令等 Flash 的时间，实际会长一点，但也就是零点几毫秒）。

> 💡 编译器没有把这个“什么也不做”的循环删掉，说明工程的优化等级较低。如果以后把优化开高，这种延时循环**可能被整个删除**。

**0.13 ms 够不够？** 一般晶振起振要几百微秒到几毫秒，所以这个延时**不一定够**。但没关系，后面的第 46 行“等 PLL 锁定”才是真正的保险：晶振没稳定，PLL 就锁不上，程序会一直等在那里。

### 第 38~42 行：把 PLL 的输入选成晶振

```c
LPC_SYSCON->SYSPLLCLKSEL = SysOSC ;       // = 1，晶振
LPC_SYSCON->SYSPLLCLKUEN = 0x01 ;
LPC_SYSCON->SYSPLLCLKUEN = 0x00 ;
LPC_SYSCON->SYSPLLCLKUEN = 0x01 ;
while ( !(LPC_SYSCON->SYSPLLCLKUEN & 0x01) ) ;
```

📖 **UM p28 Table 17**（SYSPLLCLKSEL，0x4004 8040）：

| SEL 值 | PLL 输入 |
|---|---|
| 0 | IRC |
| **1** | **晶振 (SYSOSC)** ← 复位值也是 1 |

📖 **UM p29 3.5.12 节**（SYSPLLCLKUEN，0x4004 8044）：

> In order for the update to take effect, first write a zero to the SYSPLLUEN register and then write a one to SYSPLLUEN.

**为什么要“0 再 1”？** 时钟选择器不会因为你改了 SEL 就马上切换（切换瞬间可能产生毛刺）。芯片规定：**UEN 寄存器出现一次 0→1 的变化**，选择器才去执行切换。所以写法固定为：

```
写 SEL  →  UEN 写 0  →  UEN 写 1   （这一次 0→1 触发切换）
```

代码里多写了一个开头的 `= 0x01`（UEN 复位值本来就是 1），没有作用，但也没有坏处。最后的 `while` 读回 UEN 确认是 1。

📖 UM p29 还有一句提醒（写在 USB PLL 那一节，系统 PLL 同理）：

> When switching clock sources, both clocks must be running before the clock source is updated.

也就是切换时**新旧两个时钟都必须在跑**。所以第 35~36 行要先给晶振上电、等一会儿，再来切换。

### 第 44 行：设置倍频系数

```c
LPC_SYSCON->SYSPLLCTRL = ((SysPSEL<<5) | SysMSEL) ;   // (1<<5)|3 = 0x23
```

📖 **UM p24 Table 9**（SYSPLLCTRL，0x4004 8008）：

| 位 | 名字 | 含义 | 本项目 |
|---|---|---|---|
| 4:0 | MSEL | 倍频 M = MSEL + 1 | 3 → **M = 4** |
| 6:5 | PSEL | 后分频 P：0→1, 1→2, 2→4, 3→8 | 1 → **P = 2** |

📖 **UM p55 公式 (1)**：

```
Fclkout = M × Fclkin = FCCO ÷ (2 × P)
```

代进去：

```
Fclkout = 4 × 12 MHz = 48 MHz
FCCO    = 2 × P × Fclkout = 2 × 2 × 48 MHz = 192 MHz
```

📖 **UM p55 Table 51**：FCCO 必须在 **156~320 MHz** 之间。192 MHz 在范围内 ✅。

📖 **UM p55 Table 52** 直接给了 12 MHz 晶振的配置例子，第一行就是：

| 输入 | 输出 | MSEL | M | PSEL | P | FCCO |
|---|---|---|---|---|---|---|
| 12 MHz | 48 MHz | 00011 | 4 | 01 | 2 | 192 MHz |

**和本项目完全一样**。写这段代码的人就是照着这张表配的。

**PLL 内部为什么有个 FCCO？** 📖 UM p53~54，3.10 节：PLL 内部有一个电流控制振荡器（CCO），它先振到一个很高的频率 FCCO，再除以 2P 得到输出。CCO 只能在 156~320 MHz 稳定工作，所以 P 不能随便选：

```
P=1 → FCCO =  96 MHz  ✗ 太低
P=2 → FCCO = 192 MHz  ✓
P=4 → FCCO = 384 MHz  ✗ 太高
```

48 MHz 输出只有 P=2 这一种选择。

📖 UM p54 “Changing the divider values”：PLL 运行时不建议改 M、P，推荐“先断电 → 改参数 → 再上电”。这段代码的顺序正好是这样：第 44 行改参数时 PLL 还是断电的（复位值 bit7=1），第 45 行才上电。

### 第 45~46 行：给 PLL 上电，等它锁定

```c
LPC_SYSCON->PDRUNCFG &= ~(0x1<<7) ;            // SYSPLL_PD = 0，PLL 上电
while ( !(LPC_SYSCON->SYSPLLSTAT & 0x01) ) ;   // 等 LOCK = 1
```

📖 **UM p24 Table 10**（SYSPLLSTAT，0x4004 800C，只读）：bit0 LOCK，0 = 未锁定，1 = 已锁定。

📖 **UM p54，3.10.1 Lock detector**：PLL 比较输入时钟和反馈时钟，**连续 8 个输入周期**相位差都足够小，LOCK 才变成 1。一次偏差过大，计数清零重来。

所以 LOCK=1 意味着：**晶振已经稳定输出 12 MHz，PLL 也已经稳定输出 48 MHz**。这就是上面说的“真正的保险”。

**如果晶振坏了会怎样？** PLL 没有输入，永远锁不上，程序卡死在这个 `while` 里。这时 1-1 课开的看门狗（约 65 秒）会把芯片复位。复位后再走一遍，晶振还是坏的，再卡住，再复位……用户看到的现象是：**鼠标插上电脑没有任何反应**（USB 都没有初始化）。

### 第 48~52 行：主时钟切到 PLL 输出

```c
LPC_SYSCON->MAINCLKSEL = 0x03 ;       // PLL 输出
LPC_SYSCON->MAINCLKUEN = 0x01 ;
LPC_SYSCON->MAINCLKUEN = 0x00 ;
LPC_SYSCON->MAINCLKUEN = 0x01 ;
while ( !(LPC_SYSCON->MAINCLKUEN & 0x01) ) ;
```

📖 **UM p30 Table 21**（MAINCLKSEL，0x4004 8070）：

| SEL 值 | 主时钟来源 |
|---|---|
| 0 | IRC ← 复位值 |
| 1 | PLL 输入（这里就是晶振 12 MHz 直接用） |
| 2 | 看门狗振荡器 |
| **3** | **PLL 输出** |

📖 **UM p30 Table 22**（MAINCLKUEN）：和 SYSPLLCLKUEN 一样，0→1 才生效。

**这一步是整个函数的关键时刻**：第 51 行那次 `= 0x01` 执行完，CPU 的时钟从 12 MHz 变成 48 MHz，之后每条指令都快了 4 倍。前面所有步骤都是为这一刻做准备：PLL 已锁定 = 新时钟稳定，IRC 还在跑 = 旧时钟没停，满足“两个时钟都在跑”的条件。

### 第 54 行：系统时钟不分频

```c
LPC_SYSCON->SYSAHBCLKDIV = AHBDiv ;   // = 1
```

📖 **UM p31 Table 23**（SYSAHBCLKDIV，0x4004 8078）：DIV = 0 关闭系统时钟；1 = ÷1；…；255 = ÷255。复位值 1。

所以 system clock = 48 MHz ÷ 1 = 48 MHz。这一行也是写了和复位值一样的值。

> ⚠️ 千万不要写 0：0 表示系统时钟关闭，CPU 会立刻停止。

### 第 55 行：打开 IOCON 的时钟

```c
LPC_SYSCON->SYSAHBCLKCTRL |= (1<<16) ;
```

📖 **UM p32 Table 24**：bit16 **IOCON**，复位值 0。

IOCON 是“引脚功能配置”模块（每个引脚当 GPIO、ADC 还是 SPI，都在它里面设置）。这一行严格说和时钟切换无关，是为**下一课 `InitGPIO()`** 做准备：不开它的时钟，就写不进 IOCON 寄存器。

## 五、这个函数没做、但应该检查的一件事：Flash 等待周期

CPU 变快了，Flash 读得过来吗？

📖 **UM p45 Table 49**（FLASHCFG，0x4003 C010）：

| FLASHTIM | Flash 访问用几个时钟 | 适用的系统时钟 |
|---|---|---|
| 0 | 1 | ≤ 20 MHz |
| 1 | 2 | ≤ 40 MHz |
| **2** | **3** | **≤ 50 MHz** ← 复位值 |

📖 UM p45 Remark：“Improper setting of this register may result in incorrect operation”。

本项目整个工程都**没有写 FLASHCFG**，靠的是复位值 2（3 个时钟），刚好支持到 50 MHz，48 MHz 没问题 ✅。

但要注意：**复位值是最慢、最保守的设置**，所以 12 MHz 跑 IRC 时也是用 3 个时钟读 Flash，这也是第 36 行延时循环实际比计算值慢一点的原因之一。

## 六、函数执行前后，寄存器的变化

| 寄存器 | 执行前（复位值） | 执行后 | 是否真的改了 |
|---|---|---|---|
| SYSOSCCTRL | 0x0 | 0x0 | 否 |
| PDRUNCFG bit5 | 0 | 0 | 否 |
| SYSPLLCLKSEL | 1 | 1 | 否（但触发了一次 UEN 更新） |
| SYSPLLCTRL | 0x00 | **0x23** | ✅ |
| PDRUNCFG bit7 | 1 | **0** | ✅ PLL 上电 |
| MAINCLKSEL | 0 | **3** | ✅ 主时钟换成 PLL |
| SYSAHBCLKDIV | 1 | 1 | 否 |
| SYSAHBCLKCTRL bit16 | 0 | **1** | ✅ IOCON 时钟 |

**真正起作用的只有 4 处**：设倍频、PLL 上电、切主时钟、开 IOCON。其余都是“写一遍复位值”的保险写法。

## 七、`MCU_OSC` 这个宏

`inc/OSC.h`：

```c
#define OSC      12000000UL
#define MCU_OSC  ( OSC * ( MSEL + 1 ) )   // = 48000000
```

后面很多代码用它来算分频值：

| 用在哪 | 干什么 |
|---|---|
| `src/IAP_CMD.c:66`、`gtech_flash.c:54` 等 | IAP 命令要告诉 ROM 当前系统时钟是多少 kHz（`MCU_OSC/1000` = 48000） |
| `src/ADC.c:64` | 算 ADC 分频 |
| `src/Timer.c:382` | 算 PWM 周期 |
| `inc/device.h:144` | `DELAY_COUNT` 延时 |

> ⚠️ 这个宏**只看 MSEL，不看 PSEL 和 SYSAHBCLKDIV**。现在 SYSAHBCLKDIV=1，所以结果正确；如果有人把 `SYS_AHB_DIV_VAL` 改成 2（系统时钟变成 24 MHz），`MCU_OSC` 还是 48000000，所有用它算的分频都会错一倍，IAP 写 EEPROM 也可能出问题。

## 八、硬件对照：晶振电路

**IRPT_V4（你手上的板）没有原理图**，只能参考 T1A。两块板的 MCU 最小系统基本相同。

**T1A 新板原理图**（`materials/GT_Lina T1A Hall Haptic POC_SCH_V0.1.pdf`，MCU 那一页）：

```
         XTALIN (pin 4)        XTALOUT (pin 5)
            │                      │
            ├──────[ 12MHz ]───────┤
            │                      │
          ─┴─ C43 12pF          ─┴─ C48 12pF
            │                      │
           GND                    GND
```

📖 **DS p56，11.2 节**：芯片内部已经集成了反馈电阻，外面**只需要一颗晶振 + 两颗电容**（Figure 30）。

📖 **DS p56 Table 18**：10~15 MHz 晶振，如果晶振的负载电容 CL = 10 pF，推荐外接电容 18 pF。T1A 用的是 12 pF，说明选的晶振 CL 更小（具体要看晶振的规格书）。这一点可以问硬件同事：**晶振型号和 CL 是多少**。

## 十、小结

```
上电 → IRC 12MHz
          │
          │  第 35~36 行  晶振上电，等一会儿
          │  第 38~42 行  PLL 输入 = 晶振（UEN 0→1）
          │  第 44 行     M=4, P=2  →  48MHz, FCCO=192MHz（UM p55 Table 52 第一行）
          │  第 45~46 行  PLL 上电，等 LOCK（晶振坏了就卡在这里，靠看门狗救）
          │  第 48~52 行  主时钟 = PLL 输出（UEN 0→1）  ← 从这一刻起 48MHz
          │  第 54 行     ÷1
          │  第 55 行     打开 IOCON 时钟，为下一课 InitGPIO 准备
          ▼
       48MHz 晶振时钟
```

**三条规律**，以后读其他时钟代码都适用：

1. **PDRUNCFG：0 = 上电，1 = 断电**。
2. **改时钟选择器：先写 SEL，再让 UEN 出现一次 0→1**。
3. **改 PLL 参数：先断电改参数，再上电等 LOCK**。

## 🧪 验证（零风险）

1. **USB 能枚举就说明本课全部成功**：USB 全速需要准确的 48 MHz，IRC 的 ±1% 达不到。你的板子插上电脑能被识别，`hid_tool.py list` 能看到设备，就证明晶振、PLL、主时钟切换都正常。
2. **对照反汇编**：在 `output/Sample.axf` 里找到 0x4928，对着第四节逐条比对寄存器偏移（0x20 = SYSOSCCTRL，0x38 → 0x238 = PDRUNCFG，0x40 = SYSPLLCLKSEL，0x08 = SYSPLLCTRL，0x0C = SYSPLLSTAT，0x70 = MAINCLKSEL，0x78 = SYSAHBCLKDIV，0x80 = SYSAHBCLKCTRL）。命令：
   ```
   llvm-objdump -d --triple=thumbv6m --start-address=0x4928 --stop-address=0x4994 output/Sample.axf
   ```
   （Windows 上可以用 Keil 自带的 `fromelf -c output/Sample.axf`，然后搜 `InitSystemOSC`。）

> ⚠️ **不要尝试**改这一课的参数来做实验（比如改 MSEL）。时钟改错，USB 就枚举不上，你就没法再用 USB 升级程序，只能靠 PIO0_1 进 ISP 救板。在确认救板方法之前，`Device_Init()` 前几行（看门狗、时钟、USB）都不要动。
