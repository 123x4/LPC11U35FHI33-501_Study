# 项目全景与新学习路线

> 这是重新设计后的学习主线。之前 0-x、1-x 的逐行讲义**不作废**，变成“字典”：讲到哪里需要细节，就链接过去查。
> 你的目标：**能灵活使用和修改这个项目的代码；理解各种协议的原理；遇到很复杂的部分，至少知道它在干什么。**

---

## 一、为什么换一种讲法

之前是“从 `main()` 第一行开始逐行往下读”。这种方法的问题，在 1-10 ~ 1-13 已经很明显了：

| 问题 | 表现 |
|---|---|
| **先看树叶，看不见森林** | 讲到 USB 初始化时，你还不知道“USB 在整个鼠标里是干什么的”，细节就无处安放 |
| **初始化代码是最枯燥、最难懂的部分** | 设寄存器、填表格，读起来没有“故事” |
| **所有代码一样深** | NXP 的 USB 通用例程（几乎不用改）和你以后要改的按键、线圈代码，花了一样多甚至更多的力气 |

新的讲法：

1. **先给全景图**（本文件）：整个项目分几层、主循环一圈做什么、数据怎么流动。
2. **再沿着“功能线”走**：从一个**你能看到、摸到的现象**出发（按一下左键、移一下鼠标、GUI 改一个参数），顺着数据流穿过各层，一直走到电脑。每层只讲到“理解这条线”需要的深度。
3. **原理课穿插在功能线里**：讲 USB、SPI、ADC、HID、通信协议时，**先讲原理、再看代码**，而且原理用具体字节、具体波形讲，不讲空概念。
4. **每段代码标上“深度等级”**：

| 标记 | 意思 | 例子 |
|---|---|---|
| ★ **要会改** | 必须读懂每一行，以后自己会修改 | 引脚定义、按键算法、线圈时序、协议命令、描述符 |
| ◆ **要懂原理** | 知道它为什么这样做，能看懂流程 | USB 枚举、SPI 时序、ADC 采样、EEPROM 存储 |
| ○ **知道在干什么** | 知道输入、输出、副作用，内部当黑盒 | USB 协议栈内部（`usbhw.c` / `usbcore.c`）、启动文件、IAP |

## 三、程序是怎么“跑”起来的：两条线同时进行

```
main()                                         src/Main.c
 ├─ Device_Init()     开机初始化一次（0-x、1-x 课讲的就是这里）
 └─ Device_Active()   死循环，永远不退出        src/device.c:493
      while (1) {
          Device_Scan();       ① 采集：传感器位移、按键（每 1 ms）、滚轮
          Device_Pack();       ② 组包：把采集结果拼成 8 字节鼠标报文
          Device_Report();     ③ 上报：报文放进 EP1，等电脑来取
          wwdt_feed();         ④ 喂看门狗
          PC_Communicate();    ⑤ 看 GUI 有没有发命令来，有就处理
          Suspend_Check();     ⑥ 电脑睡眠了吗？要不要省电
          Ele_PollingTask();   ⑦ 线圈状态机（消抖、保护）
          Task_ParamGuard();   ⑧ 参数改过了吗？要不要写 EEPROM
      }

同时，中断随时打断主循环：
  CT16B0 中断（每 1 ms）  → 毫秒计时 mySysTickMs++、各种倒计时减 1
  USB 中断               → 枚举问答（自动完成）、“报文已被取走”通知、收到 GUI 数据
  看门狗中断             → 程序卡死时复位
```

**最重要的一句话**：主循环负责“**干活**”（采集、组包、处理命令），中断负责“**计时**”和“**和电脑打交道**”。两者通过全局变量交接，例如：主循环把报文放进 EP1 柜子 → USB 中断告诉主循环“取走了”。

## 四、新的学习路线：六条功能线

每条线都从一个**现象**出发，按“现象 → 原理 → 代码路径 → 动手观察 → 你能改什么”的顺序讲。

| 线 | 现象 | 穿过哪些层 | 原理课 | 和 T1A 适配的关系 |
|---|---|---|---|---|
| **L1 USB** | 鼠标一插上，电脑就认出来了 | 硬件 → USB 协议栈 → 描述符 | **USB 怎么工作**、HID 报告 | USB 基本不用改，但必须懂 |
| **L2 一次点击** | 按下左键 → 电脑收到点击 | 红外光电 → ADC → 按键算法（AP/RT）→ 组包 → EP1 | ADC 采样、触发算法、HID 报文 | ★ 改成 Hall 芯片（需求①） |
| **L3 一次“咔哒”** | 按下左键 → 手指感到振动 | 按键事件 → 线圈状态机 → MOS 管 → 升压 | 电磁线圈、MOS、续流、制动 | ★ 引脚和升压控制要改 |
| **L4 移动光标** | 移动鼠标 → 光标移动 | PAW3950 → SPI → 位移 → 组包 | **SPI 协议**、光学传感器 | ★ SSP1 改 SSP0（需求④） |
| **L5 GUI 调参** | GUI 改触发点 → 立即生效、断电不丢 | EP4 OUT → 协议解析 → 参数 → EEPROM | **自定义通信协议**、校验、EEPROM | ★ 合入新协议（需求④） |
| **L6 系统机制** | 开机、升级、睡眠唤醒、死机自救 | Bootloader、中断/主循环时序、看门狗、挂起 | 启动流程、中断、低功耗 | ◆ 理解即可 |
| **毕业** | T1A 新板跑起来 | 全部 | — | 编码器（需求②）、充电芯片 BQ21128（需求③） |

**顺序**：L1（把 USB 的疑问彻底解决）→ L2 → L3 → L4 → L5 → L6 → 毕业项目。L2~L5 是你以后最常改的代码，会讲得最细。

## 五、每一课的样子

```
🎯 现象         从一个能看到的事情出发
🧠 原理         用具体字节、具体电压讲清楚“为什么”
🧭 代码路径     函数调用链（谁调用谁），每个函数一句话说明 + 深度标记 ★◆○
🔬 动手观察     用 hid_tool、设备管理器、USB 查看工具等零风险地看到它
🛠️ 你能改什么   如果要改这个功能，改哪个文件哪几行，会有什么影响
📚 字典         需要细节时去查哪份旧讲义
```
