# 1-1 看门狗：`wwdt_config(0xFFFF)`

> 📍 **位置**：`main()` → `Device_Init()`（`src/device.c:415`）→ **第 419 行 `wwdt_config(0xFFFF);`**
> 📄 **代码**：`src/WWDT.c`（全文 105 行）
> 📖 **手册**：UM 第 17 章 p369~378（WWDT）；第 3 章 p26 Table 14（WDTOSCCTRL）、p32 Table 24（SYSAHBCLKCTRL）、p41（STARTERP1）、p44 Table 47（PDRUNCFG）；DS p30（看门狗振荡器精度）

---

## 一、看门狗是干什么的

📖 **UM p370，17.4 Applications**：

> The purpose of the Watchdog Timer is to reset or interrupt the microcontroller within a programmable time if it enters an erroneous state.

看门狗是芯片里一个**独立的倒计时器**。程序正常运行时，要定期去“喂狗”，把倒计时重新拉满。如果程序卡死了，没人喂，倒计时归零，看门狗就**把整个芯片复位**，让程序从头再来。

```
正常：  倒计时 ████████▇▆▅ ← 喂狗 → ████████▇▆▅ ← 喂狗 → ……  永远到不了 0
卡死：  倒计时 ████████▇▆▅▄▃▂▁  0 → 芯片复位，从头运行
```

0-4 课讲过：某个中断没写处理函数时，CPU 会卡在 `B .` 死循环里。这时救场的就是看门狗。

**为什么放在 `Device_Init()` 第一行？** 后面的初始化里有很多“等待硬件就绪”的循环，比如下一课 `InitSystemOSC()` 里的 `while (!(LPC_SYSCON->SYSPLLSTAT & 0x01));`（等 PLL 锁定）。如果晶振坏了，这个循环永远出不来。先开看门狗，初始化卡住也能被复位。

---

## 二、看门狗的时钟从哪来

📖 **UM p371，17.6 节**：看门狗有两个时钟：
- **PCLK**：CPU 读写看门狗寄存器时用，来自系统时钟；
- **WDCLK**：倒计时用，可以选 IRC，也可以选**看门狗振荡器（WDOSC）**。

这个项目选的是 WDOSC，整条时钟链是：

```
看门狗振荡器 WDOSC          WDTOSCCTRL 分频           看门狗内部固定 ÷4
FREQSEL=2 → 1.05 MHz  ──▶  DIVSEL=9 → ÷20  ──▶  52.5 kHz  ──▶  ÷4  ──▶  13125 Hz
（UM p26 Table 14）       （2×(1+9)=20）       （WDCLK）     （UM p370 17.5） （计数器每秒减 13125 次）
```

**这就是上一课第 3 题的答案**：看门狗用自己的振荡器计时，和 CPU 的主时钟（此时是 12MHz IRC）**无关**。所以在 12MHz 下配置它没有问题，主时钟后面切到 48MHz 也不影响它。

## 三、`wwdt_config()` 逐行（`src/WWDT.c` 第 51~97 行）

### 第 58~61 行：打开时钟和电源

```c
LPC_SYSCON->SYSAHBCLKCTRL |= (1 << 15);   // ①
LPC_SYSCON->PDRUNCFG &= ~(1 << 6);        // ②
LPC_SYSCON->WDTOSCCTRL  = ((0x2) << 5) | ((20 >> 1) - 1);   // ③
LPC_SYSCON->STARTERP1 &= ~(1 << 12);      // ④
```

| 行 | 寄存器 | 📖 手册 | 作用 |
|---|---|---|---|
| ① | SYSAHBCLKCTRL bit 15 **WWDT** | p32 Table 24，复位值 0 | 打开看门狗**寄存器接口**的时钟（PCLK）。不开就读写不了看门狗寄存器 |
| ② | PDRUNCFG bit 6 **WDTOSC_PD** | p44 Table 47，复位值 1（断电） | 写 0 = 给**看门狗振荡器上电**。这是 WDCLK 的来源 |
| ③ | WDTOSCCTRL | p26 Table 14 | `(0x2 << 5)`：FREQSEL = 2 → **1.05 MHz**；`(20 >> 1) - 1` = 9：DIVSEL = 9 → 除以 2×(1+9) = **20**。结果 52.5 kHz |
| ④ | STARTERP1 bit 12 **WWDTINT** | p41 | 写 0 = 看门狗中断**不能**把芯片从深度睡眠唤醒。⚠️ 代码注释写的是 “Enable the watchdog interrupt”，和实际作用相反，注释写错了 |

📖 UM p369 的 17.2 节 “Basic configuration” 列出的正是 ①②④ 这三步，代码完全按手册的顺序来。

### 第 63~67 行：先把看门狗设成“不工作”的初始状态

```c
LPC_WWDT->MOD = 0;              // 模式寄存器全清
LPC_WWDT->TC = 0xFF;            // 计数初值设为最小值
LPC_WWDT->WARNINT = 0xFFFF;     // 警告值（实际只有低 10 位有效）
LPC_WWDT->WINDOW = 0xFFFFFF;    // 窗口设为最大 = 不启用窗口功能
```

📖 p373 Table 336 列出了全部 7 个寄存器。`WINDOW` 的复位值就是 0xFFFFFF，📖 p377 说：等于这个值时“windowing is not in effect”，也就是不启用窗口功能（窗口功能见第五节）。

### 第 69~73 行：算出计数频率（纯计算，不碰寄存器）

```c
clk = ((LPC_SYSCON->WDTOSCCTRL >> 5) & 0xF);          // 读回 FREQSEL = 2
wdt_div = LPC_SYSCON->WDTOSCCTRL & 0x1F;              // 读回 DIVSEL = 9
WDTLFORate = wdtOSCRate[clk] / ((wdt_div + 1) << 1);  // 1050000 / 20 = 52500 Hz
wdtFreq = WDTLFORate / 4;                             // 52500 / 4 = 13125 Hz
```

`wdtOSCRate[]` 是文件开头第 15~33 行的表，和 UM p26 Table 14 的 FREQSEL 频率一一对应。

### 第 76 行：选择时钟源

```c
LPC_WWDT->CLKSEL = 0x00000001;   // 📖 p376 Table 342：1 = 看门狗振荡器 WDOSC
```

### 第 80~81 行：设置超时时间和警告时间

```c
LPC_WWDT->TC = (wdtFreq / 1000) * wwdt_time;   // (13125/1000) × 65535
LPC_WWDT->WARNINT = 0;
```

**算一下超时时间**（`wwdt_time` 就是传进来的 0xFFFF = 65535）：

```
wdtFreq / 1000 = 13125 / 1000 = 13          ← 整数除法，小数 .125 被丢掉
TC = 13 × 65535 = 851955 （0xCFFF3）
超时 = 851955 ÷ 13125 次/秒 ≈ 64.9 秒
```

函数注释说“`wwdt_time` 为 1 表示 1ms”，所以 0xFFFF 本意是 65535 ms ≈ 65 秒，算出来也确实是约 65 秒。

⚠️ 但看门狗振荡器很不准。📖 **DS p30**：*“The frequency spread over processing and temperature is ±40 %.”* 所以实际超时在 **约 46 秒 ~ 108 秒**之间，因芯片和温度而异。

📖 p375 17.8.2：TC 是 24 位的，最大 0xFFFFFF；小于 0xFF 的值会被强制当成 0xFF。0xCFFF3 在范围内。

### 第 84 行：超时后复位芯片

```c
LPC_WWDT->MOD |= 1 << 1;   // 📖 p373 Table 337：bit 1 WDRESET = 1，超时就复位芯片
```

📖 p375 Table 338：WDEN = 1 且 WDRESET = 1，就是“看门狗复位模式”。

### 第 87~88 行：清除两个标志位

```c
LPC_WWDT->MOD &= (~((uint32_t)(1 << 2))) & ((uint32_t)0x1F);   // 清 bit 2 WDTOF
LPC_WWDT->MOD |= ((uint32_t)(1 << 3));                          // 清 bit 3 WDINT
```

注意这两个标志**清除的方法相反**，📖 p374 写得很清楚：
- **WDTOF**（超时标志）：*“cleared by software writing a 0 to this bit”*，写 **0** 清除；
- **WDINT**（警告中断标志）：*“cleared by software by writing a 1 to this bit”*，写 **1** 清除。

（`& 0x1F` 顺便把 bit 5 以上的保留位清零，📖 p374：保留位不应写 1。）

### 第 91~92 行：使能看门狗中断

```c
NVIC_ClearPendingIRQ(WDT_IRQn);
NVIC_EnableIRQ(WDT_IRQn);
```

从这一刻起，`WDT_IRQHandler()`（第 36 行）就有可能被执行了。这是我们逐行读代码以来**第一个被使能的中断**。向量表第 41 项（`WDT_IRQHandler`）指向 0x6AFD，不是默认死循环 0x9A2D，也和 map 第 1000 行对得上。

### 第 95~96 行：启动

```c
LPC_WWDT->MOD |= ((uint32_t)(1 << 0));   // bit 0 WDEN = 1
wwdt_feed();                             // 第一次喂狗，真正开始计时
```

📖 p375 17.8.3：*“Setting the WDEN bit in the WDMOD register is not sufficient to enable the Watchdog. A valid feed sequence must be completed after setting WDEN.”* 只置 WDEN 还不够，必须**再喂一次**，看门狗才真正开始倒计时。

📖 p369 17.3：*“Once enabled, requires a hardware reset or a Watchdog reset to be disabled.”* 一旦启动，**软件再也关不掉它**，只有复位才能让它停下。

## 四、喂狗：`wwdt_feed()`（第 43~47 行）

```c
LPC_WWDT->FEED = 0xAA;
LPC_WWDT->FEED = 0x55;
```

📖 p375 17.8.3：必须**先写 0xAA、紧接着写 0x55**，才算一次有效的喂狗，计数器重新装入 TC 的值。写了 0xAA 之后如果插入了对看门狗其他寄存器的访问，会**立刻**触发复位。要求两个特定数字连着写，是为了防止程序跑飞时乱写内存，意外喂了狗。

**整个工程里在哪些地方喂狗？**

| 位置 | 什么时候执行 |
|---|---|
| `src/device.c:515` | **主循环 `Device_Active()` 每转一圈喂一次**，主要靠它 |
| `src/device.c:926` | `Device_Check_UsbActive()` 里，USB 枚举完成时 |
| `src/WWDT.c:38` | 看门狗中断 `WDT_IRQHandler()` 里（见第五节） |
| `src/WWDT.c:96` | 启动时第一次 |

主循环每圈只要几百微秒到几毫秒，远远小于 46 秒，所以程序正常时看门狗永远不会超时。

## 五、一个设计细节：在看门狗自己的中断里喂狗，有没有问题？

`WDT_IRQHandler()` 只有一行：调用 `wwdt_feed()`。这看起来很危险。

📖 **UM p370 17.4** 专门提醒过这种情况：

> …application code could be stuck in an interrupt service that contains a watchdog feed.

意思是：如果在中断里喂狗，那么主循环卡死了，中断却还在照常运行、照常喂狗，看门狗就**永远不会复位**，等于没用。

**这个项目里不会出问题**，原因在第 81 行 `WARNINT = 0`。📖 **p376 17.8.6**：

> If WARNINT is 0, the interrupt will occur at the same time as the watchdog event.

警告中断和超时复位**同时发生**。中断还没来得及喂狗，芯片已经复位了。所以这个中断函数实际上起不了作用，看门狗依然有效。

反过来说：如果有人把 `WARNINT` 改成一个较大的值，想“提前收到警告”，这个中断里的喂狗就会让看门狗失效。**改这里时要特别小心。**

## 六、看门狗什么时候会被“关掉”

`wwdt_close()`（第 101~105 行）把看门狗振荡器断电（PDRUNCFG bit 6 写 1）。振荡器停了，倒计时也就停了。

整个工程只有一处会调用它：`src/gtech_flash.c:233` 的 `Chip_IAP_ReinvokeISP()`，也就是**跳进芯片 ROM 的 ISP 下载模式之前**。原因是看门狗一旦启动就关不掉，如果不让它停下，ISP 下载进行到一半就会被看门狗复位。（第 582 行那份同名函数在 `#if 0` 里，不生效。）

## 七、小结

| 参数 | 值 | 依据 |
|---|---|---|
| 时钟源 | 看门狗振荡器 WDOSC | CLKSEL = 1 |
| 计数频率 | 13125 Hz（标称） | 1.05 MHz ÷ 20 ÷ 4 |
| 超时时间 | 约 65 秒（实际 46~108 秒） | TC = 851955；DS p30 ±40% |
| 超时后 | 复位整个芯片 | WDRESET = 1 |
| 警告中断 | 与复位同时发生，等于不起作用 | WARNINT = 0 |
| 窗口功能 | 不启用 | WINDOW = 0xFFFFFF |
| 能否关闭 | 启动后不能，只能断振荡器电源 | UM p369 |
| 谁来喂 | 主循环每圈一次 | `device.c:515` |
