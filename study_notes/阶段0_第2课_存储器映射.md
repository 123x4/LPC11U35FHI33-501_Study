## 第 2 步 📖 UM p15，2.2 节：外设地址的规律

原文要点：
- APB 外设区大小 512KB，最多 32 个外设；AHB 外设区 2MB。
- **每个外设分配 16KB（0x4000）的地址空间。**

所以 APB 外设的基地址 = `0x4000 0000 + 编号 × 0x4000`。

## 第 3 步 📖 UM p18，Figure 6：整张地图

Figure 6 左边是整个 4GB 地址空间，右边是 APB 外设的放大图。下面从低地址往高地址走一遍，右列是**我们项目怎么用这块地方**：

| 地址范围 | 手册里的名称 | 我们项目的用法 |
|---|---|---|
| 0x0000 0000 ~ 0x0000 FFFF | 64 kB on-chip flash (LPC11U35) | 0x0000~0x3FFF：**公司 Bootloader**；0x4000~0xFFFF：**应用程序**（Keil 中 IROM1 = 0x4000 / 0xC000） |
| 　其中 0x0000 0000 ~ 0x0000 00BF | active interrupt vectors | 当前生效的**中断向量表**，0xC0 = 192 字节 = 48 个向量 × 4 字节 |
| 0x1000 0000 ~ 0x1000 1FFF | 8 kB SRAM0 | 主 RAM。应用程序用 0x1000 0100 起的 0x1E60 字节（Keil 中 IRAM1） |
| 0x1FFF 0000 ~ 0x1FFF 3FFF | 16 kB boot ROM | NXP 的 **ROM Bootloader**（上一课讲的 ISP 就在这里），还有 IAP 程序 |
| 0x2000 0000 ~ 0x2000 07FF | 2 kB SRAM1 (LPC11U35/501 …) | **没有用** |
| 0x2000 4000 ~ 0x2000 47FF | 2 kB USB RAM | USB 端点缓冲区（Keil 中 IRAM2 = 0x2000 4000 / 0x800） |
| 0x4000 0000 ~ 0x4007 FFFF | APB peripherals | 大部分外设，见第 4 步 |
| 0x4008 0000 ~ 0x4008 3FFF | USB | USB 控制器（AHB 总线） |
| 0x5000 0000 ~ 0x5000 3FFF | GPIO | GPIO（放在 AHB 上，读写比 APB 快） |
| 0xE000 0000 ~ 0xE00F FFFF | private peripheral bus | Cortex-M0 内核自己的部件：NVIC、SysTick 等（UM 第 24 章） |

> 💡 和 STM32 对比：STM32F1 的 Flash 从 0x0800 0000 开始，SRAM 从 0x2000 0000 开始。不同厂家的地址各不相同，**所以每换一颗芯片，第一件事就是看它的存储器映射图**。

## 第 5 步：寄存器地址 = 外设基地址 + 偏移

📖 翻到 **UM p31，Table 24** 的标题：

> System clock control register (**SYSAHBCLKCTRL, address 0x4004 8080**)

0x4004 8080 = SYSCON 基地址 0x4004 8000 + 偏移 0x80。项目里写 `LPC_SYSCON->SYSAHBCLKCTRL`，编译器就是按结构体成员的偏移算出这个地址的（`inc/LPC11Uxx.h:455` 的注释里也写着 `@ 0x40048080`）。和 STM32 的 `RCC->APB2ENR` 是同一个原理。

**手册里每张寄存器表的标题都写着完整地址**，以后查寄存器时可以用这个地址和头文件互相核对。

## 第 6 步：两块“小 RAM”为什么一个用、一个不用

📖 **UM p33，Table 24 的 bit 26 和 bit 27**：

| 位 | 名称 | 说明 | 复位值 |
|---|---|---|---|
| 26 | RAM1 | Enables SRAM1 block at address 0x2000 0000 | 0（关） |
| 27 | USBRAM | Enables USB SRAM block at address 0x2000 4000 | 0（关） |

这两块 RAM **上电默认是关闭的**，要先打开时钟才能用：
- USB RAM：项目在 `src/usbhw.c:129` 执行了 `LPC_SYSCON->SYSAHBCLKCTRL |= (BIT14|BIT27);`，其中 bit 14 是 USB 控制器、bit 27 是 USB RAM，所以能用；
- SRAM1：整个项目都没有打开 bit 26，Keil 里也没有配置这块 RAM，所以**没有用**。

（UM p19 的 3.1 节 “How to read this chapter” 也特别提醒了：bit 26 只有 /501 等型号才有。）

## 第 7 步：两个地图上“看不到”的东西

**① EEPROM 不在地图上**
Figure 6 里找不到 EEPROM，因为它**不能像 RAM 那样直接按地址读写**，只能调用 ROM 里的 IAP 程序来访问（📖 UM 第 20 章 p416：Write EEPROM、Read EEPROM 命令）。项目里对应 `src/IAP_CMD.c` 中的 `Chip_EEPROM_Write()` 和 `Chip_EEPROM_Read()`。

**② 地址 0 处的内容可以“换”**
📖 **UM p23，Table 7**：SYSMEMREMAP 寄存器（地址 0x4004 8000）

| MAP 值 | 含义 |
|---|---|
| 0x0 | Boot Loader Mode：中断向量映射到 Boot ROM |
| 0x1 | User RAM Mode：中断向量映射到 SRAM |
| 0x2（复位值） | User Flash Mode：中断向量就是 Flash 里的 |

这就是上一节课提到的 Bootloader 技巧：它把应用程序 0x4000 处的向量表复制到 RAM 开头（0x1000 0000），再把 MAP 设成 **0x1**。之后 CPU 去地址 0 找中断向量时，实际读到的是 RAM 里那份，于是中断就能跳进应用程序。

这也解释了为什么**应用程序的 RAM 从 0x1000 0100 开始**：前 0x100（256）字节要留给这张向量表，表本身只需要 0xC0（192）字节（第 3 步表格中的 active interrupt vectors）。

## 小结：一张图记住

```
0xE000 0000  内核外设（NVIC、SysTick）
0x5000 0000  GPIO
0x4008 0000  USB
0x4000 0000  APB 外设（每个 16KB）：I2C、WWDT、定时器、ADC、SSP、IOCON、SYSCON……
0x2000 4000  USB RAM 2KB    ← 端点缓冲区（bit27 打开）
0x2000 0000  SRAM1 2KB      ← 没用
0x1FFF 0000  Boot ROM 16KB  ← NXP 的 ISP / IAP
0x1000 0000  SRAM0 8KB      ← 0x000~0x0FF 给向量表副本，0x100 起给应用程序
0x0000 4000  应用程序
0x0000 0000  公司 Bootloader
（EEPROM 4KB 不在地图上，通过 IAP 访问）
```
