# 第 1 课：按键链路——从 ADC 采样值到“按下”

> 目标：搞清楚左右键从“传感器读数”变成“按下/松开”的每一步，并用 PC 仿真亲眼看到算法的行为。
> 以当前板型 `IRPT_V4`（光电 + ADC）为例。Hall 板只是第 1 步取数方式不同，后面的算法完全相同。

---

## 1. 全景：谁调用谁

```
TIMER16_0_IRQHandler()            src/Timer.c:65    每 1ms 中断一次，把 one_ms_cycle 减到 0
        ↓（只置标志，不干活）
Device_Active() 主循环             src/device.c:493
 └ Device_Scan()                   src/device.c:875   发现 one_ms_cycle==0 → 重置为 1，执行一次扫描
    └ Device_Button_Scan()         src/device.c:949
       └ Button_Scan()             app/button.c:592   ④ 比较新旧状态 → 触发振动
          └ Button_GetState()      app/button.c:551  普通 GPIO 键 + 左右键合成一个 32 位状态字
             └ LR_GetState()       app/button.c:298   ① 读 ADC
                └ ProcessRecvSampleRawData()  src/my_misc.c:418   ② 滤波、基线  ③ 分段、AP/RT
```

STM32 类比：相当于 SysTick 中断里只做 `flag = 1`，`while(1)` 里检查 flag 再调用 `Key_Scan()`。这样中断里不做耗时操作。

1ms 是怎么得到的：`TIME_CT16B0_PR = 47`、`TIME_CT16B0_COUNT = 999`（`inc/Timer.h:17`），48MHz ÷ 48 = 1MHz，计 1000 个数就是 1ms。

## 2. 第①步：取原始值 `LR_GetState()`（`app/button.c:298`）

```c
ret  = MyADC_GetValue(pLeftAdcHandle,  &leftVal);   // AD2 = PIO0_13
ret |= MyADC_GetValue(pRightAdcHandle, &rightVal);  // AD3 = PIO0_14
if (ret) return result;                             // 任一路读失败，本次按“全部松开”处理

hall_spi_rx[0] = rightVal >> 8;  hall_spi_rx[1] = rightVal;   // 右键在前
hall_spi_rx[2] = leftVal  >> 8;  hall_spi_rx[3] = leftVal;    // 左键在后
result = ProcessRecvSampleRawData(hall_spi_rx, 4);
```

要点：
- **为什么把 ADC 值塞进 `hall_spi_rx`？** 为了让后面的算法和 Hall 板共用。Hall 菊花链 SPI 读出来就是“右键 2 字节 + 左键 2 字节”，这里故意凑成同样的格式。
- **ADC 读取**（`src/my_adc.c` `MyADC_GetValue`）：选通道 → 启动 → 每 2µs 查一次 DONE 位（bit31），最多查 10 次 → 取 `DR[ch]` 的 bit[15:6]（10 位，0~1023）。ADC 时钟 3MHz，一次转换 11 个时钟，约 3.7µs。
- **ADC 读失败**时这里返回 0，也就是左右键都算“松开”。如果按住的时候偶尔读失败一次，会不会产生一次误松开？答案见第 4 步末尾。

---

## 3. 第②③步：算法核心 `ProcessRecvSampleRawData()`（`src/my_misc.c:418`）

整个函数分成两个阶段：**上电校准阶段** 和 **正常工作阶段**。

### 3.1 先统一方向：让“按下 = 数值变大”

```c
temp[k] = MAX_VALUE_10BIT - temp[k];   // 1023 - adc
```
IRPT_V4 板按下时 ADC 变小（`PRESS_KEY_AND_VALUE_INCREASE = 0`，`inc/my_misc.h`），所以先反转。之后的算法都假设**按得越深，数值越大**。
例：松开 ADC≈820 → 反转后≈203；按到底 ADC≈320 → 反转后≈703。

> 数组下标约定：**`k = 0` 是右键，`k = 1` 是左键。** 后面看到 `[1]` 就是左键。

### 3.2 两条基线

| 名称 | 含义 | 变量 |
|---|---|---|
| top 基线 | 完全松开时的值（≈203） | `gwTopBaseline[k]` |
| bottom 基线 | 按到底时的值（≈703） | `gwBottomBaseline[k]` |

后续一切都是“当前值在 top 和 bottom 之间的哪个位置”。

### 3.3 上电校准阶段（`cali_init_cnt` 从 600 开始倒数）
`Hall_InitBaseline()`（`my_misc.c:135`）：
- 新值和 top 基线相差超过 ±`MAGNETIC_NOISE`（IRPT 为 20）→ top 直接改成新值，计数清零；
- 在 ±20 范围内 → top = (top + 新值) / 2，计数 +1，连续 100 次（100ms）稳定后校准结束；
- 校准期间 **bottom = top**（这一点后面很关键）。

所以**上电的前约 100ms 内不能碰按键**，否则 top 基线会定在按下的位置。

### 3.4 正常工作阶段，每个键依次处理：

**(a) 振动期间冻结**
```c
if (Ele_IsVibrating(ELE_POS_LEFT) && k == 1) { gbKeyState[1] = previousKeySta[1]; continue; }
```
线圈通电会让传感器读数跳变，所以振动期间（包括之后 8ms 的消抖期）直接沿用旧状态，本次采样**扔掉不用**。

**(b) 滤波：一阶低通 + 大跳变直通**
```c
if (|temp - avg| > FILTER_SKIP_VALUE(10)) { avg = temp; sum = temp << 4; }  // 变化大：直接跟上
else { sum += temp - avg; avg = sum >> 4; temp = avg; }                     // 变化小：平滑
```
相当于 `avg = avg + (新值 - avg) / 16`，是指数平均，不是真正的“滑动窗口”。设计思路是：手指快速运动时数据变化大，直接用原始值，不引入延迟；手指不动时只剩噪声，就平滑掉。

**(c) 分段 `Hall_CalculateNode()`（`my_misc.c:288`）**
```
       当前值 - top
tmp = ─────────────── × 255      → 再查表 nodeCaliTable[tmp] → 0~100 段
       bottom - top
```
- 用 `step = 2^21 / (bottom-top)` 的定点数写法代替浮点除法（Cortex-M0 没有硬件除法器，也没有 FPU）。
- **保护条件：`bottom - top < 100` 时一律返回 0 段。** 结合 3.3 节“校准结束时 bottom = top”，这意味着**上电后第一次按键时，段数会一直是 0，直到 bottom 基线学习到比 top 大 100 以上**。

**(d) AP/RT 判定 `Hall_HandleKeyRapidTrigger()`（`my_misc.c:330`）**

用一个变量 `current_node_update` 记录“极值点”：

```
当前是 松开 状态：
    记录最低点 low（段数变小就更新）
    if 段数 ≥ 100                          → 按下（按到底，无条件触发）
    if 段数 ≥ low + RT按下  且  段数 ≥ AP   → 按下

当前是 按下 状态：
    记录最高点 high（段数变大就更新）
    if 段数 == 0                           → 松开（回到顶，无条件松开）
    if high - 段数 > RT松开                → 松开
```
这就是 Rapid Trigger：不在固定位置触发，而是**相对上一次的极值点再移动 N 段就切换**。所以手指在半路来回抖动也能连续点击。

**(e) 基线跟踪**
- `Hall_CalibrateTopBaseline`：只在**松开**时工作，慢慢跟随温漂（往下修得快，往上修得慢）。
- `Hall_CalibrateBottomBaseline`：只在**刚按下的前 100ms 内**工作，而且**只会往上涨，不会往下降**。

**(f) 输出**
```c
if (gbKeyState[0]) ret |= 0x02;   // 右键 → bit1
if (gbKeyState[1]) ret |= 0x01;   // 左键 → bit0
```
注意：数组是“0 右 1 左”，输出 bit 是“bit0 左 bit1 右”，正好反过来。

## 4. 第④步：状态变化 → 振动 `Button_Scan()`（`app/button.c:592`）

```c
for (i = 0; i <= 1; i++) {          // 0 = 左, 1 = 右（这里又是按 bit 序号）
    if (新状态 != 旧状态) {
        if (按下) Ele_LeftKeyPressProcess();   / Ele_RightKeyPressProcess();
        else      Ele_LeftKeyReleaseProcess(); / Ele_RightKeyReleaseProcess();
        button_changed = TRUE;
    }
}
```
- 左右键**没有消抖计数**（中键、侧键有 5ms/8ms 的消抖），因为模拟量已经有滤波和 RT 的回差，不需要再消抖，这样延迟最低。
- 振动是在**判定的同一个 1ms 周期内立即触发**的，比 USB 上报还早。
- `button_changed` 为真时，`Device_Button_Scan` 发出 `BUTTON_EVENT` → `Device_Pack()` 组装报文 → `Device_Report()` 写入 USB 端点 1。

关于第 2 节留的问题：ADC 读失败时 `LR_GetState` 返回 0，但**没有调用** `ProcessRecvSampleRawData`，`gbKeyState` 保持不变。不过 `Button_Scan` 拿到的左右键 bit 是 0，所以**会产生一次误松开**，并且同时触发一次松开振动；下一毫秒读成功后又会触发一次按下和按下振动。实际中 ADC 很少读失败，但这里存在隐患，值得记下来。**【待确认：可以改成读失败时返回上一次的状态】**

## 5. 动手实验：PC 仿真

`study_notes/sim/` 目录里直接编译了**仓库原版的 `src/my_misc.c`**（只用替身头文件把芯片相关部分换掉），然后每 1ms 喂一个模拟的 ADC 值。

```sh
cd study_notes/sim
sh build.sh              # 需要 gcc（Windows 可用 WSL 或 MSYS2）
./key_sim                # 默认参数 AP=10 RT按下=30 RT松开=20
./key_sim 50 5 5         # 换参数：AP=50 RT按下=5 RT松开=5
./key_sim 10 30 20 0     # 第 4 个参数为 0 时关闭“振动冻结”
```

模拟的手指动作：上电不碰 → 第 1 次完整按下松开 → 第 2 次按下 → 只抬起 40% → 再压下 35% → 完全松开。

### 默认参数的实验结果（节选）

```
 时间ms 深度%  ADC  反转滤波后 top基线 bottom基线 段数 状态
    468  100   317     704      201      322    100  按下 <<< 第1次：手按到底 18ms 后才判定
    627   46   588     435      201      502     78  松开 >>> 第1次松开：深度还有 46% 就判定松开
    809   18   729     294      203      502     30  按下 <<< 第2次：段数到 30 就判定（不是 AP=10！）
    917   66   492     531      203      622     79  松开 >>> 只抬起 40%，RT 生效
    974   84   399     624      203      622    100  按下 <<< 半路再压下，RT 生效
   1064   68   479     544      203      642     78  松开
```

### 从实验中得到的 4 个发现

1. **上电后第一次按键有延迟**：t=400 开始按，t=450 已经按到底，但 t=468 才判定按下。原因是 3.3 节和 3.4(c) 节：校准结束时 bottom = top，`bottom - top < 100` 时段数恒为 0，要等 bottom 每 30ms 涨 60，涨两次之后才有段数。
2. **bottom 基线需要按好几次才能学准**：真实按到底的值约 703，但 6 次按键后 bottom 才学到 642。在此之前段数和物理深度对不上（深度 46% 时显示 78 段）。原因是 bottom 只在每次按下的前 100ms 内往上涨。这也是 GUI 上 `baselineBtm` 的含义。
3. **AP 只有在大于 RT按下 时才起作用**：默认参数 AP=10、RT按下=30，从顶部开始按，到 30 段才触发。对比实验：

   | AP / RT按下 / RT松开 | 第 2 次按下的触发段数 | 物理深度 |
   |---|---|---|
   | 10 / 30 / 20 | 30 | 18% |
   | 10 / 5 / 5 | 13（≥AP 且 ≥0+5） | 8% |
   | 50 / 5 / 5 | 53 | 32% |

   因为代码要求“段数 ≥ low + RT按下 **并且** ≥ AP”，而从顶部开始时 low=0。**【待确认：这是设计意图吗？一般 RT 产品里“首次触发看 AP，之后再看 RT”。】**
4. **RT 确实生效**：t=917 只抬起了 40% 就判定松开，t=974 再压下就重新判定按下，不需要回到顶部。
