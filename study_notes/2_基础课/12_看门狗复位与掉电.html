看门狗、复位、掉电：程序卡死了怎么办

再小心的程序也可能卡住：比如死循环、跑飞、电压突然掉下去。这一课讲芯片的三道“保险”：看门狗（程序太久没报平安就重启）、复位（重启有哪几种原因、怎么查）、掉电检测 BOD（电压太低就先别跑）。照例先讲场景，再讲代码，手册放最后。

1/9看门狗：一个要你定时“报平安”的倒计时

看门狗是芯片里的一个倒计时器。程序要时不时去把它拨回满格（叫“喂狗”）。只要程序正常跑，倒计时永远到不了 0；一旦程序卡死、没人喂，倒计时归零，芯片就自己重启。

动手 · 看门狗模拟器（时间加快了 20 倍）
看门狗（WWDT）：Windowed Watchdog Timer，带“窗口”功能的看门狗定时器。
喂狗（feed）：往 FEED 寄存器先写 0xAA、再写 0x55，倒计时就重新装满。
复位：芯片从头开始跑，相当于重启；RAM 里的变量要重新初始化。

这个项目的设置（下一节算给你看）：倒计时约 65 秒，主循环每转一圈喂一次（device.c:515）。主循环一圈只要几毫秒，所以正常情况下离 0 远得很。

3/9看门狗的倒计时是怎么算出 65 秒的

原始代码（WWDT.c:51~97，wwdt_config()）里决定时间的几行：

		LPC_SYSCON->WDTOSCCTRL  = ((0x2) << 5) | ((20 >> 1) - 1);// Uses the watchdog oscillator set at a 50KHz (1Mhz / 20) clock rate.
		...
		clk = ((LPC_SYSCON->WDTOSCCTRL >> 5) & 0xF);	// Get WDT oscillator settings
		wdt_div = LPC_SYSCON->WDTOSCCTRL & 0x1F;
		WDTLFORate = wdtOSCRate[clk] / ((wdt_div + 1) << 1);	// Compute clock rate and divided by divde value
		wdtFreq = WDTLFORate / 4;
		...
		LPC_WWDT->TC = (wdtFreq / 1000) * wwdt_time;

4/9掉电检测 BOD：电压太低就按住复位

电压掉得太低时，芯片可能还在跑，但读错 Flash、算错数，比直接停下来更危险。BOD（Brown-Out Detect，掉电检测）就是一个电压比较器：电压低于门限，就把芯片按在复位状态；电压回升到另一个门限以上，才放开。

动手 · 拖动电源电压

原始代码（device.c:479~481，在 Device_Init() 后段）：

  LPC_SYSCON->BODCTRL = (3 << 0)   /* BODRSTLEV = Level 3 (2.63V assert / 2.71V release) */
                      | (0 << 2)   /* BODINTVAL = 0 (interrupt disabled) */
                      | (1 << 4);  /* BODRSTENA = 1 (enable brown-out reset) */
回差：往下掉要到 2.63 V 才复位，往上回要到 2.71 V 才放开。两个门限不一样，是为了电压在门限附近抖动时不会反复复位。

7/9📖 手册导读（只给名字，先自己找）

任务 1：第 17 章开头找 Basic configuration 和 Applications。Applications 最后一段举了一个例子，说什么样的写法会让看门狗失效？
答案17.2、17.4，p.369~370。基本配置 3 条：开 SYSAHBCLKCTRL bit15、在 PDRUNCFG 打开时钟源、要唤醒的话开 STARTERP1。
17.4 原文：“application code could be stuck in an interrupt service that contains a watchdog feed.” 如果在某个中断里喂狗，程序卡在那个中断里时还会一直喂，看门狗就救不了。用“窗口”功能可以防止这种情况。
任务 2：找 Watchdog mode register（MOD）。哪几位一旦写 1 就再也改不回 0？WDTOF 和 WDINT 分别怎么清？
答案Table 337，p.373~374。WDEN、WDRESET、WDPROTECT、LOCK 写 1 后软件改不回来，只有复位能清。所以 wwdt_config() 开头的 MOD = 0（WWDT.c:64）在看门狗已经开过以后没有作用。
表下面原文：WDTOF “is cleared by software writing a 0”；WDINT “is cleared by software by writing a 1”。
任务 3：找 Watchdog Feed register。喂狗写到一半（写了 0xAA 还没写 0x55）时去碰别的看门狗寄存器，会怎样？
答案Table 340 上面那段，p.375：“access to any Watchdog register other than writing 0x55 to WDFEED causes an immediate reset”。立刻复位。手册建议喂狗的两句之间关中断，防止中断里也去碰看门狗。这个项目只有看门狗自己的中断会碰它（第 8 节），影响不大。
任务 4：找 Watchdog Timer Warning Interrupt register。WARNINT = 0 时，警告中断什么时候来？
答案17.8.6，Table 343，p.376~377。原文：“If WARNINT is 0, the interrupt will occur at the same time as the watchdog event.” 警告和复位同时发生，中断函数里来不及喂。所以 WDT_IRQHandler() 里的喂狗实际上没起作用。
任务 5：第 3 章找 WDTOSCCTRL，自己验算第 3 节的 52.5 kHz。再找它前面那段 Remark，看看这个振荡器有多不准。
答案Table 14，p.26。FREQSEL = 2 → 1.05 MHz；DIVSEL = 9 → 除以 2 × (1 + 9) = 20 → 52.5 kHz。Remark（p.26）：任何 FREQSEL 设置的频率都可能偏差 40%。
任务 6：第 3 章找 SYSRSTSTAT 和 BODCTRL。项目设的 BOD Level 3 是多少伏？
答案Table 16，p.27：bit0 POR 上电、bit1 EXTRST 复位脚、bit2 WDT 看门狗、bit3 BOD 掉电、bit4 SYSRST 软件复位，都是写 1 清。
Table 36，p.37：BODRSTLEV = 3 → 低于 2.63 V 复位，高于 2.71 V 放开。BODRSTENA = 1 打开复位功能（复位后默认是 0，不打开）。
任务 7（了解）：找 Watchdog timing examples（17.9）看几张时序图。
答案17.9，p.377 起。画的是“提前喂（窗口外）→ 复位”“按时喂 → 继续”“警告中断 → 超时复位”几种情况。这个项目没开窗口（WINDOW 保持复位值 0xFF FFFF），所以任何时候喂都算数。

8/9容易出错、你能改什么、T1A

看门狗中断里喂狗，没起作用 ⚠️WDT_IRQHandler() 调 wwdt_feed()（WWDT.c:36~39）。WARNINT = 0，中断和复位同时到，来不及。不会造成危害，但会误导人以为“中断会自动续命”。如果把 WARNINT 改大，它反而有害：程序卡死了中断还在喂，看门狗就永远不复位了（手册 17.4 说的就是这个）。
挂起后 BOD 没有重新打开 ⚠️挂起时 wnDrv_Pmu_Init()（wnDrv_Pmu.c:61）和 clockinit()（usbhw.c:644）把 BOD 断电（PDRUNCFG bit3 = 1），醒来时没有任何代码把它打开。所以电脑睡过一次以后，掉电复位就失效了，直到下次重新插线。要不要修，问杰哥。
倒计时 65 秒偏长程序卡死后，鼠标要将近一分钟才会自己恢复。可以改小，但要先算清楚最慢的一圈主循环：开机 TimerDelayMsec(500)、PAW3950 初始化、写 EEPROM 等，都不能超过倒计时。和杰哥商量再改。
复位原因没人记我们的程序没读 SYSRSTSTAT，wwdt_config() 还把 WDTOF 清了。所以鼠标“自己重启过”是查不出来的。调试时可以在开机时读一下 SYSRSTSTAT 打印出来（只读，安全）。
bootloader 的 |= 会顺手清掉别的位SYSRSTSTAT |= 1<<4：读出来再写回，其他为 1 的位也被写 1 = 一起清掉。和第 10 课 DEVCMDSTAT 是同一个坑。
注释和实际相反WWDT.c:61 STARTERP1 &= ~(1 << 12) 注释写“Enable”，实际是关掉看门狗唤醒（Table 44：1 才是打开）。睡眠时看门狗振荡器本来也关了，所以没影响。

你能改什么

  • 倒计时长度：改 wwdt_config(0xFFFF) 的参数（单位约 1 ms）。device.c:419 和 usbhw.c:707 两处要一起改。
  • BOD 门限：BODCTRL 的 BODRSTLEV（device.c:479）。要和硬件同事确认板子的供电电压。
  • 开机打印复位原因：调试时有用，只读寄存器，不会变砖。

T1A 上

看门狗、复位、BOD 都在芯片内部，换板子不用改。要注意两点：T1A 加了充电芯片 BQ21128 和电池，供电路径变了，BOD 门限是否合适要问硬件同事；T1A 的 RESET 脚同时接了 PAW3950 的复位（引脚总表 2 号脚），按复位键时传感器也会一起复位。

小测验

这一课你只需要记住：看门狗是一个要定时喂的倒计时，这个项目约 65 秒，主循环每圈喂一次，卡死就自动重启。芯片有 5 种复位原因（上电、复位脚、看门狗、掉电、软件），都记在 SYSRSTSTAT 里，写 1 清。BOD 在电压低于 2.63 V 时把芯片按住不跑。进入升级用的是软件复位 NVIC_SystemReset()。
