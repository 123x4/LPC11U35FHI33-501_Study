SPI 与光学传感器 PAW3950

鼠标移动多少，是 PAW3950 算出来的；单片机通过 SPI 这条“4 根线的电话”去问它。这一课先讲 SPI 怎么一位一位地传数据，再讲 PAW3950 的“说话规矩”，最后把开机初始化和每次读位移的全过程走一遍。要读两本手册：芯片用户手册第 13 章、PAW3950 数据手册第 6、7 章。

1/8SPI：4 根线、一边说一边听

线方向作用IRPT_V4 引脚
SCLK（时钟）单片机 → 传感器打拍子：每一拍传 1 位。只有主机（单片机）能发时钟，所以传感器永远是被动回答PIO1_15
MOSI单片机 → 传感器Master Out Slave In：单片机说的话PIO0_21
MISO传感器 → 单片机Master In Slave Out：传感器说的话PIO0_22
NCS（片选）单片机 → 传感器拉低 = “我在跟你说话”。线上可以挂好几个设备，靠片选区分PIO0_20（普通 GPIO）
同步：双方按同一个时钟收发，不需要事先约定速度（不像串口）。
主机 / 从机：发时钟的是主机（单片机），被动的是从机（传感器）。

SPI 最特别的地方：两边各有一个 8 位的“移位寄存器”，首尾接成一个圈。每打一拍时钟，单片机移出一位给传感器，同时传感器也移出一位给单片机。8 拍以后，两边的字节正好互换。所以“发”和“收”永远同时发生：想收一个字节，就必须发一个字节（哪怕是没用的 0xFF）。

动手 · 点“下一拍”，看两个字节怎么互换（读 Motion 寄存器 0x02）
📖 用户手册 p.275 · 13.4 General description（请翻过去读这一段）
Data transfers are in principle full duplex, with frames of 4 bits to 16 bits of data flowing from the master to the slave and from the slave to the master. In practice it is often the case that only one of these data flows carries meaningful data.
原理上双向同时传；实际上往往只有一个方向的数据有用。上面的例子里，第 1 个字节只有单片机说的有用，第 2 个字节只有传感器说的有用。

2/8SPI 的 4 种“说话方式”：CPOL 和 CPHA

双方还要约定两件事：没说话时时钟线停在高还是低（CPOL），在第几个边沿读数据（CPHA）。约定不一致，读到的全是错的。

动手 · 切换 CPOL / CPHA

PAW3950 手册规定用模式 3（CPOL = 1、CPHA = 1）：时钟平时是高；数据在下降沿变化、在上升沿被读取（PAW p.27 第 6.0 节、p.28 第 6.3 节）。代码 LPC_SSP1->CR0 = 0x01C7 里 CPOL、CPHA 两位都是 1，正好对上。

3/8PAW3950 的说话规矩

和传感器的每一次对话都是 2 个字节：第 1 个字节 = 读还是写（最高位）+ 寄存器地址（低 7 位），第 2 个字节 = 数据。

时间要求（PAW p.13 AC 表）手册要求代码实际

读：发完地址到开始读数据 tSRAD≥ 1 µs等 3 µs（PAW3950_DelayUs(3)）

这个项目把每个间隔都留得比要求宽，所以很稳，代价是慢一点。读一次位移（5 次读）大约 100 µs。

4/8SPI 和 PAW3950 的一生：生命周期图

一句话来龙去脉
Device_Init() 最后调 PAW3950_Init()：先把 SSP1 设成 8 位、模式 3、1 MHz，再按 PAW3950 手册 7.1 的开机流程：等 50 ms → 拉一下片选复位 SPI → 软件复位 → 读产品 ID（应为 0x53）→ 写入厂家给的一百多条初始化设置 → 清掉位移寄存器 → 设 1600 CPI。之后主循环每隔一段时间（定时器中断倒数 optical_scan_cycle）读一次 0x02，有移动就再读 0x03~0x06 拿到 X、Y，交给组包。每次读写一个寄存器：拉低 NCS → 发地址 → 等 3 µs → 收数据 → 拉高 NCS。

问题 1：13.2 第 4 条为什么特别强调 Reset？原文：“Before accessing the SSP/SPI block, ensure that the SSP0/1_RST_N bits … in the PRESETCTRL register are set to 1.” SSP 开机处于复位状态，不先解除，后面写的设置都无效。这是用 SPI 最容易忘的一步（第 3 课）。
问题 2：FIFO 是什么？8 帧 FIFO 对这个项目有什么影响？FIFO 是先进先出的小队列：可以一次往 DR 写好几个字节，硬件按顺序发；收到的字节也先排队，等你来读。这个项目每次只发一个字节就等它发完，没有用到队列的能力。但正因为有接收队列，发送时顺带收到的字节如果不读掉，会一直排在队列里，下次读到的就是旧的（所以 SSP_Send() 发完要读一次 DR 丢掉）。
📖 p.278 · Table 260 CR0：DSS、FRF、CPOL、CPHA、SCR。精读。
📖 p.279 · Table 261 CR1：LBM、SSE（启动）、MS（主/从）。
📖 p.279 · Table 262 DR、p.280 · Table 263 SR、p.280 · Table 264 CPSR
问题 3：把 0x01C7 按 Table 260 拆开0x01C7 = 0000 0001 1100 0111：DSS（3:0）= 0111 → 8 位一帧；FRF（5:4）= 00 → SPI；CPOL（6）= 1；CPHA（7）= 1；SCR（15:8）= 1。
问题 4：SPI 时钟频率怎么算？这个项目是多少？Table 260 SCR 说明里有公式：PCLK / (CPSDVSR × [SCR+1])。PCLK = 48 MHz ÷ SSP1CLKDIV(1) = 48 MHz；CPSDVSR = 0x18 = 24；SCR = 1。48 / (24 × 2) = 1 MHz。
问题 5：CR1 里 MS 位没设，这个项目是主机还是从机？MS 复位值 0 = 主机（Master）。没写就是主机，正好。
问题 6：SR 的 BSY、TNF、RNE 分别是什么？例程等的是什么条件？TNF = 发送队列没满（能往里写）；RNE = 接收队列不空（有东西可读）；BSY = 正在收发。SSP_Send() 先等“没满且不忙”再写，然后等“不忙且收到了”再读掉。
📖 p.283~287 · 13.7.2 SPI frame format、Figure 33~36：4 种模式的波形图。重点看 p.287 Figure 36（CPOL = 1、CPHA = 1），和上面第 2 节的模拟器对照。

问题 7：6.2 为什么说“不用的时候不要一直拉低 NCS”？原文：“The port must not be remained enabled when not in use to prevent misinterpret ESD and EFT/B events and put the chip into an unknown state.” 片选一直低着，线上的干扰（静电、电快速脉冲）可能被当成命令。所以代码每次读写完都把 NCS 拉高。
问题 8：读寄存器 0x02 时，第一个字节发什么？写寄存器 0x48 呢？读：最高位 0 → 0x02（代码 regAddr & ~(1<<7)）。写：最高位 1 → 0x48 | 0x80 = 0xC8（代码 regAddr | (1<<7)）。
问题 9：对照 7.1 的 8 步，PAW3950_Init() 每一步在哪？1 上电（硬件）；2 等 50 ms（:329）；3 NCS 高 1 ms 再拉低（:331~333）；4 写 0x3A = 0x5A（:341）；5 等 5 ms（:342）；6 读 Product_ID（:346~354）；7 写初始化设置（:357~389）；8 读 0x02~0x06（:391~395）。代码完全按手册的顺序写的。
问题 10：Product_ID 应该是多少？为什么要先读它？p.62：默认值 0x53。它是固定不变的，读到 0x53 就说明 SPI 线接对了、模式对了、传感器活着。7.1 第 6 步要求“任何读写之前先读它验证”。
问题 11：6.6 Burst Read 是什么？这个项目用了吗？一次片选连续读出多个位移寄存器，不用每个都发地址，更快。这个项目没用，是一个个单独读的（PAW3950_GetMotionDataSingleRead）。以后要提高回报率可以考虑改成 burst。

8/8容易出错、你能改什么、T1A

CPOL / CPHA 和传感器不一致读到的全是错位的数据。先读 Product_ID 验证。
忘了 PRESETCTRL 解锁SSP 不工作，读出来全是 0 或卡在等待里。
接收队列里有残留读到的是上一个字节。发送后要把收到的读掉（例程已经做了）。
NCS 一直拉低容易被干扰。每次对话都要用 NCS 框起来。
间隔太短违反 tSRAD、tSRR，读到错误数据。
初始化失败没人管 ⚠️PAW3950_Init() 读不到 0x53 会返回 -1，但 Device_Init()（device.c:484）没检查返回值。传感器坏了或没接好，鼠标照样启动，只是光标不动。
PAW3950_Read() 的小隐患 ⚠️参数 length 大于 1 时，每次都写进同一个 pData（应该是 pData + i）。现在所有调用都是 length = 1，所以没出问题；以后改成一次读多个就会出错。

你能改什么

  • 改 CPI（灵敏度）：PAW3950_SetCPI(1600)（PAW3950.c:398）。全仓库只有这一处调用，所以现在 DPI 键不会改传感器的 CPI。
  • 提速：SCLK 最高可到 16 MHz；把 CPSR 从 24 改小即可（必须是偶数）。间隔延时也可以按手册最小值缩短。
  • 改用 Burst Read：一次读出 Motion 和 X、Y，减少片选次数。

T1A 上

T1A 上 PAW3950 改接 SSP0（MISO = PIO0_8、MOSI = PIO0_9、SCLK = PIO0_10），SSP1 改给两颗霍尔芯片用（03_T1A适配清单.md）。要改：③ 解锁位改成 bit0、② 时钟改成 bit11 和 SSP0CLKDIV、④ 三根脚的 FUNC、所有 SSP_Send(1, …) 改成 0。
⚠️ PIO0_10 同时是 SWD 调试的 SWCLK：改成 SCK0 之后，调试器就连不上了。这件事要和杰哥确认怎么调试。

小测验

这一课你只需要记住：SPI = 时钟 + 两根数据线 + 片选，主机打拍子，每拍双方各交换一位，8 拍换一个字节，所以收一个字节必须发一个字节。双方要约定 CPOL/CPHA（PAW3950 用模式 3）。PAW3950 每次对话 2 字节：最高位 1 写、0 读，加 7 位地址，然后数据。用 SSP 要记得 PRESETCTRL 解锁。
