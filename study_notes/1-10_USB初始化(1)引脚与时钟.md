## 一、`nsAPI_USB_Init()` 全貌（`src/usbhw.c:285~328`）

```c
void nsAPI_USB_Init (void)
{
	g_USBCore_Setting.EP0_SetReq=0;        // ① 清几个状态变量
	g_USBCore_Setting.EP0_GetReq=0;
	g_USBCore_Setting.EP0_DosMode=0;

	NVIC_DisableIRQ(USB_IRQn);             // ② 先关 USB 中断（第 301 行）
	NDrv_USB_IOClkConfig();                // ③ 时钟和引脚（第 303 行）  ← 本课重点

#if LPM_SUPPORT          …  #endif         // ④ 三段 #if，全部不执行
#if USB_FIQ_EVENT        …  #endif
#if USE_DOUBLE_BUFFER    …  #endif

	NVIC_EnableIRQ(USB_IRQn);              // ⑤ 打开 USB 中断（第 323 行）
	NDrv_USB_Reset();                      // ⑥ 1-11 课
	NDrv_USB_Connect(TRUE);                // ⑦ 1-12 课
}
```

### ① 清状态变量

`g_USBCore_Setting` 在 `usbcore.o` 的 `.bss` 里（`List/Sample.map` 第 10 行等处可以看到 `refers to usbcore.o(.bss) for g_USBCore_Setting`）。0-4 课讲过，`.bss` 在进 `main()` 之前已经被 `__scatterload` 清零了，所以这三行在第一次上电时是**多余的保险写法**。

### ② 关 USB 中断

1-1 课“三道门”里的 NVIC 那道门：配置过程中不让 USB 中断进来。1-9 课已经把它的优先级设成了 1。

### ④ 三段 `#if`，全部不执行

`inc/usbcfg.h`：

| 宏 | 值 | 如果打开会做什么 |
|---|---|---|
| `LPM_SUPPORT`（第 77 行） | 0 | Link Power Management，USB 2.0 的一种更细的省电模式 |
| `USB_FIQ_EVENT`（第 116 行） | 0 | 把 SOF（每 1 ms 一个的帧开始信号）改走 USB_FIQ 中断，并打开 USB_FIQ |
| `USE_DOUBLE_BUFFER`（第 76 行） | 0 | 端点双缓冲 |

> ⚠️ **更正 1-9 课**：1-9 课的优先级表里写了 “USB_FIQ 在 1-10 课（`usbhw.c:316`）使能”。实际上 `usbhw.c:316` 在 `#if USB_FIQ_EVENT` 里，`USB_FIQ_EVENT = 0`，**USB_FIQ 中断没有被打开**，`USB_FIQHandler` 不会执行。1-9 讲义已同步更正。

### ⑤ 打开 USB 中断

这时 USB 控制器自己的中断使能寄存器（INTEN）还是 0（复位值），所以虽然 NVIC 开了，**USB 中断还不会来**——要等 1-11 课 `NDrv_USB_Reset()` 设置 INTEN 之后。又是“三道门”：

```
外设 INTEN    = 0   ✗（1-11 课才打开）
NVIC bit22    = 1   ✓（本行）
PRIMASK       = 允许 ✓
```

## 二、`NDrv_USB_IOClkConfig()` 逐行（`src/usbhw.c:123~143`）

📖 **UM p221，11.2 Basic configuration** 列出了 USB 要配置的东西，对照着看：

```
• Pins: Configure the USB pins in the IOCON register block.                  ← 第 134~138 行
• In the SYSAHBCLKCTRL register, enable the clock to the USB controller
  register interface by setting bit 14 and to the USB RAM by setting bit 27   ← 第 129 行
• Power: Enable the power to the USB PHY and to the USB PLL                   ← 1-5 课已做
• Configure the USB main clock                                                ← 1-5 课已做
• Configure the USB wake-up signal if needed                                  ← #if POWERDOWN_MODE_USB_WAKEUP，不执行
```

### 第 126 行：GPIO 时钟

```c
LPC_SYSCON->SYSAHBCLKCTRL |= BIT6;
```

1-3 课已经开过了（而且 boot 之后本来就是 1），这里是第三次写，保险写法。

### 第 129 行：USB 寄存器和 USB RAM 的时钟

```c
LPC_SYSCON->SYSAHBCLKCTRL |= (BIT14|BIT27);
```

📖 **UM p31~32 Table 24**：

| 位 | 名字 | 作用 |
|---|---|---|
| 14 | USB | USB 控制器**寄存器接口**的时钟（1-5 课 Q2 说的“房间的门”） |
| 27 | USBRAM | **USB RAM**（0x2000 4000，2 KB）的时钟 |

1-5 课勘误里讲过，boot 之后这两位**已经是 1**（SYSAHBCLKCTRL = 0x0800485F）。这里再写一次也是保险。

**USB RAM 是干什么的？** 📖 UM p222 Figure 20：USB 控制器内部有一个 DMA 引擎，**直接**从内存里取要发的数据、把收到的数据写进内存，不经过 CPU。本项目把所有端点的收发缓冲区和端点列表都放在这块 2 KB 的 USB RAM 里。具体怎么分配、为什么放这里，1-11 课讲。

### 第 134~135 行：PIO0_3 设为 USB_VBUS，并接下拉

```c
LPC_IOCON->PIO0_3 &= ~0x1F;            // 清 bit 4:0（FUNC 和 MODE）
LPC_IOCON->PIO0_3 |= (BIT3|BIT0);      // FUNC = 001（USB_VBUS），MODE = 01（下拉）
```

📖 **UM p88 Table 79**（PIO0_3，0x4004 400C）：

| 位 | 名字 | 写入 | 含义 |
|---|---|---|---|
| 2:0 | FUNC | **001** | 0 = PIO0_3；**1 = USB_VBUS**；2 = IOH_1 |
| 4:3 | MODE | **01** | 0 = 无；**1 = 下拉**；2 = 上拉（复位值）；3 = 中继 |

`0x1F` = 0001 1111，正好盖住 FUNC 和 MODE 这 5 位。`BIT3|BIT0` = 0000 1001 → FUNC=1，MODE=01。

**VBUS 是什么？** 1-5 课 Q1 讲过 USB 线里有 4 根线，VBUS 就是那根 **5V 电源线**。📖 **UM p225 Table 212**：

> VBUS — VBUS status input. When this function is not enabled via its corresponding IOCON register, it is driven HIGH internally.

USB 控制器通过这根脚知道“USB 线有没有插着”。📖 **UM p228 Table 214 bit28 VBUSDEBOUNCED**：

> This bit indicates if Vbus is detected or not. The bit raises immediately when Vbus becomes high. It drops to zero if Vbus is low for at least 3 ms. **If this bit is high and the DCon bit is set, the HW will enable the pull-up resistor to signal a connect.**

记住最后一句，1-12 课要用：**VBUS 有电 + 软件设置 DCON，硬件才会去接 D+ 的上拉**。

**为什么要接下拉？** 代码注释（第 131~133 行）说：不接下拉的话 VBUS 脚内部可能悬空，导致 VBUSDEBOUNCED 状态不对；而且注明“只在 NXP 验证板上出现（用错了 ESD 保护芯片）”。这是从 NXP 例程里照抄来的。下拉保证“线拔掉时，这根脚确定是低电平”。

**这根脚在板子上接到哪？** IRPT_V4 没有原理图。看 **T1A 原理图 MCU 页**：

```
VDD_MCU (3.3V)
   │
 [R41 10kΩ]
   │
 PIO0_3/USB_VBUS（第 9 脚）
```

T1A 上 PIO0_3 **没有接到 USB 的 5V**，而是用 10 kΩ **上拉到 3.3V**。也就是说：只要 MCU 有电，VBUS 就永远是“高”。

- 这和代码里的内部下拉并不冲突：外部 10 kΩ 上拉比内部下拉（几十 kΩ）强，读到的仍然是高。
- T1A 有电池（BQ21128 充电芯片），不插 USB 时 MCU 也有电，这时 VBUS 仍然是“高”，USB 控制器会以为线插着。对鼠标功能没有影响，只是不能靠 VBUS 判断有没有插线。
- **和 0-1 课的 ISP 联系起来**：📖 DS 6.2 节 PIO0_3：“A HIGH level during reset starts the USB device enumeration”（复位时 PIO0_3 为高 → ROM ISP 走 USB）。T1A 上 PIO0_3 永远是高，所以**在 T1A 上，复位时拉低 PIO0_1 就会进 USB ISP（U 盘模式）**。IRPT_V4 是不是这样，仍然要问杰哥。

### 第 137~138 行：PIO0_6 设为 USB_CONNECT

```c
LPC_IOCON->PIO0_6 &= ~0x07;
LPC_IOCON->PIO0_6 |= BIT0;            // FUNC = 001（USB_CONNECT）
```

📖 **UM p90 Table 82**（PIO0_6，0x4004 4018）：FUNC 0 = PIO0_6，**1 = USB_CONNECT**，2 = SCK0。

📖 **UM p223，11.4.3 SoftConnect**：

> The connection to the USB is accomplished by bringing USB_DP (for a full-speed device) HIGH through a 1.5 kOhm pull-up resistor. The SoftConnect feature can be used to allow software to finish its initialization sequence before deciding to establish connection to the USB. … To use the SoftConnect feature, the CONNECT signal should control an external switch that connects the 1.5 kOhm resistor between USB_DP and VDD (+3.3 V).

📖 DS 6.2 节 PIO0_6：“USB_CONNECT — Signal used to switch an **external 1.5 kΩ resistor** under software control.”

也就是说，**1.5 kΩ 上拉电阻在芯片外面**，USB_CONNECT 脚控制一个开关去接通它。看 **T1A 原理图 MCU 页**：

```
                VDD_MCU (3.3V)
                    │ 发射极 E（2 脚）
             ┌──────┘
 USB_Connect ─[R47 4.7kΩ]─ 基极 B（1 脚）   Q1  S8550（PNP 三极管）
 (PIO0_6)                    │
                             └ 集电极 C（3 脚）
                                    │
                               [R38 1.5kΩ]
                                    │
              USB_D+ ───────────────┴─────── MCU USB_DP（第 14 脚）
```

PNP 三极管的规律：**基极被拉低时导通**。所以：

| USB_CONNECT | Q1 | D+ | 电脑看到 |
|---|---|---|---|
| 高 | 截止 | 没有上拉 | 没有设备 |
| **低** | **导通** | 经 1.5 kΩ 拉到 3.3V | **有一个全速设备插上了** → 开始枚举 |

所以这个电路里 USB_CONNECT 是**低电平有效**。什么时候变低，由 1-12 课的 `NDrv_USB_Connect(TRUE)` 设置 DCON 位决定（再加上 VBUSDEBOUNCED = 1）。

**为什么要这样做（而不是直接焊一个 1.5 kΩ 上拉）？** 📖 UM p223 那句话：让软件**先把初始化做完，再告诉电脑“我插上了”**。如果上拉一直接着，电脑会在 MCU 还没准备好的时候就开始枚举，第一次请求就会失败。

### 第 140~143 行：不执行

```c
#if POWERDOWN_MODE_USB_WAKEUP      // inc/usbcfg.h:74 = 0
	...
#endif
```

从 Power-down 模式用 USB 唤醒的配置，不执行。

## 三、USB 的两根数据线不需要配置 IOCON

📖 **UM p225 Table 212** 列了 5 个 USB 信号：VBUS、USB_CONNECT、USB_FTOGGLE、**USB_DP、USB_DM**。

前三个和普通 GPIO 共用引脚，要在 IOCON 里选功能。**USB_DP / USB_DM 是专用引脚**（T1A 原理图上是第 13、14 脚，名字就叫 USB_DM / USB_DP，后面没有 PIOx_x），没有 IOCON 寄存器，不用配置。

T1A 上 D+/D- 从 Type-C 接口进来，经过：共模电感 L1（滤除共模干扰）→ ESD 保护二极管 D6/D7 → 0 Ω 电阻 R7/R8 → MCU。

## 补充问答

### Q1：USB 设备是怎么用电的？（对照 T1A 原理图第 2 页电源部分）

**① 先说 USB 本身的规矩**

USB 线里的 **VBUS** 是电脑提供的 **5V**。鼠标这种设备可以直接用它供电，叫**总线供电（Bus-powered）**。

但电脑不会无限制地给电。USB 2.0 的规矩是：

| 阶段 | 设备最多能用多少电流 |
|---|---|
| 刚插上、还没“报到”（枚举）完成 | 100 mA |
| 枚举完成，电脑同意了设备申请的电流 | 设备在描述符里申请的值，最多 500 mA |

设备在**配置描述符**里告诉电脑“我是怎么供电的、要多少电流”。本项目 `src/usbdesc.c` 第 233~235 行：

```c
USB_CONFIG_BUS_POWERED|USB_CONFIG_REMOTE_WAKEUP,   // bmAttributes：总线供电 + 支持远程唤醒
USB_CONFIG_POWER_MA(400),                          // bMaxPower：申请 400 mA
```

也就是说，鼠标告诉电脑：“我靠 USB 供电，最多要 400 mA。”（描述符在 1-13 课细讲。）

**② T1A 上电从 USB 口到 MCU 走过的路**

把第 2 页的几个框按电流方向串起来：

```
Type-C 口 J1 的 VBUS（A4/A9/B4/B9 四个脚并在一起）
   │
 [F1 1206P110TF]  自恢复保险丝：电流太大时自己变成高阻，冷却后恢复
   │ ── D1 BSD3C241V（TVS 管，对地）：吸收静电、浪涌尖峰
   ▼
USB_5V_IN                                   ← 你红框圈的这个网络
   │
 [U1 LP5308QVF  OVP/OCP]  过压/过流保护：输入电压太高或电流太大时切断输出
   │                       R9/R10 接在 ISET 脚上，设定电流限制
   ▼
 5V
   │
 [U2 BQ21128  Charger]    充电芯片（带“电源路径管理”）
   │   ├─ 给电池 VBAT 充电（BAT Connector CON1）
   │   └─ SYS 脚输出 → Charger_OUT
   ▼        插着 USB 时：由 USB 供电（同时给电池充电）
Charger_OUT  拔掉 USB 时：自动改由电池供电
   │
 [SW1 拨动开关  Power ON/OFF]  拨到中间：只充电，鼠标不工作
   │                           上拨或下拨：SYS_PWR 接通，PWR_EN = 高
   ▼
SYS_PWR ──┬─▶ [U4 XC6220B331R  LDO] ──▶ VCC3.3V ─[R37 0Ω]─▶ VDD_MCU   给 MCU
          │      CE = PWR_EN                                          ← 你红框圈的 R37
          ├─▶ [U3 XC9265  DC-DC 降压] ──▶ VCC1.9V                     给 PAW3950 传感器
          │      CE = PWR_EN
          └─▶ [U5 ETA1628  DC-DC 升压] ──▶ H_VDD（7V）                 给左右键线圈（1-4 课）
                 EN = PWR_EN
```

各个元件一句话说明：

| 元件 | 是什么 | 为什么需要 |
|---|---|---|
| F1 自恢复保险丝 | 过流时阻值变大，冷却后自动恢复 | 防止短路时把电脑 USB 口烧坏 |
| D1 / D6 / D7 TVS 管 | 平时不导通，电压突然很高时导通到地 | 手摸接口时的静电（几千伏）直接泄放掉 |
| U1 LP5308 | 过压/过流保护开关 | 插上不合格的充电器（电压过高）时保护后面的芯片 |
| U2 BQ21128 | 锂电池充电芯片 | T1A 是**无线**鼠标方案，有电池；插 USB 时充电 |
| SW1 | 机械拨动开关 | 用户开关机；“中间位置”只充电不工作 |
| U4 XC6220 | **LDO**（低压差线性稳压器） | 把 SYS_PWR（3.x~5V）稳成干净的 3.3V 给 MCU |
| U3 XC9265 | **降压 DC-DC** | 产生 1.9V（给传感器） |
| U5 ETA1628 | **升压 DC-DC** | 把电压升到 7V 给线圈，线圈电压越高“咔哒”越有力 |
| R37 0 Ω | 一个“跳线” | 调试时可以拆掉它，单独测 MCU 的电流 |

**③ Type-C 口上的 R6、R11（5.1 kΩ 接 CC1、CC2 到地）**

Type-C 口和老的 USB-A 口不一样：**C 口的电脑/充电器默认不在 VBUS 上输出 5V**，要先在 CC 线上“看到”对方是一个设备，才会给电。

设备表明身份的方法就是：**CC1、CC2 各接一个 5.1 kΩ 电阻到地**。没有这两个电阻，用 C 对 C 的线插到电脑上，鼠标会完全没电。

**④ 你红框圈的 PIO0_3 和 R41**

1-10 课正文讲过：T1A 上 PIO0_3（USB_VBUS）**没有接到 USB_5V_IN**，而是用 R41 10 kΩ 上拉到 VDD_MCU。

结合上面的电源路径就明白为什么可以这样：T1A 有电池，**不插 USB 时 MCU 也有电**。这时 VBUS 脚读到的仍然是“高”，USB 控制器以为线插着，会去接 D+ 上拉——但线没插，没有任何影响。缺点是**不能用 VBUS 脚判断 USB 线有没有插着**。

另外不能把 USB_5V_IN 直接接到 PIO0_3：5V 超过了 MCU 引脚的耐压范围（MCU 是 3.3V 供电），要接的话得先分压。

**⑤ 和代码的关系（为 T1A 适配记下来）**

| 项目 | IRPT_V4（当前代码） | T1A 原理图 |
|---|---|---|
| 线圈升压使能 | MCU 的 HP_EN（PIO0_16）控制，`Ele_EnableBoost()` | ETA1628 的 EN 接 **PWR_EN**（拨动开关），**MCU 控制不了** |
| 电池 / 充电 | （推测没有电池，纯 USB 供电，待确认） | BQ21128 + 电池，充电芯片的 SCL1/SDA1、/CE、INT 等接到 MCU |
| VBUS 检测 | 未知（问杰哥） | PIO0_3 上拉到 3.3V，不检测 |

第一行是 T1A 适配时要注意的：`Ele_EnableBoost()` / `Ele_DisableBoost()` 在 T1A 上没有对应的引脚（MCU 第 26 脚 Hall_PWR_EN 是给 Hall 芯片供电用的，不是升压）。

**一句话总结**：USB 口的 5V 先经过保险丝、静电保护、过压过流保护，再进充电芯片；充电芯片的输出经开关后分三路：LDO 出 3.3V 给 MCU，降压出 1.9V 给传感器，升压出 7V 给线圈。鼠标在 USB 描述符里向电脑申请了 400 mA。
