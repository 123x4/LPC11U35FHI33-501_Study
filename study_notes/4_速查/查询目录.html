常问的 6 个问题

GUI 发来的包落在哪？0x2000_4500 起 64 字节（EP4 OUT buf0）。表格那一格在 0x2000_4040。
鼠标回 GUI 的包写在哪？0x2000_4480 起（EP3 IN buf0），表格那一格在 0x2000_4038。
怎么知道收到了 / 能发了？看表格那一格的 bit31（A）：A = 0 就是“收到了”或“上一包已发走”。函数 nsAPI_USB_EP_Status（usbhw.c:1429）。
收到了几个字节？64 − 表格里剩下的 NBytes（bit25~16）。usbhw.c:1183。
端点地址 → 表格第几格？(端点号 × 2 + 方向) × 2，方向 OUT=0、IN=1；每格 4 字节。例：0x04 → (4×2+0)×2 = 16 → 0x2000_4000 + 16×4 = 0x2000_4040。
表格里的 Offset 怎么变回地址？缓冲区地址 = 0x2000_0000 + Offset × 64。例：0x0114 × 64 = 0x4500 → 0x2000_4500。

常问

为什么写 0x04，不直接写 4？因为同一个“4”有两个方向：0x04 是端点 4 的 OUT，0x84 是端点 4 的 IN（本项目没用）。最高位把方向带上，一个字节就能唯一指定。
这个格式是谁定的？USB 2.0 规范 9.6.6 节 Table 9-13（bEndpointAddress）。所有 USB 设备都这么写。
EP_4_CUSTION_IN 明明是 OUT？名字是从固件角度起的：“自定义数据从这里进来”。按 USB 的规矩方向看电脑：电脑往外发，所以是 OUT。值 0x04 说了算。
函数为什么不直接收“第几格”？上层只认 USB 的端点地址（和描述符、和电脑说的一致），换算成物理号、格号是底层驱动 usbhw.c 的事。
谁让端点 4 能收数据的？nsAPI_USB_EnableEP(0x04)：清 D 位、置 A 位。调用点：开机 usb.c:26、重新配置后 usb.c:162、usb.c:332，以及每次读之前 usb.c:79。
0x83 呢？bit7 = 1 → IN；端点 3 → 物理号 3×2+1 = 7 → 第 14 格 → 0x2000_4038 → 缓冲区 0x2000_4480。点上面的“算一算”选 0x83 看全过程。

static RetU32 EPAdr(U32 EPNum)              // usbhw.c:103   EPNum = 0x04
{
    U32 val;
    val = (EPNum & 0x0F) << 1;              // :107  取低 4 位 = 4，乘 2 → 8
    if(EPNum & 0x80)                       // :109  bit7 是 1 吗？0x04 不是
    {   val += 1;  }                       // :111  IN 才 +1
    return (val);                          // 返回 8
}

    addr = (U32)USB_EPLIST_ADDR;           // :194  0x2000_4000
    addr += ((EPAdr(EPNum)*2) << 2);       // :195  (8 × 2) × 4 = 64 = 0x40
    return (addr);                         // 0x2000_4040
}

EPAdr 上面的注释（usbhw.c:103 之前那段）写得很清楚：返回值是“EP address in interrupt status”，也就是 INTSTAT 寄存器里的位号。手册 Table 222：INTSTAT 第 8 位 = EP4OUT。
