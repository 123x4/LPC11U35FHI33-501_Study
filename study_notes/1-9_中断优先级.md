# 1-9 中断优先级：`NVIC_SetPriority(USB_IRQn, 1)`

> 📍 **位置**：`main()` → `Device_Init()`（`src/device.c:415`）→ **第 448 行 `NVIC_SetPriority(USB_IRQn , 1);`**
> 📄 **代码**：`inc/core_cm0.h` 第 491~493 行（三个辅助宏）、第 569~577 行（`NVIC_SetPriority`）；`inc/LPC11Uxx.h` 第 75、95 行
> 📖 **手册**：UM 第 6 章 NVIC —— p69 Table 59（中断号）、p70 Table 60（NVIC 寄存器总表）、p78 Table 70/71（IPR4 / IPR5）；UM 第 24 章 —— p447~448 24.3.3.5 节（优先级规则）、24.3.3.6 节（抢占）

---

## 一、优先级解决什么问题

现在已经有两个中断在跑（看门狗、1 ms 心跳），马上还要加 USB 中断。问题是：

1. **两个中断同时来了，先处理谁？**
2. **正在处理一个中断时，另一个来了，要不要打断它？**

这两件事都由**优先级**决定。

---

## 二、规则（📖 UM p447~448，24.3.3.5 / 24.3.3.6）

**规则 ①：数字越小，优先级越高。**

📖 UM p78 Table 70：“Interrupt Priority. **0 = highest priority. 3 = lowest priority.**”

LPC11U35（Cortex-M0）只有 **4 级**：0、1、2、3。

**规则 ②：高优先级可以打断（抢占）正在执行的低优先级中断。**

📖 UM p448：

> When the processor is executing an exception handler, the exception handler is preempted if a higher priority exception occurs.

**规则 ③：同优先级不能互相打断，只能排队。**

📖 UM p448：

> If an exception occurs with the same priority as the exception being handled, the handler is not preempted, irrespective of the exception number. However, the status of the new interrupt changes to pending.

**规则 ④：同优先级同时等待时，中断号小的先执行。**

📖 UM p448：

> If multiple pending exceptions have the same priority, the pending exception with the lowest exception number takes precedence.

画成时间线：

```
优先级：CT16B0 = 0（高），USB = 1（低）

情况 A：正在跑 USB 中断，CT16B0 来了
主程序 ──┐                                        ┌── 主程序
         └─ USB 中断 ──┐            ┌─ USB 继续 ──┘
                       └─ CT16B0 ───┘
                          （打断 USB，处理完再回去）

情况 B：正在跑 CT16B0 中断，USB 来了
主程序 ──┐                              ┌── 主程序
         └─ CT16B0 ─────┐ ┌─ USB ───────┘
                         └─┘
                  （USB 先挂起等待，CT16B0 跑完再进 USB）
```

---

## 三、优先级存在哪里

📖 **UM p70 Table 60**：NVIC 有 8 个 IPR（Interrupt Priority Register）寄存器，IPR0~IPR7，地址 0xE000 E400 ~ 0xE000 E41C。**每个 32 位寄存器管 4 个中断，每个中断占 8 位，但只用最高 2 位**。

📖 **UM p78 Table 71**（IPR5，0xE000 E414）：

```
位：  31 30 │29 … 24│23 22 │21 … 16│15 14 │13 … 8│ 7  6 │ 5 … 0
     IP_USB_FIQ│ 无用  │IP_USB_IRQ│ 无用 │IP_USART0│ 无用 │IP_SSP0│ 无用
     中断 23   │       │ 中断 22  │      │ 中断 21 │      │中断 20│
```

USB_IRQn = 22（`inc/LPC11Uxx.h:75`），22 ÷ 4 = 5 余 2 → **IPR5 的第 2 个字节**，有效位是 **bit 23:22**。

> 为什么每个中断给 8 位却只用 2 位？ARM 的 Cortex-M 架构统一规定每个中断 8 位，但允许芯片厂商只实现高几位。NXP 这颗芯片只实现了 2 位（`inc/LPC11Uxx.h:95` `#define __NVIC_PRIO_BITS 2`），低 6 位读出来永远是 0（📖 Table 71：“These bits ignore writes, and read as 0”）。

## 四、`NVIC_SetPriority()` 逐行（`inc/core_cm0.h:569~577`）

```c
__STATIC_INLINE void NVIC_SetPriority(IRQn_Type IRQn, uint32_t priority)
{
  if(IRQn < 0) {                                   // 负数 = 内核异常（SysTick、PendSV…），在 SCB 里
    SCB->SHP[...] = ...;
  }
  else {                                           // 0~31 = 外设中断，在 NVIC 里  ← 走这里
    NVIC->IP[_IP_IDX(IRQn)] =
        (NVIC->IP[_IP_IDX(IRQn)] & ~(0xFF << _BIT_SHIFT(IRQn)))                          // ① 清掉这个中断的 8 位
      | (((priority << (8 - __NVIC_PRIO_BITS)) & 0xFF) << _BIT_SHIFT(IRQn));             // ② 写入新值
  }
}
```

辅助宏（第 491~493 行）：

```c
#define _BIT_SHIFT(IRQn)  ( ((uint32_t)(IRQn) & 0x03) * 8 )   // 在寄存器里第几个字节 × 8
#define _IP_IDX(IRQn)     ( ((uint32_t)(IRQn) >> 2) )         // 第几个 IPR 寄存器
```

代入 `IRQn = 22`、`priority = 1`：

| 步骤 | 计算 | 结果 |
|---|---|---|
| `_IP_IDX(22)` | 22 >> 2 | **5** → `NVIC->IP[5]` = IPR5 = 0xE000 E414 |
| `_BIT_SHIFT(22)` | (22 & 3) × 8 = 2 × 8 | **16** |
| ① 清除掩码 | `~(0xFF << 16)` | 清掉 bit 23:16 |
| `priority << (8 - 2)` | 1 << 6 | 0x40 = 0100 0000（把 2 位的优先级放到 8 位的**最高 2 位**） |
| ② 写入值 | 0x40 << 16 | 0x0040 0000 → **bit 22 = 1** → bit 23:22 = **01** = 优先级 1 ✅ |

### 在编译产物里看

`__STATIC_INLINE` 表示这个函数会被**内联**（直接把代码展开在调用处，不产生函数调用）。`Device_Init` 的反汇编（`output/Sample.axf`，0x9BC6 起）：

```
9bf6: bl   InitCT16B0              ; 第 445 行
9bfa: ldr  r1, [pc, #0x240]        ; r1 = 0xE000E414（IPR5 地址，0x9E3C 处的常量）
9bfc: ldr  r0, [r1]                ; 读 IPR5
9bfe: movs r2, #0xff
9c00: lsls r2, r2, #0x10           ; r2 = 0xFF << 16
9c02: bics r0, r2                  ; ① 清 bit 23:16
9c04: movs r2, #0x1
9c06: lsls r2, r2, #0x16           ; r2 = 1 << 22
9c08: orrs r0, r2                  ; ② 置 bit 22
9c0a: str  r0, [r1]                ; 写回 IPR5
9c0c: bl   nsAPI_USB_Init          ; 第 449 行
```

和上面的计算完全一致。编译器在编译时就把 `_IP_IDX`、`_BIT_SHIFT`、`1<<6<<16` 全部算好了，运行时只剩 7 条指令。

## 六、到目前为止的中断优先级表

| 中断号 | 中断 | 优先级 | 在哪使能 | 会不会真的触发 |
|---|---|---|---|---|
| 16 | CT16B0（1 ms 心跳） | **0**（复位值） | 1-8 课 | ✅ 每 1 ms |
| 18 | CT32B0（线圈定时） | 0（复位值） | 1-4 课 | ❌ MCR=0，不会触发 |
| 22 | USB_IRQ | **1** | 本课设优先级，1-10 课使能 | ✅ |
| 23 | USB_FIQ | 0（复位值） | **没有使能**（`usbhw.c:316` 在 `#if USB_FIQ_EVENT` 里，该宏为 0；1-10 课更正） | ❌ |
| 25 | WDT | 0（复位值） | 1-1 课 | 只在复位前一刻 |

**设计意图**：只有 USB 被降到了 1，其他保持 0。所以 1 ms 心跳永远能打断 USB 处理，计时不受 USB 通信影响。

> ⚠️ 一个要留意的点：CT16B0 和 WDT 同为 0，彼此不能打断。如果某天 CT16B0 中断里加了耗时的代码，看门狗的警告中断就得排队。（不过 1-1 课讲过，WARNINT=0 时警告中断和复位同时发生，排队也没有意义。）

## 七、小结

```
NVIC_SetPriority(USB_IRQn=22, 1)
  → IPR5（0xE000E414）的 bit 23:22 = 01
  → 内联展开为：读 IPR5 → 清 bit 23:16 → 置 bit 22 → 写回

规则：数字小 = 优先级高；高的能打断低的；同级只排队；同级同时等待时中断号小的先跑
```
