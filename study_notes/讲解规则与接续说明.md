# 讲解规则与接续说明

换新会话、或者要做新讲解页时，先读这份。

## 最新的讲法（2026-11 起，优先于下面的旧规则）

- **学习状态判断（2026-11-03，根据第 3 课上的 12 个提问）与据此定的课程组织方式**：
  - 提问暴露的缺口：① 分不清**软件 / 外设电路 / 外部芯片**各自做什么（“tx 发出去后怎么进来东西”“芯片还是软件”“是不是芯片把 SCLK 拉低”）；② 分不清**配置、动作、结果**（“切回 SCK1 就打时钟了吗”“打时钟就转换了吗”“随便写 DR 就能启动转换吗”）；③ 涉及具体数据时，`& 0x3F`、`× 256`、异或、高低位要结合这个数据逐步算出来（但**不单独讲 C 语言位运算基础**：`|=`、`&= ~`、`<<` 的通用讲解学习者明确说不需要，2026-11-03）；④ **时序参数写法**（± 5%、> 2 µs）需要解释；⑤ 不接受没来源的数字（“1 µs 是怎么来的”）。
  - 优点：追问到底、关注因果和边界、视觉型、喜欢一步一步可控地走。
  - 因此每课固定这样组织：(a) 开头放“本课角色表”：软件 / 外设（哪些寄存器）/ 外部芯片各做什么，每根线谁驱动；(b) 每写一个寄存器都讲三件事：**改了哪几位（二进制前后对比）→ 改完硬件处于什么状态 → 它只是“准备好”还是“开始动作”**；(c) 改寄存器时给“改之前 / 改之后”的二进制对比（不另讲 `|=`、`&= ~` 这些 C 写法本身）；(d) 每个数字给出处（手册表号或计算过程），估计值标明是估计；(e) 图里带寄存器、容器、位号、连线，配上一步 / 下一步 / ± 控制；(f) 预判容易问的“常见疑问”，提前放进页面；(g) 每节配算题和随机练习。

- **图里带上寄存器和数据容器（2026-11-03 学习者要求）**：凡是画数据收发，都要把数据经过的每个容器画出来：软件这边的变量 / 数组 / 指针（如 `hall_spi_tx[]`、`buf_wr`），外设这边的寄存器和缓冲（如 `DR`、发送 / 接收 FIFO、移位寄存器、`SR` 的各个标志位），对方芯片的寄存器；并标清哪一步是软件做的、哪一步是硬件自动做的。
- **多画图（2026-11-03 学习者明确要求）**：第 3 课加的“MCU 与两颗霍尔芯片接线图”效果很好。以后每讲一块电路或一个过程都配图：接线图（照原理图，标网络名和脚号，可按类别高亮）、时序图、数据流动 / 寄存器格子的动画或步进图、状态图。能用图说清的，先图后文。
- **只在电脑上看（2026-11-03 学习者说明）**：页面按电脑宽度设计即可，不用为手机窄屏妥协（图可以更宽、字更大、信息更密），也不必做 400 px 宽度检查；只检查电脑宽度下的效果。
- **学习者反馈（2026-11-03）**：“半拍”概念用文字表 + 格子网格讲两遍都没懂；换成形象动画图后“一下子就明白了”。结论：学习者是强视觉型，**讲法直接决定学习效率**。一个概念讲一遍没懂时，不要加更多文字，而是换一种画法。
- **形象图：学原则，不套模板（2026-11-03 学习者认可第 3 课下①“半拍演示”重画版，同时提醒“都这样画会死板”）**。那张图好用的原因是下面几条原则，每个新场景按内容重新设计画法，不照搬“方框 + 格子 + 小球 + 气泡”的样子：
  1. 画东西本来的样子：看得见的实物、连线、位置关系，而不是只用文字表格。
  2. 让“变化”被看见：哪个东西从哪到哪、哪个值变了，用动画或前后对比显示出来。
  3. 一眼看出此刻谁在动手：其余角色淡下去。
  4. 不同的表示对齐放：同一时刻的图和波形 / 数值 / 代码行放在一起。
  5. 先简后全：先给只含一条主线的简化版，再给完整版。
  6. 能一步步走，也能自动播放。
  具体画法因场景而异，例如：状态机画成路线图或开关；滤波 / 算法画成数轴、曲线，或者拖一拖看结果；时间问题画成时间轴；内存画成地址条；协议包画成拆开的信封；电源画成水路。

- **2026-11-03 补充**：学习者说第 2 课（全程）基本看不懂，要求“考虑实际情况、每一步讲清楚、不跳步、过程中每个变量都解释”。原因判断：全程里用到的零件（移位寄存器、SPI、指针、状态寄存器）都还没讲过。做法：先按站把零件讲透（每课开头列“先认识要用到的东西”、逐行表格“代码 | 白话 + 涉及变量”、课末“本课所有变量”表），学完几站再回头看全程。

- 学习者在“有具体数字、能自己算”的时候学得最好；一上来给公式或代码、一屏塞太多东西、讲解跳步时会卡住。
- 每块内容按 **问题 → 一句话规则 → 数字例子 → 自己算一题 → 最后才对代码** 的顺序讲；代码默认折叠。
- 每块配**大量随机练习题**（数字每次随机、答完给完整算式），页面最后有综合练习，错题过几题再出。
- 学习者会较真（抓到过例子里的错、追问“是不是巧合”）：例子必须自洽，规则要说明为什么对所有情况都成立。
- 讲不懂时，在聊天里用最小步骤重讲、出题确认，懂了再把这个讲法写回页面。

## 讲代码时的固定规则

讲到任何一段功能，都按三层分开讲：

| 层 | 是什么 | 你要做到 |
|---|---|---|
| 🟦 芯片自动做的 | 硬件本身的行为，设置好寄存器后自己运行（例：ADC 转换、USB 收发包、定时器计数） | 知道它会自动发生，不用写代码 |
| ⬜ 现成代码 | 分两种：① 芯片厂商 / 方案商例程（文件头有 NXP、Keil、ARM、World Peace：USB 协议栈、启动文件、LPC11Uxx.h、wnDrv_Pmu.c）；② 公司老项目代码（文件头 Writer ADAM 或在 M300S 老项目里也有：GPIO.c、Timer.c、SPI.c、OSC.c、device.c…）。注意老文件里也夹着本项目新加的函数和 #if 分支 | 知道怎么调用它、它给你什么结果 |
| 🟩 你要负责的代码 | 这个产品自己的逻辑，以后你会改（例：按键算法、线圈时序、组包、GUI 协议、引脚定义） | 每一行都要懂，能自己改 |

## 我对你学习状态的判断，以及据此定的讲法

- 你会认真追问每个没定义的词（“最低点”“学”“反转”“设置外设”）→ **每个新词第一次出现就用一句大白话定义（虚线框 + 绿色定义卡），课末列出“本课新词”**。
- 一页同时出现寄存器、文件行号、算法细节时你会卡住 → **一课只讲一件事；细节和边角情况不放进正课**。
- 你说地图那张图最有帮助，因为能看清“谁干了什么” → **每课开头标出“在地图上的位置”，讲代码时分 🟦 芯片自动 / ⬜ 现成代码 / 🟩 你负责**。
- 你没写过完整项目，学校的知识忘了 → **打地基阶段补电、0/1、单片机、程序结构、代码仓库怎么读，再进入外设**。
- 判断你懂没懂，靠小测验，不靠问“懂了吗”。

## 模块课的固定结构（成体系讲解）

每个外设 / 模块课都完整覆盖以下内容，不只讲片段：

1. 它是干什么的（原理 + 动手演示）
2. **生命周期图**：横轴是时间（开机准备 → 平时工作 → 中断 → 停止/出错），纵轴是谁在做（🟦 芯片 / ⬜ 例程 / 🟩 项目）；每个方块标真实执行顺序、所属七步、代码原文、文件行号、调用链
3. **七步核对**：① 通电 → ② 时钟 → ③ 解锁 → ④ 引脚 → ⑤ 配置 → ⑥ 中断 → ⑦ 使用，哪些有、哪些不需要、为什么；前提依赖（如 IOCON 时钟）也列出
4. **标志和残留**：哪些标志要清、谁清、在哪清；例程已经清了的明确标出
5. 项目里怎么用：谁调用、多久一次、结果交给谁
6. 容易出错的地方
7. 你能改什么
8. T1A 上的变化

**手册对照**：讲到每个寄存器 / 每个开关，都附上用户手册 UM10462（`materials/mcu_reference/LPC11U3x2x1x User Manual.pdf`）的章、表号、页码、英文原文和中文意思；电气参数、引脚表引用数据手册 `LPC11U3X.pdf`。

## 手册能力练习阶梯
