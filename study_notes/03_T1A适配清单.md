## 三、需要特别注意的问题（⚠️ 带去问杰哥 / 硬件）

1. **PIO0_1 接了 BQ21128 的 /CE。** PIO0_1 是 ROM 的 ISP 引脚（0-1 课）：复位时如果是低电平就进 ISP。/CE 上有 R13 2.2M（接 5V）/ R14 1M（接地）分压，再加上 MCU 内部上拉，复位那一刻的电平需要确认是“高”，否则可能开机进 ISP。另外，app 里如果把 PIO0_1 输出低去打开充电，**不能在复位期间保持低**。
2. **VBUS（PIO0_3）恒为高。** 有好处：复位时拉低 PIO0_1 就能进 USB ISP（U 盘模式）救砖（1-10 课）。坏处：不能检测 USB 插拔。
3. **PIO0_10 同时是 SWCLK 和 PAW3950 的 SCLK。** 一旦 `PAW3950_Init()` 把它切成 SCK0，**SWD 调试器就连不上了**（在线单步调试会在这一刻断开）。下载程序靠复位后、切换之前的那段时间，或者靠 ISP。调试策略要提前想好。
4. **PAW3950 NRESET 和 MCU 复位共用一根线**：按复位或看门狗复位时传感器一起复位，这通常是期望的行为；但 MCU 软件复位（升级时的 `NVIC_SystemReset`，0-3 课）**不会**拉低 RESET 脚，传感器不会被复位。
5. **Flash / RAM 余量**：app 代码已到 0xF28B，离 0xFE00 只剩约 2.9 KB；RAM 只剩 904 B（0-3、0-4 课）。新增 Hall、I2C、编码器驱动可能放不下，需要先删掉不用的代码（例如 IRPT_V4 的 ADC/光电部分、`flash_emptyData[4096]`、老配置系统）。
6. **升压不受 MCU 控制**：开机后 7V 一直存在，空闲功耗、电池续航要评估。
