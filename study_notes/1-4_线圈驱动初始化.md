> 📍 **位置**：`main()` → `Device_Init()`（`src/device.c:415`）→ **第 422 行 `Ele_Init();`**

## 一、先搞清楚线圈是怎么被驱动的

这个鼠标的“触感”来自左右键下面各一个**电磁线圈**：给线圈通一下电（约 1~2 ms），它产生一个磁力脉冲，手指就感觉到“咔哒”一下。

IRPT_V4 没有原理图，下面用 **T1A 原理图**的 “LB & RB Haptics Driver” 部分（两块板的线圈驱动思路相同）：

```
              H_VDD（升压芯片输出，由 HP_EN 控制开关）
                │
              [R62 10Ω]          限流
                │
       ┌────────┼──────────┬──────────┐
       │        │          │          │
   D28 ▲     Coil1(LB)   C58 470uF  C59 100uF     储能电容：升压芯片慢慢充，线圈瞬间取电
   续流 │        │          │          │
       └────────┤         GND        GND
                │
              漏极 D
   PWM1 ─[R63 100Ω]─┬── 栅极 G   Q4 MS3416K（N 沟道 MOS 管）
                    │       源极 S
                 [R65 1MΩ]    │
                    │        GND
                   GND

   PWM1 = 高 → MOS 管导通 → 电流 H_VDD → 线圈 → MOS 管 → GND → 线圈吸合（振一下）
   PWM1 = 低 → MOS 管截止 → 线圈断电；线圈里残留的电流经 D28 续流，避免高压击穿 MOS 管
```

所以控制线圈只需要三根线：

| 信号 | IRPT_V4 引脚 | 作用 |
|---|---|---|
| HP_EN | PIO0_16 | 升压芯片使能（高 = 打开，产生 H_VDD） |
| PWM1 | PIO0_4 | 左键线圈：高 = 通电 |
| PWM2 | PIO0_5 | 右键线圈：高 = 通电 |

> 💡 **和上一课的开漏问题对上了**：T1A 的栅极只有 R65 **下拉** 1MΩ，没有上拉。T1A 原理图 MCU 页上 PIO0_4/5 接的是 SCL1/SDA1（I2C），PWM1/PWM2 换到了别的普通脚。而 IRPT_V4 用的是真开漏的 PIO0_4/5，“输出高”只是松开引脚，**板上必须有外部上拉**，MOS 管才能导通。你的板子线圈能振，说明 IRPT_V4 上确实有上拉（具体阻值问杰哥）。

**通电多久由谁控制？** 不能靠主循环去数时间（主循环一圈的时间不固定），要用硬件定时器。本课初始化的 **32 位定时器 CT32B0** 原本就是干这个的“闹钟”——但读到第四节你会发现，当前配置下它其实没被用上。

## 二、`Ele_Init()` 逐行（IRPT_V4 分支，第 304~308 行）

```c
#elif (defined(HAPTIC_V4) || defined(IRPT_V4) || defined(V4_HALL_HPTIC_V4))
  Ele_DisableBoost();      // HP_EN  = 0
  Ele_LeftClose();         // PWM1   = 0
  Ele_RightClose();        // PWM2   = 0
  Ele_EnableBoost();       // HP_EN  = 1
#elif ...
#endif
  Ele_InitCT32B0();
```

四个宏在 IRPT_V4 下的展开（第 83~89 行）：

```c
#define Ele_LeftClose()     DrvGPIOOutput(PWM1_PORT, PWM1_PIN, 0)   // PIO0_4 输出低
#define Ele_RightClose()    DrvGPIOOutput(PWM2_PORT, PWM2_PIN, 0)   // PIO0_5 输出低
#define Ele_EnableBoost()   DrvGPIOOutput(HP_EN_PORT, HP_EN_PIN, 1) // PIO0_16 输出高
#define Ele_DisableBoost()  DrvGPIOOutput(HP_EN_PORT, HP_EN_PIN, 0) // PIO0_16 输出低
```

`DrvGPIOOutput()`（`src/GPIO.c:569`）做两件事：`DIR |= 1<<pin`（设为输出），再 `SET` 或 `CLR`。

| 行 | 做了什么 | 为什么 |
|---|---|---|
| `Ele_DisableBoost()` | 关升压 | 上一课已经设成低了，这里再确认一次 |
| `Ele_LeftClose()` | 左线圈 MOS 管关 | 同上，**先保证两个线圈都不通电** |
| `Ele_RightClose()` | 右线圈 MOS 管关 | 同上 |
| `Ele_EnableBoost()` | **打开升压** | 开始给 C58/C59 充电，为第一次振动储能 |

**顺序为什么是“先关线圈，再开升压”？** 如果升压先开、而某个线圈的 MOS 管恰好是导通的，H_VDD 一出来就直接从线圈流到地，线圈会一直通电发热。先把两个 MOS 管都关掉，再开电源，才安全。

> 💡 上一课讲过“先设电平再切输出”防毛刺。`DrvGPIOOutput()` 的顺序反过来了（先 DIR 再 SET/CLR），但因为上一课已经把这三根脚设成输出了，这里 DIR 不会再变化，所以没有毛刺。

注意：**升压从这里开始就一直开着**，之后整个运行过程中只控制 PWM1/PWM2。

## 三、`Ele_InitCT32B0()` 逐行（第 992~1006 行）

### 先认识 CT32B0 的计数原理

📖 **UM p356，16.7.5 节**：

> The Prescale Counter is incremented on every PCLK. When it reaches the value stored in the Prescale Register, the Timer Counter is incremented, and the Prescale Counter is reset on the next PCLK. This causes the TC to increment on every PCLK when PR = 0, every 2 PCLKs when PR = 1, etc.

画出来：

```
PCLK（48MHz）  ┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃ …
                  │
PC（预分频计数）  0 1 2 … 47 0 1 2 … 47 0 …     数到 PR 就清零
                              │            │
TC（定时器计数）       0       1            2 …  每 PR+1 = 48 个 PCLK 加 1
                                                 → 每 1 µs 加 1
MR0 / MR1（匹配寄存器）  TC 等于它时 → 置 IR 标志 → （MCR 允许的话）产生中断
```

📖 **UM p351，16.2 节**：

> The peripheral clock is determined by the system clock (see Table 23).

上一课系统时钟已经是 48 MHz，所以 PCLK = 48 MHz。

### 第 994 行：先关掉 CT32B0 的 NVIC 中断

```c
NVIC_DisableIRQ(TIMER_32_0_IRQn);   // TIMER_32_0_IRQn = 18（inc/LPC11Uxx.h:71）
```

📖 **UM p72 Table 59**：中断号 18 = CT32B0，中断源 “Match 0 - 3”（还有捕获）。

1-1 课讲过的三道门：**外设自己的中断开关 → NVIC → PRIMASK**。这一行先把 NVIC 这道门关上，配置期间不会误进中断。

### 第 995 行：停止计数（但这一行其实没有生效）

```c
LPC_CT32B0->TCR = 0 ;
```

📖 **UM p355 Table 320**（TCR，0x4001 4004）：bit0 CEN，0 = 停止计数；bit1 CRST，1 = 计数器清零。

⚠️ **这一行写在打开时钟（第 997 行）之前**。CT32B0 的时钟还没开时，往它的寄存器里写东西是**无效的**。不过 TCR 复位值本来就是 0，所以结果没有影响。正确的顺序应该是先开时钟、再写寄存器。

### 第 997 行：打开 CT32B0 的时钟

```c
LPC_SYSCON->SYSAHBCLKCTRL |= (0x01 << 9);
```

📖 **UM p32 Table 24**：bit9 **CT32B0**，复位值 0。📖 UM p351 16.2 节：“Power: In the SYSAHBCLKCTRL register, set bit 9 and 10”（bit9 = CT32B0，bit10 = CT32B1）。

### 第 998~1000 行：清零，并设置 1 µs 一拍

```c
LPC_CT32B0->TC = 0;
LPC_CT32B0->PC = 0;
LPC_CT32B0->PR = 47;   // 48MHz / (47+1) = 1MHz → TC 每 1µs 加 1
```

| 寄存器 | 📖 | 写入 | 含义 |
|---|---|---|---|
| TC（0x008） | p356 Table 321 | 0 | 计数值从 0 开始 |
| PC（0x010） | p356 Table 323 | 0 | 预分频计数从 0 开始 |
| PR（0x00C） | p356 Table 322 | 47 | 每 48 个 PCLK，TC 加 1 |

**为什么选 1 µs？** 线圈通电时间以微秒为单位设置（例如 `MAX_VIBRATE_DURATION_US 2000`，第 20 行），TC 的 1 就直接等于 1 µs，计算时不用换算。

**TC 多久会溢出？** 📖 UM p356 16.7.3：TC 数到 0xFFFF FFFF 后回到 0，**不产生中断**。2³² µs ≈ 4295 秒 ≈ **71.6 分钟**溢出一次。（后面设闹钟用的是 `MR0 = TC + 1 + 时长`，32 位无符号数相加会自动绕回，溢出时也能正确匹配——这是练习第 3 题。）

### 第 1002 行：不允许任何匹配动作

```c
LPC_CT32B0->MCR = 0;
```

📖 **UM p357 Table 324**（MCR，0x4001 4014），每个匹配通道 3 位：

| 位 | 名字 | 1 = |
|---|---|---|
| 0 | MR0I | MR0 匹配时**产生中断** |
| 1 | MR0R | MR0 匹配时**TC 清零** |
| 2 | MR0S | MR0 匹配时**停止计数** |
| 3 | MR1I | MR1 匹配时产生中断 |
| 4 | MR1R | … |
| 5 | MR1S | … |

全部写 0：现在 MR0、MR1 匹配了也什么都不做。**R 和 S 位以后也一直是 0**，所以 TC 永远不会被清零或停止，是一个**一直往前走的“时钟”**（📖 UM p351 16.4 节 Applications 里的 “Free running timer”）。

### 第 1004~1005 行：开始计数，打开 NVIC

```c
LPC_CT32B0->TCR = 1 ;               // CEN = 1，开始计数
NVIC_EnableIRQ(TIMER_32_0_IRQn) ;   // NVIC 打开中断 18
```

此时三道门的状态：

```
外设开关 MCR.MR0I / MR1I = 0  ✗   ← 还关着
NVIC ISER0 bit18          = 1  ✓
PRIMASK                   = 允许 ✓
```

所以**现在不会有任何 CT32B0 中断**。按设计，要等用户按键时代码才去打开 MCR 的那一位（但第四节会看到，当前配置下这一步从来没执行）。

## 四、⚠️ 重要发现：当前配置下，这个“闹钟”根本没被用到

### 1. 设计意图（`#else` 分支，当前不编译）

`Ele_LeftKeyPressProcess()` 等 4 个函数里，原本的设计是这样用 CT32B0（第 806~812 行，简化）：

```c
LPC_CT32B0->MCR &= ~(0x01 << 0);                 // 先关 MR0 中断
Ele_LeftOpen();                                   // PWM1 = 高，线圈通电
LPC_CT32B0->MR0 = LPC_CT32B0->TC + 1 + 时长(µs);  // 闹钟定在“现在 + 时长”
LPC_CT32B0->MCR |= (0x01 << 0);                  // 打开 MR0 中断
```

闹钟响时进 `TIMER32_0_IRQHandler`（第 265~294 行）：

```c
if (LPC_CT32B0->IR & (1<<0)) {        // MR0 匹配了？（📖 p355 Table 318 bit0 MR0INT）
    LPC_CT32B0->IR = (1<<0);          // 写 1 清标志（写 0 无效）
    LPC_CT32B0->MCR &= ~(1<<0);       // 关掉 MR0 中断（一次性闹钟）
    Ele_LeftClose();                  // PWM1 = 低，线圈断电
    ...
}
if (LPC_CT32B0->IR & (1<<1)) { ... 右线圈用 MR1，同样处理 ... }
```

```
TC:     1000      1001                    3001
         │         │                       │
         按键      PWM1=高 MR0=3001          TC==MR0 → 中断 → PWM1=低
                   ├────── 线圈通电 2000µs ──┤
```

左用 MR0、右用 MR1，共用一个一直往前走的 TC，这就是为什么 MCR 的 R、S 位都是 0。这种写法的好处是：线圈通电期间 CPU 可以去干别的事。

### 2. 实际执行的是 `#if BRAKE_FUNC_ENABLE` 分支

`src/my_electromagnet.c:28`：

```c
#define BRAKE_FUNC_ENABLE               1
```

所以 4 个按键处理函数编译进去的都是 `#if BRAKE_FUNC_ENABLE` 这一支（第 791~803 行，简化）：

```c
Ele_LeftOpen();                          // PWM1 = 高
CT16B1_DelayUs(通电时长);                 // 用 CT16B1 原地等（忙等）
Ele_LeftClose();                         // PWM1 = 低
if (leftEle.brakeEnable) {               // “制动”：等一会儿再补一个短脉冲
    CT16B1_DelayUs(brakeDelayUs);
    Ele_LeftOpen();
    CT16B1_DelayUs(brakeDurationUs);
    ...
}
```

`CT16B1_DelayUs()`（`src/Timer.c:202`）用的是**另一个定时器 CT16B1**，而且是 `while (TC < us-2);` **原地死等**，等待期间 CPU 什么也不做。

### 3. 用编译产物证实

在 `output/Sample.hex` 里搜索 CT32B0 的基地址 0x4001 4000，整个程序只有 **0x7074** 这一处常量。反汇编看谁用了它：

```
6c7a: ldr r4, [pc, #0x3f8]  @ 0x7074   ← 在 TIMER32_0_IRQHandler（0x6C79 起）里
6ce2: ldr r0, [pc, #0x390]  @ 0x7074   ← 在 Ele_InitCT32B0（0x6CD9 起）里
```

只有中断函数和初始化函数访问 CT32B0，**没有任何代码会打开 MCR 的 MR0I / MR1I**。

### 4. 结论

```
CT32B0：时钟开着、TC 每 1µs 加 1、NVIC 中断 18 开着
        但 MCR 永远 = 0  →  TIMER32_0_IRQHandler 永远不会被执行
线圈定时：实际由 CT16B1_DelayUs() 忙等完成（1-8 课、2-5 课细讲）
```

这是老代码切换方案后留下的“空转”部分，不影响功能。在 T1A 适配时可以考虑：要么删掉 CT32B0 初始化，要么改回中断方案（这要和杰哥确认为什么改成了忙等，可能和“制动”需要精确的脉冲间隔有关）。

**中断函数的地址**（0-4 课的向量表复习）：中断 18 是第 16 + 18 = 34 项，地址 0x4000 + 34×4 = **0x4088**。在 `output/Sample.hex` 里读这个地址，值是 **0x6C79**，正好是 `List/Sample.map` 第 1009 行 `TIMER32_0_IRQHandler 0x00006c79`（末位 1 表示 Thumb）。函数虽然不会被调用，但向量表里确实填了它。`src/Timer.c:135` 的同名函数在 `#if 0` 里，不参与编译。

## 六、小结

```
Ele_Init()
 ├─ 关升压 → 关左线圈 → 关右线圈 → 开升压     先确保线圈不通电，再给电源
 └─ Ele_InitCT32B0()
     ├─ NVIC 关中断 18
     ├─ TCR=0（时钟还没开，这一行无效，但不影响结果）
     ├─ 开 CT32B0 时钟（SYSAHBCLKCTRL bit9）
     ├─ TC=0, PC=0, PR=47          → 1µs 一拍
     ├─ MCR=0                      → 不清零、不停止、暂不中断
     └─ TCR=1 开始计数，NVIC 开中断 18
                               （但 BRAKE_FUNC_ENABLE=1，MCR 永远不开，中断不会来）
```

**两条规律：**

1. **先开外设时钟，再写外设寄存器**。时钟没开时写入无效。
2. **定时器“一直走 + 匹配寄存器定闹钟”**，可以让多个通道共用一个定时器，各自独立定时。

## 补充问答

### 练习参考答案

**第 1 题**

TC 每 (PR+1) 个 PCLK 加 1（📖 UM p356 16.7.5）。

- PR = 23，PCLK = 48 MHz：48 MHz ÷ 24 = 2 MHz → TC 每 **0.5 µs** 加 1。
- PR = 47，PCLK = 12 MHz：12 MHz ÷ 48 = 250 kHz → TC 每 **4 µs** 加 1。

所以 `PR = 47` 能得到 1 µs，前提是系统时钟已经是 48 MHz。`Ele_Init()` 排在 `InitSystemOSC()` 后面，顺序是对的。如果把它挪到切 PLL 之前，所有通电时间都会变成 4 倍。

**第 2 题**

第二次调用时，第 995 行**有效**。第一次调用已经把 SYSAHBCLKCTRL bit9 置 1，时钟一直开着，所以 `TCR = 0` 能真正停止计数。

“写在开时钟之前无效”只在第一次调用、时钟还没开的时候成立。正确的写法应该是“先开时钟，再写寄存器”，这样第一次和第二次的行为就一致了。

**第 3 题**

```
  0xFFFF FF00
+ 0x0000 0001
+ 0x0000 03E8   （1000）
= 0x1 0000 02E9  → 超过 32 位，最高位丢掉
= 0x0000 02E9   （745）
```

TC 怎么走到 745：

```
0xFFFF FF00 → 0xFFFF FFFF   走了 255 µs
0xFFFF FFFF → 0x0000 0000   再走 1 µs（溢出，回到 0）
0x0000 0000 → 0x0000 02E9   再走 745 µs
合计 255 + 1 + 745 = 1001 µs
```

正好是 “1 + 1000” µs。32 位无符号数加法溢出后自动绕回，和 TC 溢出后从 0 开始，两边“绕”的方式一样，所以溢出时闹钟照样准。

**第 4 题**

`MCR = (1<<0) | (1<<1)` 表示 MR0 匹配时既产生中断（MR0I），又把 TC 清零（MR0R）（📖 UM p357 Table 324）。

左右键几乎同时按下（时长都是 2000 µs）：

```
TC = 1000  按左键：MR0 = 1000 + 1 + 2000 = 3001
TC = 1500  按右键：MR1 = 1500 + 1 + 2000 = 3501
TC = 3001  MR0 匹配 → 左线圈断电（正确，2000 µs）
           同时 TC 被清零！
TC = 0 … 一直数到 3501 才匹配 MR1
           → 右线圈实际通电 1500 + 3501 ≈ 5000 µs，是设定值的 2.5 倍
```

右线圈通电过久会发热，触感也不对。所以共用一个定时器时，**不能让任何一个通道去清零 TC**。这就是原代码 MCR 的 R、S 位一直为 0 的原因。

**第 5 题**

调用链是：主循环 `Device_Active()` → `Device_Scan()` → `Device_Button_Scan()` → `Button_Scan()` → `Ele_LeftKeyPressProcess()`（`app/button.c:626`）→ `CT16B1_DelayUs()`。所以忙等发生在**主循环**里。

- **主循环能不能读按键、发 USB 报文？不能。** CPU 卡在 `while (TC < us-2);` 里，主循环后面的 `Device_Pack()`、`Device_Report()` 都要等这 2000 µs（如果有制动，还要再加上制动延时和制动脉冲时间）结束后才能执行。所以这次按键的报文会晚 2 ms 以上才发出去。
- **中断能不能进？能。** `CT16B1_DelayUs()` 里没有关中断，`while` 循环可以被打断。USB 中断、CT16B0 的 1 ms 节拍中断照常进入，处理完再回来继续等。

> 小提醒：中断打断忙等时，延时不会变短。中断处理期间 TC 照样在走，所以中间被打断一般没有影响。但如果中断恰好在快到时间时进来，CPU 要等中断处理完才能回到 `while` 判断，线圈就会多通电一段时间，最多多出一次中断处理的时长。

这也正好说明了中断方案（`#else` 分支）的优点：线圈通电期间 CPU 不用等，主循环照常运行。当前用忙等的代价，就是每次按键会让主循环停 2 ms 以上。
