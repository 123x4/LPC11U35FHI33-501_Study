# HapticPOC 精通版学习计划

> **目标**：不只是看懂代码，而是做到：
> 1. 每一行寄存器操作，都能说出对应手册的哪一页、哪个位、为什么写这个值；
> 2. 每一个电路，都能说出它为什么这样设计、参数怎么算、坏了会出现什么现象；
> 3. 能**不看项目代码**，只看手册就把任何一个驱动重新写出来；
> 4. 能独立完成新板（GT_Lina T1A）的适配，并用仪器证明它工作正常。
>
> 预计用时：**8~10 周**（全职）。每个阶段都有“过关标准”，没过关不进入下一阶段。
> 本计划取代原来的“第 1 课”讲法。第 1 课的内容并入阶段 10。

## 二、学习方法（每个阶段都按这个流程走）

**“手册 → 自己写 → 对照项目 → 上板验证 → 写笔记”五步法**

1. **读手册三遍**
   - 第 1 遍：读概述、特性和框图，回答“这个外设能做什么”；
   - 第 2 遍：**逐位**读寄存器表，回答“每一位是什么、复位值是多少”；
   - 第 3 遍：读注意事项、Remark、时序图和勘误，回答“哪里容易踩坑”。
2. **先不看项目代码**，只根据手册写出最小驱动（比如“ADC 读一次”）。
3. **对照项目代码**，逐行比较，把差异记进笔记。每一处差异要回答：是项目代码更好、我的更好，还是项目代码有问题？
4. **上板验证**：用调试器的 Peripherals 窗口看寄存器的实际值，用示波器或逻辑分析仪看真实波形。**任何结论都要有波形或数据支撑。**
5. **写寄存器笔记**（模板如下），存放在 `学习笔记/寄存器笔记/外设名.md`：

```
| 寄存器 | 地址 | 位 | 手册页 | 项目写入值 | 代码位置 | 为什么这样写 | 我验证的方法 |
|---|---|---|---|---|---|---|---|
| SYSPLLCTRL | 0x4004 8008 | MSEL[4:0]=3, PSEL[6:5]=1 | UM p23-24 | 0x23 | src/OSC.c:44 | 12MHz×4=48MHz，FCCO=2×2×48=192MHz∈[156,320] | CLKOUT 输出用示波器测 |
```

**每周和杰哥对一次“待确认清单”**（每个阶段末尾都有）。

## 四、各阶段详细安排

### 阶段 0：认识芯片和板子（2 天）

**读：**
- DS p5 订购信息：你的芯片是 **LPC11U35FHI33/501**，有 64KB Flash、4KB EEPROM、8KB SRAM 和 2KB USB SRAM，HVQFN33 封装。
- DS p11~18 引脚描述：33 脚封装每个引脚有哪些复用功能。
- UM 第 1 章 p6~13：整体特性、框图。
- UM 第 2 章 p14~18：存储器映射（Flash、SRAM、EEPROM、外设地址）。

**做：**
- 对照 `Sample.uvproj`：Keil 里选的器件是 **LPC11U37/501（128KB）**，但芯片实际是 U35（64KB），应用程序放在 `0x4000~0xFFFF`（IROM1 起始 0x4000，大小 0xC000）。想一想这三者是否矛盾。
- 填一张**引脚分配总表**：IRPT_V4（依据 `inc/my_board.h`）和 T1A（依据 SCH 第 1 页 U6）各一列，每一行写 引脚号 / 网络名 / 复用功能 / IOCON 的 FUNC 值 / 方向 / 上下拉。

- [ ] 能说出 SRAM0、USB SRAM、EEPROM 各在哪个地址、多大。
- [ ] 能说出为什么 PIO0_10、PIO0_13、PIO0_14 默认不是 GPIO。
- [ ] 能解释 Keil 里选 U37 却能给 U35 用的前提条件和风险。

### 阶段 1：硬件电路精读（4 天）

用 SCH 两页 + 板子照片 + 万用表实测。

| 模块 | 要搞懂的问题 |
|---|---|
| USB 输入 | CC1/CC2 上的 5.1kΩ 下拉电阻有什么作用？共模电感 L1 和 TVS（D6/D7）为什么要加？ |
| 过压保护 LP5308 | 过压阈值由什么决定？R9/R10 的作用是什么？ |
| 充电 BQ21128 | ILIM、TS（NTC）、/CE、QON 引脚分别做什么？R13/R14 分压出的 /CE 是什么电平？ |
| 电源开关 SW1 | 拨到中间、向上、向下三个位置时，SYS_PWR 和 PWR_EN 分别是什么状态？（图上红字说明） |
| DC-DC 1.9V、LDO 3.3V | 分别给谁供电？PAW3950 为什么需要 1.9V？ |
| **升压 7V ETA1628** | 用 R32/R33 反馈电阻计算输出电压；EN 接的是 PWR_EN，意味着 MCU **无法**关断升压 |
| **线圈驱动** | ① MOS 导通后线圈电流 `i(t) = V/R × (1 - e^(-t/τ))`，其中 τ=L/R；② 关断时 DS32W 续流二极管的作用；③ R62（10Ω）+ C58（470µF）+ C59（100µF）组成的储能和限流；④ 栅极 100Ω + 0.1µF 的 RC 会让开关变慢多少；⑤ **R67/R68 是 0Ω 1206 电阻，可以换成小阻值采样电阻来测线圈电流** |
| Hall 供电开关 | Q3（NPN）+ MOS1（PMOS）的工作原理：Hall_PWR_EN 为高电平时为什么是**打开**？ |
| 光学编码器 | SCROLL_EN 控制发射管，UP/DOWN 是接收管的输出 |
| MCU 最小系统 | 12MHz 晶振 + 负载电容、复位电路、SWD 接口、USB 上拉（USB_Connect）、VBUS 检测（PIO0_3） |

**产出：** ① 手绘**电源树**（从 USB 5V 一路画到每颗芯片）；② **线圈驱动计算书**：先测线圈的 R 和 L，算出 Ton = 100/500/1000/2000µs 时的峰值电流和能量。

- [ ] 不看图能画出线圈驱动电路，并解释每个元件的作用。
- [ ] 能回答：如果续流二极管 D28 开路，会发生什么？
- [ ] 能回答：充电器拨到“只充电”档时，MCU 有没有电？

### 阶段 2：Cortex-M0 内核、启动、内存布局、Bootloader（4 天）

**读：**
- UM 第 24 章 p432~501（Cortex-M0 附录），重点是 **p444~447 异常模型和向量表**，以及 p437~459 HardFault 相关内容。
- UM 第 6 章 NVIC p68~79（中断优先级 IPR 在 p70~79）。
- UM 第 22 章 p427~429：ROM 里的**整数除法程序**（M0 没有硬件除法器）。
- UM 第 20 章 p394~400：**CRP（代码读保护）**，地址 0x2FC 处的值决定保护级别。

**对照代码：**
- `src/startup_LPC11Uxx.s`：向量表、Reset_Handler、`Stack_Size = 0x200`（512 字节）、`Heap_Size = 0`。
- `Sample.uvproj`：IROM1 = 0x4000/0xC000，IRAM1 = 0x10000000/0x2000，IRAM2 = 0x20004000（USB RAM）。
- 编译生成的 `List/*.map`：看每个段放在哪里、栈放在哪里、最大栈深度（Keil 的 `.htm` 静态调用图）。

**动手实验：分析 `资料/Z_M300S FW Update/merge_firmware.bin`**

我已经初步解析过，结果如下：

| 偏移 | 初始 SP | 复位向量 | 含义 |
|---|---|---|---|
| 0x0000 | 0x10000AD8 | 0x00000181 | **Bootloader**（不在仓库中） |
| 0x4000 | 0x10001BF8 | 0x00007F1D | **应用程序**（就是本工程） |

Bootloader 的中断向量都指向它自己内部的几个小函数（0x18D、0x1AD……）。

**思考题（本阶段最重要的问题）**：Cortex-M0 **没有 VTOR 寄存器**，不能把向量表移到 0x4000。那么应用程序的 USB 中断、定时器中断是怎么被执行到的？（提示：要么 Bootloader 把中断“转发”到 0x4000 处表里的地址，要么用 SYSMEMREMAP 把向量表重映射到 RAM。自己反汇编 0x18D 处的代码来验证。）**【待确认：向杰哥要 Bootloader 源码】**

另外：`Sample.hex` 的 0x2FC 处写的是 `FFFFFFFF`，说明 CRP 没有开启，自己对照 UM p394 确认。

- [ ] 能讲清从上电到进入 `main()` 每一步发生了什么（Boot ROM → Bootloader → 应用 Reset_Handler → `__main` → 分散加载 → `main`）。

### 阶段 3：时钟、电源控制、复位、BOD（3 天）

**读：** UM 第 3 章 p19~55，重点：

| 内容 | 页码 |

| 时钟总框图 | p19~20 |
| SYSPLLCTRL | p23~24 |
| SYSOSCCTRL | p25 |
| MAINCLKSEL / UEN | p30 |
| SYSAHBCLKCTRL（外设时钟门控） | p31~33 |

| FLASHCFG（Flash 等待周期，复位值 0x2 = 3 个时钟，≤50MHz 可用） | p45 |
| BODCTRL | p50~52 |
| **PLL 频率计算**：Fclkout = M × Fclkin = FCCO / (2×P)，FCCO 必须在 156~320MHz | p53~55 |

另外：UM 第 4 章 PMU p56~58，第 5 章功耗配置 p59~67，DS p40~44 功耗数据。

**对照代码：** `src/OSC.c`（`InitSystemOSC`、`InitUSBOSC`）、`inc/OSC.h`（MSEL=3、PSEL=1）、`src/device.c:479`（BODCTRL）。

**练习：**
1. 手算：12MHz 晶振，MSEL=3 → M=4 → 48MHz；PSEL=1 → P=2 → FCCO=192MHz。USB PLL 也一样算一遍。
2. 解释为什么切换时钟源时要给 UEN 寄存器写 1→0→1，并在手册中找到依据。
3. 项目代码**没有**设置 FLASHCFG，为什么在 48MHz 下没问题？如果超频到 50MHz 以上会怎样？
4. 自己写一份 `my_clock_init()`，和 `OSC.c` 逐行比较。
5. BOD 设置的是 Level 3（2.63V 触发，2.71V 释放），对照 UM p50~52 确认；思考电池供电的 T1A 板是否需要调整。

**上板实验：** 用 `CLKOUT()` 把主时钟分频后从 CLKOUT 引脚输出，用示波器测频率。注意 T1A 板上 PIO0_1 接的是充电器的 /CE，不能乱用；在 IRPT_V4 板上 PIO0_1 是前侧键（FRONT_BUTTON），实验时先把这个按键功能屏蔽掉。

### 阶段 5：定时器与时间基准（3 天）

**读：** UM 第 15 章 CT16B p333~350（MCR p335~336），第 16 章 CT32B p351~368，第 18 章 SysTick p379~382。

**对照代码：**
- `src/Timer.c`：CT16B0 产生 1ms 中断（PR=47、MR0=999），`CT16B1_DelayUs()`（`:202`）是忙等延时。
- `src/my_tick.c`、`POLLING_INTERVAL_MS` 宏。
- `src/my_electromagnet.c`：`Ele_InitCT32B0()` 和 `TIMER32_0_IRQHandler`（非阻塞方案，目前未启用）。

**本阶段的核心问题：Ton 到底有多准？**

当前的振动代码是“开线圈 → `CT16B1_DelayUs(Ton)` → 关线圈”，而且**期间没有关中断**。`CT16B1_DelayUs` 的循环条件是 `TC < us - 2`。如果等待过程中进入 USB 中断，中断返回前定时器继续计数，线圈却一直开着，**导通时间就会被拉长**。

**上板实验：**
1. GUI 设置 Ton = 100、500、1000µs，用示波器测 PWM1 引脚的高电平宽度，每组测 100 次，统计最小值、最大值和平均值。
2. 一边猛点按键一边让 USB 持续传输（比如 GUI 持续读 RawData），看最大值有没有变大。
3. 根据数据评估：现在的误差是否可以接受？如果不行，比较“临界区关中断”和“改用 CT32B0 匹配输出（硬件自动翻转引脚）”两种方案。

**过关标准：**
- [ ] 能用一张表说清本项目 4 个定时器（CT16B0/CT16B1/CT32B0/CT32B1）分别被谁占用、做什么用。
- [ ] 有 Ton 精度的实测数据，并能解释误差来源。
