## 0. 项目概况

这是一款**带电磁振动反馈的游戏鼠标 POC**（概念验证样机）：

- 左、右键不用传统机械微动开关，而是用**模拟量传感器**测量按键的按压深度（早期板子用 Hall 霍尔芯片，IRPT_V4 板用的是光电对管 + MCU 内部 ADC）。
- 按下、松开时，MCU 给按键下方的**电磁线圈**通电几百微秒，让手指产生“咔哒”触感。
- 支持类似磁轴键盘的 **AP（触发点）/ RT（Rapid Trigger 快速触发）**，参数都能用 PC 端 GUI 调整。
- 光学传感器是 **PAW3950**，滚轮可以用编码器。
- 走 USB HID 连接电脑，VID=`0x1A81`、PID=`0x2071`（`inc/usbdesc.h:39`）。

MCU 是 **NXP LPC11U3x（Cortex-M0，48 MHz）**。STM32 的思路基本都能套用，只是寄存器名称不一样。

## 1. 给 STM32 开发者的 LPC11U 速查

| 概念 | STM32（HAL/寄存器） | LPC11U（本项目写法） |
|---|---|---|
| 开外设时钟 | `RCC->APB1ENR \|= ...` | `LPC_SYSCON->SYSAHBCLKCTRL \|= (1<<n)` |
| 模拟外设上电 | 无此概念 | `LPC_SYSCON->PDRUNCFG &= ~(1<<n)`（ADC、PLL 等要先上电） |
| 引脚复用 / 上下拉 | `GPIOx->MODER/AFR/PUPDR` | `LPC_IOCON->PIOx_y`：bit[2:0] 选功能，bit[4:3] 选上下拉，bit7 选模拟/数字 |
| GPIO 方向 / 读写 | `MODER` / `IDR` / `BSRR` | `LPC_GPIO->DIR[port]` / `PIN[port]` / `SET[port]`、`CLR[port]` |
| 定时器 | TIMx | CT16B0/CT16B1（16 位）、CT32B0/CT32B1（32 位），带 MRx 匹配寄存器 |
| SPI | SPI1/2 | SSP0 / SSP1 |
| 内部 EEPROM | 无（一般用 Flash 模拟） | 片上 4 KB EEPROM，通过 IAP 读写（`src/eeprom.c`） |
| 进 ISP 下载 | BOOT0 | 代码里调用 `Chip_IAP_ReinvokeISP()` |

`src/my_adc.c` 写得比较规范，可以当 LPC 外设入门例子：上电 → 开时钟 → 配 IOCON → 配外设 → 启动转换 → 轮询 DONE 位。

参考资料：`资料/mcu参考资料/lpcopen_v2_03_.../` 是 NXP 官方的 LPCOpen 例程（含 ADC、SSP、USB ROM 例程）。数据手册和用户手册（UM10462）仓库里没有，需要到 NXP 官网下载。

## 3. 系统架构与主循环

### 3.1 信号链

```
手指按压 → 磁铁/遮光片位移 → 传感器（Hall 芯片 或 光电+ADC）
        → MCU 每 1ms 采样 → 滤波/基线/分段 → AP/RT 判定 → 按键状态变化
        → ①马上驱动线圈振动（PWM1/PWM2 引脚输出高电平 Ton 微秒）
        → ②打包 HID 报文，经 USB 上报给电脑
GUI（MouseTest.exe）⇄ USB 自定义报文 ⇄ 修改 AP/RT/振动参数 → 写入 EEPROM
```

### 3.2 初始化 `Device_Init()`（`src/device.c:415`）

关键顺序：看门狗 → 时钟 → GPIO → **`Ele_Init()` 线圈 IO 先拉低（防止上电误通电）** → USB 时钟 → `Param_Init()` 从 EEPROM 读参数 → SPI（按板型）→ 1ms 定时器 CT16B0 → USB 初始化 → 延时 500ms → Hall 初始化（非 IRPT 板）→ BOD 掉电复位 → PAW3950 和 ADC 初始化。

### 3.3 主循环 `Device_Active()`（`src/device.c:493`）

裸机超级循环，没有 RTOS：

```c
while (1) {
    Device_Scan();      // 光学传感器 + 每 1ms 一次按键扫描（左右键振动在这里触发）
    Device_Pack();      // 根据事件组装鼠标/键盘报文
    Device_Report();    // 写入 USB 端点
    wwdt_feed();        // 喂狗
    PC_Communicate();   // 处理 GUI 发来的命令
    Suspend_Check();    // USB 挂起
    Ele_PollingTask();  // 振动状态机、防长通电看门狗、互斥缓存、自动振动
    Task_ParamGuard();  // 参数有改动时写 EEPROM 并生效
    MyDebug_Task();
}
```

1ms 节拍的来源：CT16B0 中断每 1ms 把 `one_ms_cycle` 减到 0（`src/Timer.c:78`），主循环检测到 0 后执行一次按键扫描再重置为 1。这是“中断置标志、主循环干活”的常见写法。

## 4. 核心链路一：按键检测（模拟量 → 按下/松开）

调用链：
`Device_Button_Scan()`（`device.c:949`）→ `Button_Scan()`（`app/button.c:592`）→ `Button_GetState()` → `LR_GetState()`（`button.c:298`）→ `ProcessRecvSampleRawData()`（`src/my_misc.c:418`）

### 4.1 取原始值（`LR_GetState`）
- **IRPT_V4 板**：`MyADC_GetValue()` 读 AD2（PIO0_13，左键）、AD3（PIO0_14，右键），10 位精度。结果按 Hall SPI 的格式塞进 `hall_spi_rx[4]`，这样后续算法可以共用。
- **Hall 板**：`hall_get_sample()` 先用 GPIO 在 SCLK 上发一个“时钟命令”脉冲，再通过 SPI 菊花链一次读出两颗 Hall 芯片的数据（14 位，带 2 位校验，用 `bit_error[]` 表验证）。

### 4.2 处理（`ProcessRecvSampleRawData`）
1. **上电基线初始化**（`Hall_InitBaseline`，`my_misc.c:135`）：上电后若干次采样稳定后，记录“没按下时的值”作为 top 基线。所以**上电时不要按键**。
2. **振动期间冻结**：线圈通电会干扰传感器读数，所以振动期间直接沿用上一次的按键状态（`USE_HALL_VALUE_DURING_VIBRATION = 0`）。
3. **一阶低通滤波（指数平均）**：`avg += (新值 - avg) / 2^N`，N=4（IRPT）或 6（Hall）；数据突变超过 `FILTER_SKIP_VALUE` 时直接跳到新值，避免滤波带来延迟。
4. **分段**（`Hall_CalculateNode`，`my_misc.c:288`）：把 `[top 基线, bottom 基线]` 线性映射到 0~255，再查表 `nodeCaliTable` 得到 **0~100 段**（段数就是按压深度百分比，GUI 上的 crtSegment 显示的就是它）。
5. **AP/RT 判定**（`Hall_HandleKeyRapidTrigger`，`my_misc.c:330`）：（注意：从顶部开始按时，实际触发点是 AP 和 RT按下 中较大的那个，详见第 1 课）
   - 未按下时：段数 ≥ AP 且比最近低点多下压 `RT按下` 段 → 判定为按下；
   - 已按下时：比最近高点回弹 `RT松开` 段，或段数回到 0 → 判定为松开；
   - 默认值：AP=10、RT 按下=30、RT 松开=20（`inc/my_misc.h:42`）。
6. **基线动态校准**：`Hall_CalibrateTopBaseline` 和 `Hall_CalibrateBottomBaseline` 会慢慢跟踪温漂和磁铁老化。
7. `Hall_SyncParam()` 把 raw、基线、段数存起来，供 GUI 的 “RowData” 面板读取。

> 注意索引：代码里 **`index 0 = 右键`、`index 1 = 左键`**（`Hall_ConvertVKeyToArrayIndex`）。上报的 bit 是 bit0=左键、bit1=右键。这里很容易搞混。

## 5. 核心链路二：振动触感

入口在 `Button_Scan()` 里：左右键状态一变化，就**立刻**调用 `Ele_LeftKeyPressProcess()` 或 `Ele_LeftKeyReleaseProcess()`（`app/button.c:626` 附近）。

### 5.1 驱动电路（看原理图 “LB&RB Haptics Driver”）
`H_VDD`（7V 升压，ETA1628）→ 线圈 → N-MOS（MS3416K）→ GND。MCU 的 PWM1/PWM2 引脚拉高，MOS 导通，线圈通电产生吸力；线圈两端反并联二极管 DS32W 用于续流。

### 5.2 一次振动（`my_electromagnet.c:777`）
当前 `BRAKE_FUNC_ENABLE = 1`（`my_electromagnet.c:28`），流程是**阻塞式**的：
```
线圈开 → CT16B1_DelayUs(Ton) → 线圈关
[若开启制动] → 延时 brakeDelay → 再开 brakeDuration → 关   ← 这就是“余震抑制”
状态 = RELEASE_DEBOUNCE，8ms 后回到 NO_VIBRATING
```
- `Ton` 就是 GUI 上的“振感强度”，0~1000（代码上限 `MAX_VIBRATE_DURATION_US = 2000` µs）。
- **动态导通时间**（GUI 的“动态导通时间”勾选框，`Ele_CalculateDuration`，`my_electromagnet.c:1017`）：按压越深，Ton 越短（`durationScale[]` 表，最多缩短到约 1/3）。需求里提到“后续可能需要根据 7 楼数据调节”，指的就是这张表。
- `#else` 分支里是用 CT32B0 匹配中断实现的**非阻塞**版本（`TIMER32_0_IRQHandler`，`:265`），目前没有启用。

### 5.3 安全机制（`Ele_PollingTask`，`:759`）
- `Ele_Daemon`：线圈连续通电超过约 40ms 就强制关断，防止线圈烧毁。
- `Ele_OnlyOne`（`SINGLE_COIL_AT_A_TIME`）：同一时刻只允许一个线圈通电（限制峰值电流），另一个排队等待。
- 自动振动：GUI “调试配置”里的“自动振动”，按固定周期反复触发，用于测试。

## 6. 核心链路三：与 GUI 的通信协议

GUI 软件位于 `资料/TEST ROG_P723_POC V1.0.019/MouseTest.exe`，界面截图是 `资料/测试软件的页面.png`。

### 6.1 报文格式（`inc/my_protocol.h`）
```
PacketHeader (6B): 0x55 | 目的ID | 源ID | 校验和 | 负载长度(LE 16bit)
Payload:           类型 | 命令 | 子命令 | 值(VK键码) | 数据...
```
- ID：HOST=0x01，MOUSE=0x02；VK：左键 0x01，右键 0x02。
- 类型：通知 0x01 / 请求 0x02 / 响应 0x03。
- 命令：`GET_INFO 01`、`GET_CONFIG 02`、`SET_CONFIG 03`、`SAVE_CONFIG 04`、`GET_DEBUG 05`、`SET_DEBUG 06`。
- 子命令（Config）：`RAPID_TRIGGER 01`、`COIL 02`（按下振感）、`COIL_RELEASE 03`（释放振感）、`COIL_BRAKE 04`（按下制动）、`COIL_BRAKE_REL 05`（释放制动）、`ALL FF`。
- 各结构体定义见 `inc/my_protocol_common.h`。`bmEnableMask` 的 bit7 是总使能。
- 完整协议表在 `资料/协议2026-09-17.xlsx`。

### 6.2 收包路径
USB 中断收到 64 字节 → `PC_Communicate()` → 命令字为 `TEST_CMD` 时 → `Protocol_ProcessReceiveData()`（`my_protocol_mouse.c:1047`）→ 按 0x55 帧头搜索、校验 → 分发到 `ProcessRequest_CMD_xxx`。

### 6.3 GUI 控件 ↔ 代码对照
| GUI 控件 | 协议 | 代码中生效位置 |
|---|---|---|
| AP值 / 按下RT / 松开RT | SET_CONFIG / RAPID_TRIGGER | `Hall_UpdateParam` → `ap_value[]` 等 |
| 按下振感强度 | SET_CONFIG / COIL | `Ele_UpdateParam` → `pressVibrateDurationUs` |
| 释放振感强度 | SET_CONFIG / COIL_RELEASE | `Ele_UpdateReleaseParam` |
| 制动配置（延时/时长） | SET_CONFIG / COIL_BRAKE(_REL) | `Ele_UpdateBrakeParam` |
| 动态导通时间 / 自动振动 / 周期 | SET_DEBUG / DEBUG_COIL | `Ele_UpdateDebugParam`（**不存 EEPROM**，断电恢复默认） |
| RowData 面板 | GET_INFO / HALL_RAW、SEGMENT | `Hall_SyncParam` 存入的数据 |

### 6.4 参数存储
`Param_Init()`（`:204`）上电时读 EEPROM。如果版本号（`MY_MAIN_VERSION`<<16 | `DEBUG_VER`）或校验和不一致，就恢复默认值并写回。所以**修改 `inc/my_debug.h` 里的 `DEBUG_VER` 会导致参数被重置**。`Task_ParamGuard()`（`:109`）发现参数有改动时整块写回 EEPROM。

### 9.2 我对各子任务的理解和建议

1. **适配 H6**：原理图上 Hall 芯片丝印是 **GTRY164**（H1=左键，H2=右键），推测 “H6” 就是指这颗芯片（上一代时序文档里叫 “Hall5/H5”）**【待确认：H6 的寄存器表、时钟命令时序是否和 H5 一样】**。
   - 现有 Hall 代码走的是 SSP0，`Hall_CLK_Command_SET()`（`app/button.c:787`）里**硬编码了用 PIO0_10 发时钟命令脉冲**。在新板上 Hall 的时钟脚是 **PIO1_15（SSP1）**，PIO0_10 已经给 PAW3950 用了，所以这个函数和 `SSP_Send_Receive` 都要改成 SSP1 和 PIO1_15。这是最容易漏掉的一点。
   - `Device_Init()` 里需要先拉高 Hall_PWR_EN 并等待芯片上电稳定，再调用 `HallSensor_INIT()`。
   - `sensor_reg_init_array` 的增益（0x14/0x16 寄存器）要根据新磁路重新调整。
2. **R-DIP 静音光学编码器**：`app/scroll.c` 里是传统机械编码器的逻辑。光学编码器需要先拉高 SCROLL_EN 点亮发射管，再读 UP/DOWN 两路的正交信号。可以考虑做成脉冲式点亮来省电（电池供电时有意义）**【待确认：编码器规格书】**。
3. **BQ21128 充电芯片**：新增 I2C 驱动（LPC 硬件 I2C 在 `src/I2C.c`），配置充电电流、终止电压，读取充电状态。需要 BQ21128 数据手册（仓库里没有）。
4. **PAW3950 + 协议**：`PAW3950.c` 已经在 IRPT_V4 上跑通了，迁移时主要核对引脚；GUI 协议基本不用改。

### 9.3 Flash 容量注意事项 **【待确认】**
仓库名和新板 MCU 都是 **LPC11U35FHI33/501（64 KB Flash）**，但 Keil 工程目标是 **LPC11U37/501（128 KB，`IROM 0-0x1FFFF`）**。目前代码约 45 KB（`BUILD.md` 中 Code+RO+RW），能装下。不过如果给新板烧录，需要确认 Flash 下载算法和 IROM 大小设置，并留意代码继续增长后可能超出 64 KB。

## 10. 阅读时发现的疑点（建议找杰哥确认）

1. **`Ele_OnlyOne()`（`my_electromagnet.c:1122`）**：被缓存的振动不管原本是“按下”还是“松开”，补发时都调用 `...ReleaseProcess()`，用的是**释放**的强度。当按下和释放强度设置得不一样，并且左右键几乎同时触发时，补发的强度会不对。
2. 阻塞式振动加制动最长可以占用约 2ms + 2ms + 2ms 的 CPU 时间，期间主循环不运行（USB 上报、另一个键的扫描都会延后）。这是有意的取舍吗？CT32B0 中断版本为什么停用了？
3. 开启 `BRAKE_FUNC_ENABLE` 后，释放振动时 `status` 被设成了 `ELE_PRESS_VIBRATING`。目前只影响调试判断，但名称有误导性。
4. `Task_ParamGuard()` 在主循环里同步写 EEPROM，写的过程中会影响按键扫描的实时性。GUI 拖动滑条时会频繁写入，需要关注 EEPROM 寿命。
